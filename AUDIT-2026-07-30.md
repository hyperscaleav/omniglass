# Mid-implementation audit: docs vs code (2026-07-30)

A full pass over every page under `docs/src/content/docs/` against the code at
`fb661ca`. Purpose: an implementation-status snapshot, a page-by-page drift list, and a
prioritized worklist. This file is a triage source, meant to be dissolved into issues,
not merged to `main` as-is.

Convention used throughout: architecture pages describe the target model, so
documented-but-unbuilt is fine when the badge and the page's status note say so. "Drift"
below means one of: the code does something different from the prose with no divergence
note; a built capability sits behind a `Design` badge or a stale "still Design" bullet;
the prose uses vocabulary the code retired; or a claim names a test, route, command,
column, or file that does not exist.

---

## 1. Where the implementation actually is

Snapshot: 29 architecture pages (19 `Partial`, 9 `Design`, 1 `Built`), 138 build-log
entries in `status.mdx`, 52 base tables, 141 API paths, 269 generated CLI commands,
roughly 22 live console pages.

**Production-grade and deep:**

- **Identity and access.** Password + session + token auth, lockout, policy, avatars,
  lifecycle (disable/archive/purge), impersonation with dual-actor audit and the owner
  takeover guard, principal groups end to end, grants with `scope_op`, the owner
  invariant trigger, topic-pattern permissions with the admin tier, three authz guard
  tests. The most mature subsystem in the repo.
- **Estate + catalogs.** location/system/component trees on the shared scoped-CRUD
  primitive, `system_member` multi-membership with primary, system roles
  (quorum/impact) and the assignment guard, product/vendor/driver/capability/standard
  registries, `location_type` with `allowed_parent_types`, uuid PKs everywhere
  (ADR-0053/0056/0062 series complete).
- **Values cascade.** Tags (allowed_values, propagation, membership-scoped system
  band), variables, envelope-encrypted secrets with reveal/copy audit, files/blob store
  with synchronous GC, the settings engine (platform level), the unified
  ResolutionPanel.
- **Collection vertical.** Node enrollment/claim, embedded NATS/JetStream with
  per-node subject isolation, icmp + tcp probes with the capability self-check,
  protobuf `TelemetryBatch`, the owner-confining reject-not-project ingest consumer,
  the transition-only reachability verdict, the reachability panel, interface/task
  authoring with derived tasks, the raw-log lane (ADR-0066) with node self-logs.
- **Telemetry ontology.** `property_type`/`event_type`/`command_type` registries,
  `metric`/`state`/`event`/`log_line` sinks, the `property` latest-value cache, the
  command pillar with computed settlement, the generated ERD with a drift test.
- **Pipeline and delivery.** `make gen` (OpenAPI, CLI, SPA client, CLI reference
  docs, ERD, proto), goreleaser matrix, multi-arch image, Helm chart, PR previews,
  docs screenshot gates.

**Genuinely not started (correctly `Design` where badged):** the expression engine,
calc/event/action rules and the alarm automation tier, the `ViewResult` read framework,
component/system templates, discovery, real snmp/http/ssh probes (today `ssh`/`http`
probe as tcp-connect only), webhook listeners, CDC and the two-lane data plane, the
clock/timer, SSE live relay, MCP/AI surfaces, group-as-scope and the cross-tier scope
cascade, multi-role scale-out.

**Position in one sentence:** the platform half (identity, estate, catalogs, values,
authoring surfaces, delivery) is well past the midpoint and solid; the monitoring half
is one proven vertical (reachability) plus its storage substrate, with the entire
detection/automation tier (rules, alarms-from-rules, actions, calculations) still ahead.

## 2. Cross-cutting drift themes

1. **The ADR-0063/0065/0066 refactor was never swept through the older docs.**
   "datapoint" survives on ~12 architecture pages (templates.md x13, health.md x13,
   messaging.md, scaling.md, identity-access.md, ui.md x9, commands.md, cascade.md,
   files.md, expressions.md, time.md, properties guide), in the glossary, in the
   console (`web/src/lib/nav.ts` operator-facing hint text, `web/src/lib/properties.ts`,
   `Properties.tsx`), in `internal/seed/properties.yaml` comments, in the Makefile
   gen-proto comment, and in stale ingest-path comments
   (`internal/bus/consumer.go:136,310`). Related retired names still in prose:
   `caused_by_event_id` (renamed `source_event_id`), the `global` owner (now
   `platform`), proto `Event` (now `TelemetryBatch`), `--mode node` (now
   `omniglass node run`), the `/types` umbrella pages that moved, `value_type` (column
   is `data_type`), the `scope`/`template_id` registry ladder (built model is the
   `official` boolean).
2. **Badges and status callouts lag the build.** Several pages hide shipped work
   behind `Design` or a stale "still Design" bullet (details per page below):
   messaging.md, workers.md, groups.md, the glossary, plus stale callout bullets on
   nodes.md, scaling.md, identity-access.md, cascade.md, audit.md, tags.md, ui.md.
   Per docs-with-everything, a built capability behind a `Design` badge is a drift bug.
3. **A handful of pages make false claims about built behavior.** These are the
   dangerous ones (a reader trusts them and is wrong): storage.md's lineage CHECK and
   arc lists, api.md's list conventions and secret-floor claims, identity-access.md's
   scope cascade and group scopes, alarms-actions.md's "alarms never write samples",
   properties.md's `instance` semantics, the guides' broken CLI invocations.
4. **The docs meta-layer has hygiene debt.** decisions.md numbering and index,
   status.mdx's intro and its 2,100-line unstructured build log, a roadmap frozen at
   slice 4b, contributing pages naming make targets and CI gates that do not exist.

## 4. P0: code issues found by the audit

These surfaced while checking doc claims; they are implementation work, not doc edits.

1. **Ingest is not idempotent and the node publish is fire-and-forget.**
   `internal/bus/consumer.go:143-146` (tracked as #311): three sinks commit in
   separate transactions before a single ack, so redelivery double-inserts into
   `metric` and `event`, which have no uniqueness key. Node side,
   `internal/node/probe.go:66` and `internal/node/run.go:161` use core-NATS
   `Publish` against a JetStream WorkQueue subject: no publish ack, no `Nats-Msg-Id`,
   so a JS outage silently loses samples and self-logs. workers.md/nodes.md/
   messaging.md all promise at-least-once + dedup + idempotent sink. Either build
   that or re-document; today the docs describe the opposite of the code.
2. **The `instance` mismatch breaks reconciliation and settlement.** Ingest stamps
   every observed sample and cache row with `instance = <interface name>`
   (`internal/bus/consumer.go:336,350`), but `Reconciliation` reads `is`/`told` at
   `instance = ""` (`internal/storage/property_cache.go:64-70`), so drift is never
   detected for task-collected values, and `CommandSettlement` looks for the observed
   row at the command's instance while the device's answer lands under the interface
   name, so a real round-trip settles `failed`. One shipped feature (checkpoint 5
   reachability) and two shipped reads (reconciliation, settlement) disagree about
   series identity.
3. **One flat registry namespace with last-write-wins.**
   `internal/collection/registry.go:19-30` merges `property_type` and `event_type`
   names into a single map, event types loaded second. A name registered in both
   silently routes to the `event` sink. Needs a cross-registry uniqueness guarantee
   or a keyed lookup.
4. **`ListSecrets` violates the scope-injection invariant.**
   `internal/storage/secrets.go:263-302` selects every secret unscoped, then filters
   per row in Go (N+1). api.md L283 additionally claims it is an all-scope-only
   admin directory; there is no all-scope check. Contrast `ListVariables`
   (`internal/storage/variables.go:122-125`), which does it right.
5. **System-scoped secrets are creatable dead data.** ADR-0052 removed the system
   band from secret resolution (`internal/storage/secrets.go:533-536` has no system
   arm), but the CHECK still admits `'system'` (`init.sql:657`), the create form
   offers it, the Secrets tooltip (`web/src/pages/Secrets.tsx:321`) and
   guides/admin/secrets.md still advertise it. A system-scoped secret can be created
   and will never resolve onto anything.
6. **`OMNIGLASS_SECURE_COOKIES` is set nowhere and documented nowhere.** Read at
   `internal/config/config.go:78`; the Helm chart (which fronts previews with edge
   TLS) never sets it, so session cookies ship without `Secure` in every TLS-fronted
   deployment. Also absent from container-image.md's env table.
7. **The audit diff is write-only.** `audit_log.old`/`new` are written on every
   mutation but no read surface selects them (`internal/storage/audit.go:46-58`,
   `internal/api/audit.go:22-33`). The audit page's headline promise ("who changed
   this, and to what?") is unanswerable through any built surface.
8. **Catalog pages render uuids as the operator-facing Id.** Post-ADR-0062
   regression across `Drivers.tsx`, `Vendors.tsx`, `Products.tsx`,
   `Capabilities.tsx`: the Id column shows `d.id` (uuid), filters match against the
   uuid so typing `snmp-generic` finds nothing, delete confirms print uuids, and the
   create-form onCreated focuses by handle while rows key by uuid so the new row is
   not found. `Products.tsx` also renders raw `vendor_id`/`driver_id` uuids in cells.
   The fetched `name` field is never displayed.
9. **Schema/gateway disagreements worth closing.** `principal_grant.scope_kind`
   CHECK admits `'group'` (`init.sql:472`) but every code path refuses it;
   `alarm_active_idx` is non-unique (`init.sql:1556`) while alarms-actions.md and
   workers.md lean on a "one-open index"; `metric`/`state` CHECKs still admit
   `provenance='declared'`, which the model says is impossible; `property.kind`
   still admits `'log'` and `deriveSamples` has no log arm, so such a sample passes
   reject-not-project then vanishes silently; the `credential.purpose`-adjacent
   dead objects: `platform_setting` table (zero readers/writers) and unrouted grants
   in `roles.yaml` (`config:create,update`, `alarm:ack,snooze,resolve`,
   `unit:create`, `severity_level:create`, `source:create`) that gate nothing.
10. **The docs-CLI guard test has the hole its comment says it closes.**
    `internal/cli/docs_commands_test.go:62-68` accepts any resolving prefix, so
    `component component effective-tag list` passes because `component` resolves.
    That is exactly how three broken invocations sit in shipped guides today.
    Require the match to consume every non-placeholder word.
11. **Two gates the contributing docs claim exist are not wired in CI.** No workflow
    runs `make gen` + `git diff --exit-code` (api-first.md L16 claims a drift check
    fails the PR), and no workflow builds the Astro docs site (docs-with-everything
    L105 claims a broken docs build fails the PR; a broken `.mdx` merges clean
    today). Either wire them or soften the claims; wiring them is cheap and this
    audit is evidence they are needed.

Smaller code nits collected by the agents: stale `internal/api/files.go:165` +
`internal/storage/storage.go:505` "blob is left in place" descriptions (the code frees
the blob; the generated CLI reference now publishes the wrong claim);
`internal/api/secrets.go:45` "absent for a global owner"; the serial-dispatch
constraint on the telemetry consumer (`consumer.go:246-253`) contradicting the
horizontal-scale story in scaling.md/messaging.md; `interface.node_name` a uuid column
with a `_name` suffix; `task.display_name` exposed but never populated or rendered;
official-row refusal is 422 on five registries but 409 on event/command types;
generated CLI verb casing splits camelCase (`setTag`) vs kebab (`change-password`);
`web/src/pages/Nodes.tsx:157` comment contradicting the edit rail below it;
`web/src/pages/Audit.tsx:9` naming the two-token gate; blank flag descriptions
(missing `doc:` tags) on the vendor/capability/driver/product/location create inputs;
`node run --server/--token` silently shadowing the root persistent flags with
different semantics; the `$dp.` binding namespace in expressions.md carrying the
retired noun into a future engine.

## 6. Glaring items worth an explicit decision

1. **The delivery-guarantee gap (P0-1) is the largest honesty gap in the system.**
   Three pages promise exactly-once outcomes; the code loses data on JS outage and
   duplicates on redelivery, and the consumer's correctness depends on serial
   dispatch that the scaling story says will be horizontal. This needs a real
   decision (ADR): either build the promised contract (publish acks, `Nats-Msg-Id`,
   idempotent sinks with a uniqueness key, then revisit concurrency) or write down
   the weaker contract as the architecture.
2. **The `instance` identity question (P0-2) blocks the intend/observe/settle loop.**
   Settlement and reconciliation are shipped surfaces that cannot currently succeed
   against task-collected data. Decide what `instance` means (interface name vs
   logical sub-entity vs both) and make writer and readers agree; ADR-0038 and
   properties.md currently answer differently.
3. **`POST /nodes:claim` is the only unauthenticated write on the API** and no
   architecture page says so. Intentional (the enrollment token is in the body), but
   it belongs in identity-access.md's allow-list discussion with its threat model.
4. **The documentation system's own gates are the meta-lesson.** The two artifacts
   that cannot drift (the ERD, the CLI reference) audited clean; nearly everything
   hand-written about generated surfaces drifted. Wiring the two missing CI gates
   (P0-11), fixing the docs-CLI guard hole (P0-10), and considering a
   status-callout-vs-code lint would convert this whole audit class from manual to
   mechanical.
