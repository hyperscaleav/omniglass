# sim: the Omniglass device simulator

The simulator serves a fleet of fictional AV and IT devices, each on its own loopback address,
speaking the protocols real gear speaks (HTTP and HTTPS, SNMP, SSH, Telnet, raw TCP line
protocols, UDP, WebSocket, server-sent events, signed webhooks) from one live state per device.
An outpost collects from a simulated device exactly as it would from hardware. It is the test
bed for the end-to-end tests, the screenshot harness and the lab, and a teaching surface: an
operator can break a device on purpose and watch the monitoring loop respond.

It is part of the single Omniglass Go module and binary, not a separate program.

## Layout

| Path | What it is |
| --- | --- |
| `sim/` | The engine: devices, faces per protocol, behavior, faults, state, observation. |
| `sim/surface/` | Protocol surfaces a Go device family declares in Go (`nvp`, `snmp`, `httpapi`). `httpapi` has the status document, the `Control` route (choices, numbers, flags and true/false switches), `Element` (a control on one element of a list named by the body), `Action` and `Sections`. |
| `sim/behave/` | The shared, typed behavior primitives a family composes. |
| `sim/wire/` | The vocabulary a family declares its faces in: `Interface` (protocol, port, TLS, auth, line framing), `Subject`, `Auth`, the route and command listing the console shows. Nothing in it is read from a file. |
| `sim/spec/` | What defines a device: the `Definition` every consumer reads, the Go family `Spec`, and the `Catalog` that resolves a product to the family that claims it. |
| `sim/device/` | The Go device families, one package per wire API; the list is generated by `make gen`. `internal/bind` joins the behavior primitives to a family's state. `coverage.go` accounts for the seeded products no family serves. |
| `sim/fleet/` | Deterministic naming and enrichment of fleet members. |
| `sim/impair/` | Network impairment (firewall table and qdisc) for a simulated device. |
| `sim/simfleet/` | Fleet and system plans built from the families. |
| `sim/simhub/` | Registry of the simulators connected to a server. |
| `sim/simoutpost/` | The simulator running beside or inside an outpost. |
| `sim/mailsim/` | The simulated mail server. |
| `sim/simtest/` | Test helpers for loopback addressing. `simtest/shipped` builds an engine or catalog over every Go family, the one door tests outside `sim` use. |

## Running it

- `omniglass sim run` runs beside an outpost with that outpost's credential (the same
  `OMNIGLASS_SERVER`, `OMNIGLASS_OUTPOST_NAME` and `OMNIGLASS_OUTPOST_TOKEN` as `outpost run`),
  pulls the devices placed on that outpost and serves them. `omniglass sim mail` runs the
  simulated mail server.
- `make lab` brings up a server, an outpost and a simulated fleet together;
  `make test-lab LAB_RUN=<test>` runs one lab scenario test.
- `make bench-sim` serves a 1,000-device fleet and reports startup time.

## Writing a device

There is one kind of device: a **Go family**, a package `sim/device/<family>` that exports
`func Spec() spec.Spec`: one wire API, implemented once, its models the rows of a typed table. Nothing about a
device is read from a file or rendered from a template (a guard test in `internal/build` fails the build if a
YAML profile or a behavior template comes back). `make gen` registers the package and renders it into the
simulation page's family table (`docs/src/generated/simulation.json`, by `cmd/simgen`). The worked example is
`sim/device/borealedge`, the Boreal Edge display, with `borealbeam` and `borealcast` beside it, and the
[simulation page](../docs/src/content/docs/architecture/simulation.mdx) walks a new device from table to test.

1. **Record what it answers.** A family's script is one `wireFamily` value (its products, requests, SNMP
   reads, drifting behaviors and room day) in a `sim/<family>_wire_test.go`, recorded with one command,
   `go test ./sim -run 'TestRecordWire$' -wire.family=<name>`; see
   [sim/testdata/wire/README.md](testdata/wire/README.md). Add its replay, `replayWire(t, family, product)`:
   same status, headers, bytes, state, SNMP types and values, drift sequences and room-day behavior
   (`sim/wire_family_test.go` is the smallest worked example). The families that replaced a YAML profile
   are `Frozen`: their transcripts were recorded from the profile and are never re-recorded from the family.
2. **The model table.** A typed `Row` (`Product`, `Diagonal`, `Resolution`, and whatever else the
   models differ by) written once, wrapped with `spec.Table`, each row's `Model`, `Summary` and `State`
   overlay saying what the product reports of itself. Five sizes are five rows, never five packages;
   a model gets a package only when its API differs.
3. **Interfaces and state.** Declare the surfaces as `wire.Interface` (protocol, port, auth) and the
   state tree with its defaults. A read-derived uptime is a typed `spec.Elapsed{Path, Since}` in `Spec.Elapsed`: the engine seeds an
   unset anchor, reads whole seconds since it at `Path`, and a reboot resets it by writing the anchor.
4. **Answers.** JSON is a typed struct through `httpapi.Document` (or `httpapi.Status`). A route that
   sets state from a body is an `httpapi.Control`, a reboot an `httpapi.Action`; SNMP is
   `sim/surface/snmp` plus typed scalars (`surface.Text`, `surface.Integer`, each `.At(statePath)`);
   a line protocol is `sim/surface/nvp`. A device web page is `html/template` over a typed view struct,
   both in the package (`//go:embed`). Read state with `spec.String`, `Int64`, `Float` and `Bool`.
5. **Behavior.** `spec.Tick`s built from `sim/device/internal/bind`, which joins a `sim/behave`
   primitive to the family's state paths; the paths a tick writes are declared in `Writes`. Write a
   behavior inline only where no primitive owns it, and add the primitive to `sim/behave` first when a
   second family will want it.
6. **Tests.** `spectest.Conform(t, Spec())` over the whole table, then the family's own: a
   `spectest.NewFake` stands in for the device, so a handler, a surface and a tick are unit tests with
   no engine. The engine-level proof is the wire replay above. A test outside package `sim` that needs an
   engine takes `shipped.Engine(t)` (or `shipped.Catalog(t)`) from `sim/simtest/shipped`, and inside
   package `sim` `shippedEngine(t)`: both serve every family, and take a family of the test's own beside them.
7. **Account for it.** The seeded products on the network that no family serves are listed in
   `sim/device/coverage.go` with their issues; a new family's products leave that list. The catalog's alignment
   test holds every family's models to the seed's products, drivers and component types.

### Policies

Written once here, so the next family repeats no workaround.

- **Quirk steps last.** A request the YAML profile (before its deletion) answered with an accident of its templates (an
  unquoted word written into a JSON document, `<no value>` written to state) is marked `Quirk` in the
  script: the family refuses it with a 400 that changes nothing, and the replay checks that
  divergence, not the bytes. Such a request leaves state behind in the recording, which would carry
  into every step after it, so the quirk steps go at the end of the script.
- **`httpapi.Control` refuses an unreadable body.** A body that was sent but is not a JSON object
  (text, an array, `null`, a truncated document) is a 400 `{"error":"the request body is not a JSON
  object"}` and writes nothing, as a field outside its list or of the wrong type already is. An empty
  body is a request with every field missing, refused by name as before. A family needs no check of
  its own for either.
- **A test that names a shipped product pins it.** `internal/build`'s catalog guard
  (`TestTestsDoNotBorrowTheSeedCatalog`) fails a `*_test.go` that names a seeded product SKU outside its
  pin files. An end-to-end test whose point is a shipped product (a lab test reading the Boreal Edge off
  the live simulator, an API test holding a component's simulation route to a family's identity) is added
  to that guard's `pinFiles` with a one-line reason and the issue; a behavior test mints its own product
  (`storagetest.MintProduct`) instead. Converting a family moves no pin: the SKU is the same.
- **Uptime is `spec.Elapsed`.** Read-derived, with no goroutine and no event.
- **Named events are published after the writes they follow.** A route calls `d.Publish(spec.Event{Name,
  Data})` after its `WriteMany`; a tick names its events in `Tick.Emit`, which reads the device once the
  tick's changes are written. The transcripts record them (`events`, `#events`), so they are held byte for
  byte. A route a web page calls but does not advertise is `Private: true`.
- **A document that kept a template's comment lines keeps them.** `httpapi.Annotated` writes a whitespace-only
  line before a `Noted` key, because a collector reads the bytes; a document with no comment is
  `httpapi.Document`.
- **A correction to the profile is written down and pinned.** The replay's `Body` and `Diverges` hooks map the
  recorded transcript to what the family means to say, and fail when the recording no longer holds what they
  correct; the divergence is an ADR.
- **A line command is listed where it is served.** A `spec.Command` names its `Face` (the interface the
  console lists it under) and a family's `Surface` names `ListedOn` for the shared surface's commands (a
  commander that is also a `surface.Described` gives each line its summary; a binary frame is listed as a
  hex command on its own interface). `spectest.Conform` fails a family that answers a typed line no
  interface lists. A
  line protocol is recorded in the wire script's `Lines` (each line on the device's TCP face, or a verb
  direct against its command table), with the pushes each draws and the device's own command list.
- **Free text and derived writes.** A control route that took any string is an `httpapi.Text` field (with a
  `Pattern` when the profile held one); a route that lands a value derived from the request in the same
  change (the signal on the input just routed) is a `Control.Also`. A tick that reads its room's booked
  meetings calls `c.ReadBookings()`.

- **A family of one is named for its product.** A model row may carry the family's own name, so the
  lab's manifests, pushers and senders, which name a product as a profile, resolve it unchanged.
- **A service that speaks for rooms reads them through `spec.RoomsOf(d)`**, sends a webhook with
  `spec.Send` (signed as the subscription says) and names a stream event with `spec.Report`; a pusher
  declares `Spec.Push` and a webhook sender `Spec.Webhook`. A paged list declares its names once
  (`httpapi.Paging`, `Cut`, `PagedDocument`). The wire script's `Extra` hook records what is not HTTP or
  SNMP: `wireConverse` (a conversation on a line face), `wireStream` (an event stream), `wireRecv` (the
  posts a device makes, and whether each signature verifies).
- **Text stays text.** A value the YAML templates coerced (an id of digits into a number) is stored as the
  string it is, and a field that is not a string is refused; the recording marks such a step `Quirk` or
  leaves its state out of the comparison (ADR-2836).

`sim/spec/spectest` is also a small family used by the engine's tests.
