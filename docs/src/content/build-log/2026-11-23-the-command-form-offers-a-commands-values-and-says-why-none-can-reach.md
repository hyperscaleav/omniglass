title: "The command form offers a command's values and says why none can reach (#2466)"
date: 2026-11-23
refs: [2466, 2115, 2423]
---

Issuing a command no longer needs outside knowledge. The form's value control is generated by a
pure function (`lib/command_form.ts`, schema in, control description out) from the type the command
targets and from its own `params_schema`: an enum is a select (set-power offers on, off and
standby, which its property type already declared and the form ignored), a true/false enum or a
boolean is a switch, a number carries its range and unit and is refused outside it in TypeScript
(never a native `min`/`max`), and free text is left for a free string. A metric type declares no
range, so a `ratio` reads 0 to 1 and a `percent` 0 to 100 from its unit. A command with params (a
PDU's outlet) now sends them; before, the form had no field for them.

The empty Commands panel names its cause: the drivers its endpoints use that bind nothing, the
drivers that bind commands (its product's first), and an Add an endpoint action. "Send command" joins
`AlarmActions` as a member of the one group (`show.command`), gated on `command:issue` and on a
reachable command through the same `createBoundCommands` the panel's Issue button asks. The
send-a-command-from-an-alarm walkthrough trips a display off through the Simulation API surface and
sends set-power from the alarm's row until it clears.

Deferred: linking a command to the alarm it cleared, in both directions. The alarm and the command
share only a component and a time, so the join is a server-side correlation, which the timeline work
(#2425) owns.
