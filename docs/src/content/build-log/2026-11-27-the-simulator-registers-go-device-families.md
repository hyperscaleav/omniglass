---
title: "The simulator registers Go device families beside YAML profiles (#2829)"
date: 2026-11-27
refs: [2829, 2826]
---

The first slice of the Go-families epic (#2826). A device is now defined as a `spec.Definition`, and a
YAML profile and a Go family both satisfy it. A family is a package under `sim/device/` exporting
`func Spec() spec.Spec`: one wire API, its models a typed table (`spec.Table`), its protocol handlers Go
funcs the engine's HTTP and line-protocol servers call, its responses typed Go values. A `spec.Catalog`
resolves a product to a family when one claims it, else to its YAML profile, and every consumer of the
profile store (the engine, the outpost, the fleet planner, the dev seed, the lab scenario's catalog, the
footprint sweep and the simulation routes) reads through it. The list of families is generated by
`make gen` (`cmd/familygen`, scanning `sim/device/*`). No profile is converted yet; a test-only family
(`sim/spec/spectest`) is served end to end beside the YAML ones, and a table test holds each consumer to
resolving it exactly as it resolves a YAML twin.
