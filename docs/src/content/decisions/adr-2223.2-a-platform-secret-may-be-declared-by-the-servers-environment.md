---
title: "A platform secret may be declared by the server's environment"
date: 2026-11-20
status: "Accepted"
summary: "OMNIGLASS_SECRET__<NAME> declares a $platform secret held in memory only, checked against its type at boot and resolved by every secret consumer behind the same secret:bind gate. It lists with source env and no fields, and the API refuses to write it (409, naming the variable). The binary loads .env then .env.local under the shell, and the lab's --omnibot-key-env becomes an alias for an env secret."
refs: [2223, 2109]

- **Date:** 2026-11-20 | **Status:** Accepted | **Pages:** [config and credentials](/architecture/variables/), [Secrets](/admin/secrets/), [settings](/architecture/settings/), [AI](/architecture/ai/), [connect an agent](/developer/agents/#pointing-omnibot-at-a-model), [the lab](/developer/lab/)
- **Decision:** (#2223, the second half beside [ADR-2223](/architecture/decisions/#adr-2223-settings-read-an-env-layer-between-the-settings-file-and-the-console); amends [ADR-2109](/architecture/decisions/#adr-2109-omnibots-model-key-stays-on-the-server-with-no-relay)'s "the key is a secret by name": it still is, from either source.)
  1. **One JSON variable a secret.** `OMNIGLASS_SECRET__<NAME>='{"type": "<secret type>", "fields": {...}}'`
     declares the `$platform` secret `<name>` (lowercased, each `_` a `-`). The JSON is judged
     before the gateway opens and the fields against the seeded `secret_type` catalog right after
     the boot seed, as a create is judged; a failure names the variable and never quotes the value.
  2. **Memory only.** Nothing is sealed, written or audited; rotation is a restart. A stored
     platform secret of the same name fails the boot naming both, and creating one under an env
     secret's name is refused, so a bare name never resolves two ways.
  3. **Every consumer, one gate.** omnibot's key, the mail relay's login and an endpoint's secret
     input resolve an env secret as they resolve a stored platform one, and naming it still takes
     `secret:bind` (the all scope, the admin tier too for an admin-sensitive type). An outpost is
     told a version that is a MAC of the value under a key derived from the encryption key, so
     servers sharing a key agree and a changed value reads as changed.
  4. **Listed, never written.** The directory lists it with `source: env`, its type and its
     `source_var`, and no fields; an update, delete, reveal or copy is a 409 naming the variable.
  5. **`.env` files load.** The `omniglass` binary loads `.env`, then `.env.local` over it, from its
     working directory, under whatever the shell already set (the architect's scope change on #2223).
  6. **The lab on the primitives.** `omniglass lab run` forwards the shell's `OMNIGLASS_SECRET__`
     variables to its server beside the `OMNIGLASS_SETTING__` ones; `--omnibot-key-env` declares the
     key as the server's env secret `lab-omnibot-key` and sets `provider` and `key_secret` in the env
     layer under any the shell set, and the seed seals nothing (it drops a key an older lab sealed).
- **Context:** Pointing omnibot at Bedrock took a secret created over the API and a setting patched
  after every lab start. A container or a Helm chart configures a credential by its environment; with
  the env settings layer of ADR-2223 the credential was the one piece still missing.
- **Not chosen:**
  - **An `env:VAR` reference inside `key_secret`.** It would let whoever may update settings point a
    model call at any variable the process holds, `OMNIGLASS_DSN` included. A named secret keeps the
    deployment deciding what is a secret and `secret:bind` deciding who may hand it out.
  - **One variable a field** (`OMNIGLASS_SECRET__BEDROCK_KEY__KEY` plus a `__TYPE`). Friendlier to a
    Kubernetes `secretKeyRef` per field, at the cost of a type variable and a secret half-declared
    when one is missing.
  - **Env secrets owned below the platform.** A location's or component's secret by environment has
    no owner the process can name stably; later, unfiled.
  - **Signing a notification target.** A target binds a stored secret by its row, so an env secret
    does not sign a webhook in this cut.
