---
title: "The console's API client is generated by orval, behind the path-keyed client it already called"
date: 2026-11-09
status: Accepted
summary: "Accepted: the console's generated API types and fetch client move off openapi-typescript and openapi-fetch (both in maintenance mode; openapi-typescript runs the TypeScript compiler API and blocks TypeScript 7) onto orval's fetch client, which emits plain source with no runtime dependency on the compiler. A generated route index keeps the path-keyed api.GET(route, ...) client every data layer already calls, so the migration touches imports, not call sites. TypeScript moves to 7. Amends ADR-0041's generated-client reference."
refs: [1619, 1465]
---

- **Date:** 2026-11-09 | **Status:** Accepted | **Pages:** [API first](/contributing/api-first/), [UI and the design system](/contributing/design-system/)
- **Decision:**
  1. **orval generates the console's API layer.** `npm run gen:api` runs orval (`client: "fetch"`,
     one file, prettier off) over the same committed `api/openapi.json`, writing
     `web/src/api/api.gen.ts`: every schema as a TypeScript type alias (not an interface, so a body
     still widens to a generic record) and one typed function per operation. Each function sends
     through `ogFetch` in `web/src/api/client.ts` (orval's `mutator`), so a generated call shares the
     console's base URL, session cookie, bearer token and 401 bounce. `gen:settings-schema` still
     chains after it, unchanged.
  2. **A generated route index keeps the call sites.** `web/scripts/gen-api-paths.mjs` reads the same
     spec and writes `web/src/api/paths.gen.ts`: for each route and method, the path params, query,
     body, whether the body is required, and the success and error bodies, each taken from the
     matching orval function's signature and response types so the index cannot disagree with it.
     `client.ts` types `api.GET/PUT/POST/DELETE/PATCH(route, { params: { path, query }, body })` off
     that index and resolves to `{ data, error, response }`, the shape openapi-fetch gave every call
     site. The data layer (`web/src/lib/*.ts`) changes only its type imports: `components["schemas"]["X"]`
     from `schema.gen` becomes `X` from `api.gen`. `client.test.ts` pins both the request the client
     builds and, with `@ts-expect-error`, the compile-time refusals (unknown route, missing or wrong
     path param, missing body or body field, unknown query param).
  3. **TypeScript moves to 7.** With the old generator gone nothing in the console's dependency tree
     pins TypeScript 5 or 6 on a path that runs, so `typescript` is `^7` with no
     `--legacy-peer-deps` and no `overrides`.
  4. **Amends ADR-0041.** Its "typed SPA client" whose `values` is a `Settings` struct is now
     orval's `Settings` type in `api.gen.ts`; `settings.schema.gen.ts` and its generator are
     unchanged.
- **Divergences and follow-ups:** the orval CLI package depends on its zod and hono generators,
  which carry a nested `typescript@6` in the lockfile. The fetch client never loads it (generation
  was verified with every TypeScript copy moved out of `node_modules`); it is an install-size cost,
  not a runtime dependency. orval drops header parameters, and the spec's only one is logout's
  `Cookie`, which the browser sends itself. Two page tests (Standards, SystemZoom) asserted on the
  microtask a request landed in, which openapi-fetch's awaited middleware happened to delay; they
  now wait for the outcome, and each still fails if its guard is removed.
- **Context:** openapi-typescript and openapi-fetch are in maintenance mode, and openapi-typescript
  calls the TypeScript compiler API at generation time, so its peer range (`typescript ^5`) blocked
  the TypeScript 7 bump (Dependabot #1465). The choice was weighed on five criteria: active
  maintenance, TypeScript 7 with no runtime dependency on the compiler API, a typed fetch client,
  deterministic output (`make gen-drift` diffs it exactly), and the size of the call-site change.
  orval meets all five: actively released, emits source by string templates, has a fetch client
  with a custom transport, and with prettier off its output depends only on the spec and its
  version (two runs produce identical files).
- **Rejected:** `@hey-api/openapi-ts`: actively maintained with a good fetch client, but it builds
  its output with `ts.factory` from the installed `typescript` and fails under TypeScript 7, whose
  package no longer exposes the compiler API. `swagger-typescript-api`: depends directly on
  `typescript ^6`. Kubb: also builds through the TypeScript factory. Staying on openapi-typescript
  with an `overrides` pin: the issue forbids it, and it keeps a maintenance-mode generator on the
  critical path. Hand-editing every call site onto orval's per-operation functions: 331
  edits for no gain in type safety, where one generated index and one façade in `client.ts` keep
  every call site as it was.
