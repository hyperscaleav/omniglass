- **Date:** 2026-11-09 | **Status:** Accepted | **Pages:** [nodes](/architecture/nodes/), [collection](/architecture/collection/), [commands](/architecture/commands/)
- **Decision:** (#1637, the first child of #1624; recorded before any of it is built, so the children build to one model.)
  1. **Per-kind queues, each with its own timer and bounded pool.** The heartbeat publishes liveness only, on its own timer. The worklist pull keeps its own interval (ADR-1577). Polls and probes share one scheduler keyed on each task's own interval, feeding a bounded poll pool (#1634). Commands are woken by a server push with a fallback pull and run on a bounded command pool (#1635). Each held session is one supervised goroutine, with bounded establish concurrency (#1636). Housekeeping (the spool's retry, the collection report window, self-logs) runs on its own timer. No work waits on the heartbeat.
  2. **One exclusion key across kinds: the endpoint.** Discrete requests to one endpoint (scheduled polls, probes that open a connection, commands, an operator's run now, and a driver preview whose transport and target match an inventoried endpoint) serialize in that endpoint's lane (#1249's key, re-keyed from the component). Endpoints run in parallel, two endpoints of one component included. Each lane's queue has two classes: operator-initiated work (a preview, a run now, an operator-issued command) is dispatched ahead of scheduled work, FIFO within a class, and nothing preempts a request in flight. Listen tasks are never lane-serialized (ADR-0151). More than one request in flight to one endpoint comes only from a held session's explicit per-endpoint pool size (#1254, default 1), which settles the nodes page's open question on intra-endpoint concurrency. A driver's opt-in to component-wide exclusion, which keys that component's lane on the component, is #1649.
  3. **One endpoint gate, holding a set of reasons, is the readiness check.** Every endpoint has one gate: today's layered gate (ADR-0158), generalized. It holds a set of reasons, each with a kind, a since time, a source (the probe, a command, an upstream component) and its own release rule, and it is open only when the set is empty. Today's terminal refusal becomes one reason, `refused`, with no change in behavior. Three triggers add the others: the probe adds `unreachable` after two consecutive failed verdicts and one up verdict removes it (#1650); a disruptive command adds `disrupted` to its hold set, followed by a quiet period with no connectivity attempts, then each endpoint's first up verdict releases it, with a backstop behind (#1651); a closed gate upstream adds `upstream` to the endpoints reached through it, over path edges, and a dependent is not probed while held (#1652, the edges from #1648). While the gate is closed, a due poll is skipped and counted in `poll-held-count` (not loss), and a command, a run now or a preview answers at once with the reason instead of queueing. **Lanes are separate from the gate:** a lane consults the gate at dispatch and holds nothing itself.
  4. **Timers, not ticks; skip, not burst.** A task runs at a stable phase on its own interval, with no rounding to the heartbeat. A run still in flight at its next due is skipped and counted, never queued twice. Lateness (the start minus the due time) is measured and published (#1625).
  5. **A batch is a flush window, not a tick.** Groups coalesce in the spool's flush (1s or 512 KiB, whichever comes first), which already holds without a tick; ADR-0311's "one batch per tick" reads as one batch per flush window.
  6. **Pool sizes are flags with env vars now,** and a node-leaf cascade value once #1351 lands. Defaults are set from the scale lab's measurements, not guessed.
  7. **Shared state has a named owner.** The session maps (the session manager's held, refused and pin maps) stay owned by the run-loop goroutine: only it adds or removes an entry. The state pool workers write gains a lock: the poll schedule (`pollSchedule`), the verdict memory (`verdicts` and `faultseen`, today plain maps in the run loop) and the collection report (`collectionReport`). The gates (`gates.mu`) and the spool (`telemetrySpool.mu`) already hold their own. How a pool worker reaches a held session without touching the maps is #1636's to settle within this rule.
  8. **Load distribution across a site's nodes** is a later decision built on this model and its capacity signal (#1638).
- **Context:** The node is one `select` loop: on each heartbeat it publishes liveness, then runs the whole worklist serially, then pulls and runs commands, then flushes the sessions' unclaimed lines. A slow poll delays the heartbeat, every other poll and every command; a poll's `schedule.every` is honored only at heartbeat granularity (ADR-0152); a probe runs every tick when `--probe-every` is unset (ADR-1273); and the nodes page described pieces of a target (a bounded poll pool behind `--workers`, component lanes) with no single model, its overrun rule (the next tick fires at once) contradicting skip-not-burst. The children of #1624 would each have invented their own.
- **Options weighed:**
  - **Keep the tick and parallelize within it** (#1249 as filed): each tick fans its work out across component lanes and waits for them. It is the smaller change, but a task's cadence still rounds to the heartbeat, one slow lane holds the next tick (or the tick overruns and bursts), a command still waits for the next tick, and the heartbeat still waits on collection. Not chosen.
  - **Per-task timers with per-kind pools** (chosen): every kind runs on its own timer, the heartbeat is liveness only, a command runs the moment it arrives, and the one invariant that matters to a device (one of our requests at a time) is held by the endpoint lane, not by a loop's serial order.
- **Not chosen:**
  - **The component as the lane key.** A component with two endpoints (a server with a management port) would serialize unrelated connections; the case a component key served (a reboot taking out both endpoints) is the gate's `disrupted` reason, and a driver that truly needs one request per component opts in (#1649).
  - **The overrun-aware loop** (the #430 fence's next tick fires at once). It queues a second run of work already late, which is a burst; a skipped run that is counted surfaces falling behind without adding load.
  - **The gate inside the lane.** A lane that blocked while its endpoint was down would queue operator work behind an outage; a gate the lane consults lets that work answer at once with its reason.
