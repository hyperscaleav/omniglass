- **Decision:** (#1024, slice 1 of epic #1146, approved as recommended on 2026-10-25: decisions 1, 2 and 6 of the epic, with the inbox of decision 4 brought forward from slice 2 for the webhook route.)
  1. **A push transport, and the listener primitive.** `webhook` joins the transport registry as its first push transport (`Push`): nothing is dialed, so it has no rung, no reachability task and no ladder (a ladder declared on one refuses at write), and its endpoint reads last heard (`endpoint_live.last_seen_at`, stamped by every attributed post) in place of a verdict, never down for silence. The listener primitive is one pipeline a host runs on each message: bound (token buckets per source, per endpoint and for the listener; a cap on posts in flight in all and per source; a 1 MiB body, the read stopping there; a read deadline), authenticate, attribute, route (listeners first, ADR-0151), extract, land. Its core is placement-agnostic and pure (`internal/ingress`); the server hosts it for webhooks, a node for the push transports of #1148 onward (decision 1).
  2. **The token is a sealed secret, minted by the endpoint.** Creating a `webhook` endpoint (bare or through a driver) mints a 128-bit token, sealed as the `webhook-token` secret on the endpoint's component, so it is revealed and copied only under `secret:reveal`, audited, scoped through the component and deleted with the endpoint. Its one field is lifecycle-origin: no operator creates or edits one (creating a secret whose every field is the platform's refuses). The receiver finds the endpoint by the token's sha256, held beside the binding (`webhook_token`); the token is random, so its digest is no oracle. `POST /endpoints/{endpoint}:rotateToken` mints it anew, the old token resolving to nothing at once. A webhook endpoint takes no node (decision 1: webhooks are central) and names one component.
  3. **The route is ungated by necessity.** `POST /webhooks/{token}` (and the `GET` and `HEAD` a sender verifies its URL with) carry no principal, on the allow-list beside `POST /nodes:claim`: the sender is not a principal, the endpoint's declared scheme is the authentication, and the write is bound to the token's one endpoint. The batch is published on the push lane with that endpoint's component as owner, whose writer admits only `collected` keys (ADR-0161), so a leaked token can write only collected keys on one component; no new writer class.
  4. **The schemes** (decision 6). A webhook driver declares `session.scheme`, never defaulted: `hmac` (an `hmac-key` secret; the signature's header, algorithm sha256 or sha1, hex or base64, an optional prefix, and an optional signed timestamp header joined to the body by a separator), `token` (a `bearer-token` in a declared header behind an optional prefix), `basic` (`basic-auth`), or `none`, which checks nothing and reads **unsigned** on the endpoint. hmac over a signed timestamp is the scheme the docs teach first. Every secret comparison runs in constant time over a fixed-length digest. The check fails closed: a credentialed scheme whose secret no longer resolves, or holds an empty field, refuses every post rather than comparing against the empty string.
  5. **Replay.** A signed timestamp more than five minutes from arrival, either side, refuses; a declared delivery-id header is remembered per endpoint for that window (bounded, in the server's memory: it is one replica), so a sender's redelivery answers 202 and lands once, and a delivery whose publish failed is forgotten so the retry lands.
  6. **The response contract.** Senders retry on anything but 2xx: `202` only once the batch is published; `401` for a refused scheme, saying nothing of which part failed; `404` for an unknown, rotated or malformed token, byte-identical; `413` past the cap; `429` with `Retry-After` past a limit; `5xx` only for our own fault. A `GET` answers the challenge a driver declares (`webhook.challenge`, a query parameter echoed as bounded text), `204` where it declares none.
  7. **Attribution** (decision 2). The token names one endpoint and so one component; nothing in the payload selects further.
  8. **The body, and the raw line** (decision 5). The body is read in the format the driver declares (`json`, `xml`, `form`, new and read by `key`, or `text`) through the one extraction primitive; a listener's match may read a declared header (`match.header`), never a credential's. What no listener claims lands as a log line on a push transport (`unmatched` may only be `log`), and a claimed post lands its raw line beside its emits unless the listener declares `log: false`; a claimed post whose emit faulted keeps its raw line with the fault, whatever the listener says. A bare webhook endpoint lands every post as a log line.
  9. **Refusals are counted, never gated.** An inbound auth failure is not a session to reject: it never reads rejected and never sets `endpoint-rejection`. It answers 401, is tallied per endpoint, source and reason, flushed once per tick to the endpoint's counters (shown on its read: the count, the latest time, source and reason, never the credential) and logged once per tick.
  10. **Unknown senders land in an inbox** (decision 4, brought forward). A post to a token no endpoint holds is tallied by its sender's address into `unclaimed_source` (per listener host and transport: a count, first and last heard, the last message cut to 512 bytes; bounded at 256 sources per listener, the least recently heard evicted; aged out after seven days), read at `GET /unclaimed-sources` under `node:read`. The token a stranger tried is never kept. Claiming one is the existing endpoint create, and a source's row is let go once its posts land on an endpoint. A sender's address is the first `X-Forwarded-For` hop where the server sits behind its ingress (Traefik overwrites the header from an untrusted client), else the connection's.
- **Context:** #1024 asked for server-hosted ingress (webhooks, traps and syslog) with a plaintext `params.secret`, a `?token=` query and a comma-separated extract grammar. Epic #1146 split it: traps and syslog move to the node (#1149, #1150), the token becomes a sealed secret and the schemes declared, and the mapping becomes a driver's listeners over #1145's emits. The proof is the simulated UCC service, whose admin API now takes a webhook subscription (the URL, the scheme, the secret, and a fault that posts a wrong signature, a stale timestamp or one delivery twice) and posts each meeting's start and end signed; the shipped `ucc-webhook` driver maps them to `call-started`, `call-ended` and the `call-state` property, end to end over the real wire.
