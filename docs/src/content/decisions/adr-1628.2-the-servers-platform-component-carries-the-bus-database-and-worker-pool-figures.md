Each server reports those figures on its one `omniglass-server` component instead (#1627, #1628, #1671), each told apart by its key and instance, because every one is the server process's own view: its consumer, its pool, its ticks. A component for the NATS or Postgres service itself, read from that service's own side, is a later decision."

- **Date:** 2026-11-10 | **Status:** Accepted | **Pages:** [collection](/architecture/collection/#self-monitoring-the-servers-account-of-itself)
- **Decision:**
  1. **One component per server process, no bus, database or worker-pool component.** #1094's spec
     made the server, each node, the bus, the database and the worker pool components of the
     platform system. What shipped is one `omniglass-server` component per server identity
     ([ADR-1627](/architecture/decisions/#adr-1627-a-server-reports-its-request-and-query-timing-by-route-template-and-statement-fingerprint)),
     and the figures #1094 gave the other three land on it: the telemetry consumer's backlog, drops
     and redeliveries and the bus request paths' failures (#1628), the database pool and slow queries
     (#1627), the calc, notification and settlement ticks (#1628) and the retention pass (#1671).
     A key and its instance (`bus-request-failure-count` per path, `sweep-duration` per sweep) say
     which part of the server a figure is about.
  2. **Every one of those figures is the server's own view.** A pool is per process, so two servers
     have two pools and a shared database component would have to merge or overwrite them. The
     consumer's lag and drops are what one server's consumer saw, not the stream's state. There is no
     worker pool: the consumer keeps one batch in flight and the rest are ticks inside the server
     ([workers](/architecture/workers/)). Putting these on a component the server does not own would
     need a writer that speaks for a shared thing, and the platform writer class admits only the
     process speaking for itself
     ([ADR-1625](/architecture/decisions/#adr-1625-a-node-reports-itself-on-its-platform-component-and-platform-keys-take-no-prefix)).
  3. **The services themselves are a later decision.** A component for the NATS server or the
     Postgres server, read from that service's own metrics rather than from a client's view of it,
     is not built and is not ruled out; it would be filed under #1094 when a figure only the service
     can report is needed.
- **Context:** #1094 is the self-monitoring epic; its sub-issues #1625, #1627, #1628 and #1671 built
  the node and server components and their figures. No entry recorded that the bus, database and
  worker-pool components were not built, so the shipped server component contradicted the design
  it was built under.
