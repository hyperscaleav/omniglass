- **Date:** 2026-11-18 | **Status:** Accepted | **Pages:** [docs with everything](/contributing/docs-with-everything/#status-moves-with-the-code), [implementation status](/architecture/status/)
- **Decision:** (#2087, amending [ADR-2087](/architecture/decisions/#adr-2087-the-rewritten-pages-are-the-architecture-of-record-the-architecture-pages-archive).)
  1. **No archive section.** The architecture pages do not move under an archive with a banner and frozen
     badges. The whole site, guides included, is rebuilt by audience (#2153), and git holds every page it
     replaces.
  2. **The old pages lose their badges now.** No page carries a status badge until it is rebuilt. The
     implementation-status grid and the badge-fence lint read a badge on any page, in any section, so both
     start empty and fill as the rebuilt sections land.
  3. **The old pages leave at cut-over, per section.** An old page stays the reference for its capability,
     kept true when a slice falsifies it, until the PR that rebuilds its section deletes it. The lints keep
     covering it while it lives; nothing exempts it.
  4. **What survives.** The decision log and the build log (one file per entry, cited by code and skills),
     the generated reference (CLI, MCP, OpenAPI, glossary), and the screenshot and demo tooling move into
     the new layout as they are.
- **Context:** ADR-2087 archived the architecture pages in place and moved the badges to rewritten overview
  and guide pages. The rebuild grew to the whole site, laid out by audience on a current docs platform, so
  an in-site archive would have kept a second copy of every page the rebuild replaces, plus lint
  exemptions to keep it frozen. Deleting a page as its replacement lands keeps the published site whole at
  every step and leaves nothing frozen to maintain.
