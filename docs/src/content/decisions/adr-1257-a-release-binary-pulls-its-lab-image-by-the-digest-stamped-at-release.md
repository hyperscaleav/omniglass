- **Date:** 2026-11-14 | **Status:** Accepted | **Pages:** [try omniglass in five minutes](/guides/lab/#flags), [container image](/guides/container-image/#where-it-ships)
- **Decision:** (#1257.) Amends [ADR-1193](#adr-1193-the-omniglass-lab-is-one-command-to-a-docker-project-and-make-only-builds)'s "the image follows the binary's version" for release binaries. `release.yml` builds and pushes the multi-platform release image (the same metadata and build actions as `image.yml`, the release version as its `VERSION`) before goreleaser runs, and passes the pushed manifest's digest as `IMAGE_DIGEST`, which `.goreleaser.yaml` stamps as `main.imageDigest` beside `main.version`. `lab.SelectImage` runs a release version with a well-formed digest as `ghcr.io/hyperscaleav/omniglass@<digest>` (the status line still names the tag), and refuses a release version with no digest with a preflight error naming `--image`; it never falls back to the tag. `--image` and dev builds are unchanged. `release.yml` becomes the only release path: `make release-apply` is retired, `goreleaser.yml` keeps only its PR snapshot (a pushed tag no longer builds binaries), and `image.yml` no longer builds a `v<version>` image on a tag. The workflow publishes nothing until the repository variable `RELEASES_ENABLED` is `true` (Fred, 2026-11-14: "I don't want to start doing releases yet"); until then a dispatch only dry-runs, and #1940 tracks the flip. The `v*` tags are protected by a repository ruleset (no deletion, no update), a GitHub setting rather than a file in the tree.
- **Consequences:** A release binary runs exactly the image its release was built with, whatever the tag points at later, and checks it with no verifier on the learner's machine. Every published release binary carries a digest, because the one path that publishes builds the image first. A binary given a release version some other way (a local build of a tagged tree) carries none and refuses the lab until given `--image`. The release workflow's image skips `image.yml`'s arm64 and lab smokes; the same commit passed them on `main`.
- **Context:** The adversarial review of the lab (#1193, #1194) found that a release binary pulled `v<version>` by tag and checked nothing, and a re-pushed `v*` tag rebuilds that image, so whoever could push a tag replaced the image every uncached release binary runs, whose node container holds root and `NET_ADMIN` in its own namespace.
- **Not chosen:**
  - **Verify a signature.** #58 and #59 sign the macOS and Windows binaries, not the image, and are open; a signature check needs a verifier and a trust root on the learner's machine, where a digest needs neither.
  - **Keep `make release-apply` beside the workflow.** A tag pushed from a workstation cascades to tag-triggered workflows that build the binaries and the image in parallel, so those binaries could not carry the digest; two paths also mean two sets of credentials that can publish.
  - **Fall back to the tag when no digest is stamped.** It reopens the hole for every binary the release workflow did not build.
