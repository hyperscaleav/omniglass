- **Date:** 2026-10-27 | **Status:** Accepted | **Pages:** [try omniglass in five minutes](/guides/lab/), [simulation](/architecture/simulation/), [nodes](/architecture/nodes/), [scaling and deployment](/architecture/scaling/), [install](/guides/install/), [the CLI](/guides/cli/), [container image](/guides/container-image/), [design system](/contributing/design-system/)
- **Decision:** (Epic #1193; slices #1198, #1194, #1195, #1196.) The architect's rulings of 2026-10-26, and the eight open decisions taken as recommended:
  - **Docker is required.** There is no native mode: a lab is worth running only if collection behaves as against real gear (an address per component, the profiles' real ports, truthful ping, impairments), and each of those leans on Linux networking that a bare binary on macOS or Windows does not get. Docker runs every container on a Linux kernel on all three platforms. Embedded Postgres (#19) moves back to #57.
  - **Three containers, `db`, `server` and `node`,** on one private bridge, two named volumes (the database, and the server's data directory with the lab's own encryption key), and only the console published.
  - **The command is `omniglass lab run`,** with `make lab` the short form: a run mode is a verb under its noun ([ADR-0058](/architecture/decisions/#adr-0058-a-run-mode-is-a-verb-under-its-noun-and-no-command-may-be-shadowed)), which leaves room for later verbs without a rename.
  - **`127.0.0.1:8080` by default.** A taken port fails preflight, naming the port and `--port`, rather than silently moving; `--port 0` lets Docker pick. Any other address needs `--listen`, which warns.
  - **The seed is the dev fleet** (`--scenario` picks another), the fleet every walkthrough is recorded on, with the login `dev`/`dev`.
  - **The demo pipeline's move (#1197) unifies only the full-stack consumers** (walkthroughs, tapes, the probe, the walkthrough stack); `make test-e2e` and `make docs-shots` keep the Postgres-and-server half of `stack.sh`. Recordings show the lab banner, re-recorded once. **Amended (#1197):** as built, a recorder or the probe runs `./bin/omniglass lab run` as a throwaway lab (`web/e2e/lib/lab.sh`) through three hidden script flags: `--ephemeral` (a project of its own, refused for `omniglass-lab`, whose volumes go at teardown, and an abandoned one of any project is reaped by the next run on the host), `--ready-file` (once ready, shell assignments saying how to reach it: the network, the server there, an owner token minted for the run, the containers and the labels a helper container carries to be torn down with it) and `--while-pid` (the hold ends once the script's process is gone, and the script's Ctrl-C is its own). Three divergences from the definition: the script's lab still publishes the console, on a loopback port Docker picks, rather than nothing, because the lab reads its own readiness and signs in from the host, which only a published port reaches on every platform (Docker Desktop routes no bridge address to the host), while the recorder still reaches the server on the lab network; the per-container log files are the recorder's own `docker logs` followers, and the simulator's log is the node's, since it runs in the node's process; and `bay-2-display` moved into a walkthrough `setup` (API creates made off camera before the title card, an existing one counting as made), which the lab guide lists for a learner as the CLI command that makes it, rather than into the dev seed, whose fixtures keep every component nameless and Bay 2 empty on purpose. The walkthrough stack's impairment check retires into `make test-lab`, which already proves it.
  - **The `lab-first-run` tape records the command itself,** with an opt-in Docker socket mount for a tape that declares it, on the CI runner only.
  - **The console's fast loop is the documented Vite proxy** against a running lab (`cd web && npm run dev`), targeting `http://127.0.0.1:8080` and moved by `OMNIGLASS_LAB_URL`, not a `--console-dev` flag a release user could not use.
  - **The lab drives the Docker Engine API** with the moby client and stamps compose's project labels on every container, network and volume, so `docker compose -p omniglass-lab ps` and Docker Desktop see one project, rather than generating a compose file for a compose binary not every Docker ships.
  - **`omniglass node run --simulate`, not `node sim`:** the simulator runs in the node's own process, on the node's own identity, so the simulated components sit on the loopback the node collects from by construction. `--impairments`, `--port-offset` and `--poll` are refused without `--simulate`; `omniglass sim run` stays for a separate process. This extends [ADR-0142](/architecture/decisions/#adr-0142-the-simulator-is-a-run-mode-beside-its-node-holding-that-nodes-identity): the simulator still holds its node's identity, now optionally in its process.
  - **The image follows the binary's version.** A dev binary runs `omniglass:dev`, checked through the OCI label `org.opencontainers.image.version` against the build id `make` stamped into both; a missing or mismatched image is refused, saying run `make`, and the lab never builds. A release binary runs `ghcr.io/hyperscaleav/omniglass:v<version>`, which a release tag now publishes. `--image` overrides, with a warning.
  - **`make` only builds.** The bare `make` builds the image and exports the host binary from one Dockerfile with nothing but Docker; `make dev` builds and runs `npm install` in `web/`. `make dev-sim`, `make up`, `make down`, `docker-compose.yml` and `SIM_PORT_OFFSET` retire; the dev seed aims at the real ports.
  - **The lab mark is a table whose one row is data the lab writes,** never a migration row or a boot-seed row (the three buckets). A server outside lab mode refuses a marked database; a lab refuses a database that holds data and no mark.
- **Context:** Running omniglass to learn on took a Go and Node toolchain, `make dev`, `make dev-sim` and their port lift, or the demo pipeline's bash stack, and none of them gave a learner the real ports, truthful ping and impairments on macOS or Windows. **Divergence from the definition:** the definition named the lab's one-offs as the owner, the dev seed, a token and the enrollment; the lab collapses them into one hidden `omniglass lab seed` one-off, run in the lab's own image on every start, which migrates, marks the database, seeds the fleet and the owner on the first run only, and enrolls the node with the token minted for that run. And readiness counts every simulated endpoint up except two kinds the definition did not name: an endpoint that receives pushes (a webhook carries no reachability verdict) and the seed's planted faults, which the seed marks itself (`planted_fault` in the dev fleet's fixtures) rather than a hand-kept list.
