- **Date:** 2026-10-29 | **Status:** Accepted | **Pages:** [simulation](/architecture/simulation/#a-simulated-service-posts-from-the-start), [lab](/guides/lab/), [collection](/architecture/collection/#collection-telemetry-every-endpoints-account-of-itself)
- **Decision:** (#1370, ruled 2026-10-29 by the architect on #1370.)
  1. **The simulator holds what the SaaS would hold.** A webhook's URL carries a token the server mints at the endpoint's creation, so a profile default cannot name it, and a simulated device's state begins again from its defaults on every simulator restart, so a one-time subscribe is lost. The simulator plays the external service that posts to the endpoint, so it is handed what that service's admin would configure: the endpoint's path and the secret its scheme signs with (the hmac key, the token, or `user:password`). The server's simulation device list (`collection.SimDevice.Webhook`) carries it; the simulator calls the profile's declared subscribe route (`webhook.subscribe`, a POST taking `url`, `scheme` and `secret`) with the server URL it already reaches plus the path, once per device instance and subscription, and again for a restarted device.
  2. **The fence.** The subscription rides only the simulator's device list, which only a simulator pulls (`node run --simulate`, `sim run`), on the node's own subject grant; a node's worklist never carries a webhook token or key. It is handed only for a component the node's endpoints reach on a loopback address, the simulator's own; a real device on the network is never handed its webhook. `TestSimlistCarriesAWebhookSubscriptionToTheSimulatorAlone` holds both halves: the simulated service gets its subscription, the real one none, and the worklist carries neither token nor key.
  3. **A first-party pusher with one grant.** The lab exercises `POST /telemetry:push` from a simulated booking service, a service principal whose one grant is a `telemetry-pusher` role holding `telemetry:push` alone, scoped to one system (the HQ boardroom's), exercising a system-owned push (ADR-0422). It reads its system off its own grant, so it pushes nowhere else and reads nothing. Its token is minted per lab run and handed over as the node's is: the plaintext to the simulator, the hash and non-secret prefix to the seed, which makes it the principal's only token. A push has no endpoint, so it counts on its collected tier alone.
- **Context:** #1266 set the bar that every collection method runs healthy in the lab on both tiers; #1370 found the simulated UCC service's `target_url` empty by default, so no webhook posted until an operator subscribed it, and nothing in the lab pushed through the API.
- **Not chosen:**
  - **The lab seed subscribes once, through the server's simulator-operate path.** A node or simulator restart loses it.
  - **A seed-supplied fixed token.** It weakens "the server mints the token" for every install to serve a lab.
  - **The token and key on the node's worklist.** Every node pulls its worklist, simulating or not; only the simulator plays the sender.
