- **Decision:** (#1145, approved as recommended on 2026-10-25, the shared primitive under epics #1146 and #1147, the architect's direction that any collection method maps into any of the four lanes.)
  1. **Three catalogs, one emit.** An emit's name resolves against `metric_type`, `property_type` and `event_type` (already one namespace), the lane baked at attach. An event emit declares a `message` (a constant or an extract, by default the whole claimed message or answer) and `attributes` (each a constant or an extract; a cast to int or float renders a JSON number), held at write to the type's `payload_schema` where it closes or requires fields. A reserved event type (`collection-failed`, `command-issued`) is refused at write naming its writer, as a reserved metric is ([ADR-0161](#adr-0161-every-key-has-one-writer-class-held-at-the-storage-gateway)).
  2. **A log line has no catalog name.** It declares `log` (its `severity` and `facility`, each a constant or an extract, and its `source`, by default the endpoint's transport) with a `message` and `attributes`. A log line is raw arrival ([ADR-0066](#adr-0066-logs-are-a-raw-ingest-lane-not-events)), so it always lands: a message extract that misses falls back to the whole text, and a severity, facility or attribute that misses is left out, each miss a fault naming it. An event is an assertion, so a field that misses lands nothing.
  3. **A time from the payload, on any lane** (decision 3). `ts` is an extract and a layout (`rfc3339`; `rfc3164`, whose missing year is the one nearest arrival, in a declared zone; `unix`; `unix-ms`; `go:` a Go reference layout). A time past five minutes ahead of arrival lands at arrival, a log line keeping the claim as `ts_claimed`, a sample counted in the node's self-log; one that does not parse lands at arrival and faults.
  4. **A task's log lines have a wire field of their own.** `TelemetryBatch.task_logs` carries a component's lines a task collected, beside the node's self-logs in `logs`, so one batch carries both and neither lands in the other's table; ingest writes them to `log_line` on the task's component, its endpoint the line's instance, owner-bound server-side from the task as every sample is, and an orphan batch lands none. A log line carries `received_at`, the server's receipt, beside the time it claims.
  5. **Unclaimed messages may land.** `unmatched: log` lands each message no listener claims as a log line under the endpoint's first listen task, an event's name kept as an attribute; held sessions keep their `discard` default.
  6. **Occurrences fire on change on a plain poll** (decision 2): a poll's event or log line lands when its content differs from what that task last landed, remembered in node memory, so a status page's last error lands once per change.
  7. **One severity vocabulary, held at the gateway** (decision 1). Every `log_line` write is held to RFC 5424's eight levels (`emergency`, `alert`, `critical`, `error`, `warning`, `notice`, `info`, `debug`) through one alias table (`internal/logline`), a word it does not know left out and kept as `severity_raw`; a message and attributes past 16 KiB each are cut and marked, never refused (decision 4). The component and system log reads filter by a severity threshold and a source and list the window's sources. This severity is a source's classification of a line, distinct from the alarm severity ladder.
- **Context:** #603 promised that polled and pushed payloads parse into the five lanes, and the spec reached two: `LaneOf` loaded the metric and property catalogs alone, the node's batch builder routed text to properties and numbers to metrics, and on the node lane every log line was the node's own, so a component's line a node sent would have landed as a self-log. Push ingress (#1146) and file fetch (#1147) both map most of what they read to log lines and events, so the primitive is a Feature of its own under #603 that both epics consume. The proof is the shipped drivers on the simulator: the Newtron panel's input push lands as the `video-input` property and an `input-changed` event, its diagnostics line as a log line with its severity, and a push no listener claims raw; the Kestrel bar's feed reports a call starting and ending as named events (a simulated route may now declare named events), which `kestrel-api` lands as `call-started` and `call-ended` carrying the call's id. Retention for the log tables is this Feature's second part, #417.
