Three kinds of value are **set** by an operator rather than collected. They share the
[cascade](/architecture/cascade/), but differ in what they are keyed by and what lifecycle they
carry:

| | **variable** | **secret** | **declared value** |
|---|---|---|---|
| what it is | a free named value | a credential, encrypted at rest | the state a component or system should hold |
| keyed by | its own name | its own name, shaped by a `secret_type` | a canonical [property type](/architecture/properties/#the-two-catalogs) |
| resolves | down the cascade | down the cascade, no system band | on one owner, over its classifier's default |
| has an observed side | no | its validity, never its value | yes: what the device reports |
| example | `poll-interval = 30`, a base URL | an `snmp-community`, a `basic-auth` | `video-input = hdmi1` |

To operate them, see [variables](/admin/variables/), [secrets](/admin/secrets/) and
[properties](/admin/properties/).

## variable: a free cascaded value

A **variable** is a named value set at one level of the fleet and inherited below it: anything
spliced into behavior that is not a device signal and has no lifecycle. It is owned on the exclusive
arc at `platform`, a location, a system or a component, and resolves by scalar shadow down the
cascade.

- **The name is the operator's own**, with no catalog behind it, on the ordinary entity name rule
  (`newtron-ssh`, never `newtron.ssh`) and unique per owner. A **label** rides beside it for a person
  to read; the cascade resolves by name alone
  ([ADR-0119](/architecture/decisions/#adr-0119-a-table-an-operator-names-carries-a-label-or-declares-why-it-does-not)).
- **The type is inline**: a `value_type` of `string`, `int`, `float`, `bool` or `json`, stored as
  jsonb and checked against the type on write.
- **Operators write, admins delete**: `variable:create,update` sits on the operator role, `delete` on
  admin and owner. A write at the `platform` rung also needs `platform:<action>`.

:::design[Variables in text, tracked in #296]
A variable is written into text as `$var:<name>` (and a secret field as `$sec:<name>.<field>`), in an
endpoint input, a driver argument or a property value, and resolved at the moment it is consumed.
The token parser exists (`internal/secret`); no consumer splices a token yet, and the property value
that holds a source reference rather than a literal is
[#296](https://github.com/hyperscaleav/omniglass/issues/296).
:::

## secret: an encrypted cascaded value

A **secret** is an encrypted credential set at one level of the fleet and inherited below it
([ADR-0017](/architecture/decisions/#adr-0017-credential-is-renamed-secret-the-cascade-is-the-reuse-mechanism)).
It is its own primitive, stored sealed and read back only through a masked, audited path, never a
sensitivity flag on an ordinary value. It is owned at `platform`, a location or a component: a
secret authenticates a session with the device itself, so it has no system band. Shared versus
per-device is just where it is owned.

**Shape is a `secret_type`**: a per-field list of `{name, type, secret, origin}`, so a password field
is sealed while a username beside it stays plaintext, and `origin` says whether the operator or the
lifecycle fills it. `default_admin_sensitive` seeds the create form: a device type (`snmp-community`,
`basic-auth`) defaults to operational, a platform integration type (`oauth2-client`) to
admin-sensitive.

**Sealed at rest.** Each secret field is sealed with AES-256-GCM under its own data key, wrapped by
the **encryption key** and stored as a `{ciphertext, nonce, wrapped_dek, key_id}` envelope, with
`(owner, name, field)` bound as additional data so a ciphertext cannot be lifted into another row.
The key comes from `OMNIGLASS_ENCRYPTION_KEY`, from `OMNIGLASS_ENCRYPTION_KEY_FILE`, or from a
warned fallback under `OMNIGLASS_DATA_DIR`, behind a seam a KMS can later fill. The old names
(`OMNIGLASS_SECRET_KEY` and its `_FILE`) are still read, with a warning, when neither new name is set
([ADR-0558](/architecture/decisions/#adr-0558-the-key-that-seals-every-secret-is-the-encryption-key-and-its-old-names-are-read-for-one-release)).

**Masked everywhere but an audited decrypt.** Every read masks a secret field (`••••••`). Reading
the plaintext is `secret:reveal`, as an on-screen `:reveal` or a clipboard `:copy`, each recorded on
the [audit log](/architecture/audit/) under its own verb. Naming a secret where it will be used (an
endpoint's input, a notification target, the mail relay) takes `secret:bind` on it
([identity and access](/architecture/identity-access/)).

**Two axes decide who reaches a secret**
([ADR-0025](/architecture/decisions/#adr-0025-secret-is-a-sensitive-resource-a-per-secret-admin_sensitive-flag-flips-a-secret-to-the-admin-tier)).
Placement scope gives locality: a field tech scoped to Singapore works the device secrets under
Singapore, not one owned at `platform`. The per-secret `admin_sensitive` flag gives same-scope
sensitivity: when set, every action on that secret lifts to the `:admin` tier.

- `secret` is a sensitive resource off the bare read floor: a viewer reads none, an operator holds a
  scoped `secret:read,reveal,bind,create,update`, and `admin` holds `secret:>`, which reaches the
  `:admin` tier.
- The `/secrets` directory is scope-filtered and hides admin-sensitive rows from a caller without the
  admin tier; revealing, updating or deleting one without it is the non-disclosing 404.
- Creating an admin-sensitive secret needs `secret:create:admin`. Delete stays with admin and owner.

**A platform secret may come from the environment**
([ADR-2223.2](/architecture/decisions/#adr-22232-a-platform-secret-may-be-declared-by-the-servers-environment)).
`OMNIGLASS_SECRET__<NAME>` declares a `platform` secret named `<name>` (lowercased, each `_` a `-`),
its value one JSON object `{"type": "<secret type>", "fields": {...}}`. The boot checks it against
the `secret_type` catalog as a create would and fails naming the variable, never quoting the value,
when it does not fit or collides with a stored platform secret. It is held in memory only: never
sealed, stored or audited, and changed by a restart. The directory lists it with `source: env` and no
fields, and a write to it is a 409 naming the variable to change instead.

:::design[The secret lifecycle and validity health, tracked in #2615 and #1119]
A secret gains a lifecycle, each part a declared use of driver commands and the clock:

- **Refresh** of an oauth2 access token, lazily on use within a skew of expiry
  ([#1119](https://github.com/hyperscaleav/omniglass/issues/1119)).
- **Rotation** as a flow: generate, set on the device through a driver command, store, verify, retire
  the old value, on a schedule ([#2615](https://github.com/hyperscaleav/omniglass/issues/2615)).
- **Expiry**: a stated or intrinsic expiry (a certificate's `notAfter`) raises an alarm before it
  lapses.
- **Validity health**: authentication failures consumers report flip a secret unhealthy after a run
  of them. A secret's health is its validity, never its value.
:::

## Declared values: device state, keyed to a signal

A **declared value** is the state an operator says a component or system should hold. It is the
declared side of a canonical signal: `video-input` is one key with two sides, the **observed** value
the device reports and the **declared** value an operator sets, and their gap is **drift**.

A declared value is a row in the property series itself, `provenance = 'declared'`
([ADR-0079](/architecture/decisions/#adr-0079-five-telemetry-lanes-and-property-stops-being-the-genus)):
an edit appends, an unset appends a tombstone, and the current value is the latest row
([properties](/architecture/properties/#declared-an-operators-assertion-as-a-series-row)). It
resolves on one owner, over the default its classifier's contract declares
([declared properties](/architecture/core-entities/#declared-properties-the-classifier-contracts-and-the-declared-rows)),
and is written with `PUT /{components,systems,locations}/{name}/properties/{property}`. Each piece
has one home:

| Piece | Lives in |
|---|---|
| the signal: name and value domain | the `property_type` catalog |
| how a class of component reads and writes it | the **driver**: an emit reads it, a command binding writes it |
| the declared value | a `declared` row in the `property` series |
| the observed value | `observed` rows in the same series |
| drift | computed on read, never stored |

The driver is the source of truth for whether a signal is settable on a class of component: it
must both read it and bind a command that writes it. A driver brings no keys of its own; it references
registered ones.

### Drift and reconcile

Drift is computed on every properties read: each row carries **want** (the declared value, or the
contract default), **told** (the last command's intended value) and **is** (the observed value), and
`drift` is true when an observed instance disagrees with want
([reconciliation](/architecture/properties/#reconciliation-want-told-is)). Nothing acts on drift yet.

::::design[A declared value's reconcile policy, tracked in #1248]
A per-item `reconcile` policy turns drift into action:

- **`observe`** (default): record the drift and show it; no alarm.
- **`warn`**: raise a warning alarm on the owner; change nothing.
- **`enforce`**: the declared value wins. Issue the signal's command through the driver's binding,
  which writes an intended row and settles against the next observation; raise an alarm if the set
  fails.

Adopting the observed value as the declared one is a separate one-shot import, never a mode. With
`enforce`, remediation needs no rule: declare, enforce, and the cascade, drift and the command
binding close the loop, with a per-item backoff so a refusing device is not hammered. Declaring on a
standard's slot (`video-input = hdmi1` on the main-display slot) reaches whichever display fills it.
The contract gains a driver access column (get, set, or declare-only) beside the policy.
::::

:::design[Target design: values across owners, sources and files, tracked in #1255, #296 and #242]
- **Across owners**: a value resolving down the cascade (product, location, system, component),
  deepest wins, rather than on one owner over its default
  ([#1255](https://github.com/hyperscaleav/omniglass/issues/1255)).
- **Sources**: a value that holds a reference (a variable, a secret, a sample, a file) rather than a
  literal, with the picker that sets one ([#296](https://github.com/hyperscaleav/omniglass/issues/296)).
- **File typing**: a `file` data type giving an attached file a role by the property it fills, a
  floor plan or a firmware image ([#242](https://github.com/hyperscaleav/omniglass/issues/242)).
:::

## Storage

`variable` and `secret` are separate tables, since a secret carries sealing and a masked read path a
variable does not; both own on the exclusive arc and are keyed for the cascade by name. A declared
value has no table of its own: it is a [`property`](/architecture/properties/#the-sample-tables)
row. The physical layout is on [storage](/architecture/storage/).
