A **group** is a named set of entities that cuts across the structural trees. The tree handles
configuration by position and kind; a group handles it by attribute or by a hand-picked set ("all AV
displays"). One primitive is meant to serve two jobs, a [cascade](/architecture/cascade/) overlay and
an [access](/architecture/identity-access/) scope, which an anonymous predicate cannot.

## What is built: user groups

Built end to end is the **user** kind: `user_group` and its membership, group-targeted grants
(`user_grant.group_id`), the effective-grant union in the loader, `/user-groups` CRUD gated by
`user_group:*`, and the console User groups pages. A user group is a **grant subject**: a grant
attached to the group reaches its members. It is not yet an access scope, and `scope_kind='group'` is
refused with a 422.

- A group's name is an ordinary entity name, checked by the Storage Gateway on create and rename
  ([ADR-0077](/architecture/decisions/#adr-0077-a-group-name-obeys-the-entity-name-rule-tightening-a-pattern-the-code-had-excused)).
- Renaming is the `:rename` custom method, gated by `user_group:rename`; the PATCH body carries no
  name ([ADR-0076](/architecture/decisions/#adr-0076-a-renameable-human-typed-identifier-stays-in-the-url-and-the-write-returns-the-uuid)).
  Membership and grants key on the group's uuid, so a rename moves nothing.
- Every route takes the group by name or uuid, and a member by username, machine user name or
  uuid ([ADR-1133](/architecture/decisions/#adr-1133-every-operator-resource-answers-to-its-name-and-an-endpoint-is-its-component-and-its-name)),
  resolved only after the all-scope check so a scoped caller learns nothing about which names exist.

:::design[Entity groups on the cascade: weights, dynamic membership, and group-as-scope, tracked in #10]
The general `group` table adds component, system and location kinds, and:

- **Static or dynamic membership.** An explicit list, or a filter re-evaluated live, so a device
  leaves the moment it stops matching.
- **A weight.** A group sits on the cascade's one specificity scale by weight: high above deployment
  (a must-apply override), low below it. The scale and precedence key are stated once on
  [cascade](/architecture/cascade/#groups-overlay-the-cascade-placed-by-weight).
- **Bindings.** Variable, tag and rule bindings, folded with the cascade's per-kind combinators. An
  entity belongs to a flat set of groups with no second precedence axis, and
  [the resolve view](/architecture/cascade/#the-resolve-view) names the winner.
- **No nesting.** A dynamic filter already expresses a union, so groups do not contain groups.
- **Access scope.** The group is also a visibility and permission scope.

A type (device, room) is a classification attribute, never a tree position: author a dynamic group
filtered on type and place it by weight.

What it is for:

- **A fleet-wide fix that clears itself.** A dynamic group `model == "Room Kit Pro" && firmware < "11.5"`
  at high weight slows the poll and suppresses a false alarm, and each codec drops out when it upgrades.
- **A policy as a floor.** Stricter thresholds on a low-weight "PCI-scope" group, so a lab that needs
  its own values still wins.
- **A hand-picked set no filter can name.** Executive briefing rooms in a static group, with the
  exec-support team granted visibility to that same group.
:::
