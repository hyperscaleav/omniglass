A **tag** is an operator `key: value` label for a dimension Omniglass does not model natively
(`category: audio-dsp`, `environment: prod`, `cost-center: 4021`). It is not a signal and has no
lifecycle. It rides the same [cascade](/architecture/cascade/) as
[variables and secrets](/architecture/variables/), with one difference in how values combine. To
operate tags, see [the admin Tags page](/admin/tags/).

## Two layers: the key and the binding

- **`tag`** is the governed key vocabulary: one row per key, shared across the install. It owns no value.
- **`tag_binding`** is the value cell: one value for one key at one owner on the exclusive arc
  (platform, location, system, component or outpost), the same arc a variable is owned at.

Splitting them keeps the vocabulary normalized: `environment` is minted once and reused, so nobody
invents `env` beside `Environment`. An operator binds by the tag's **name**, an ordinary entity name
(lowercase letters, digits and hyphens, 100 characters, never a uuid), enforced by the [Storage Gateway](/architecture/storage/#the-storage-gateway-and-tiering), the one layer every database read and write passes through.
A key also carries an optional **label**, the friendly string an operator reads ("Cost Center"). The
label is not an identifier: it has no uniqueness and nothing resolves through it
([ADR-0119](/architecture/decisions/#adr-0119-a-table-an-operator-names-carries-a-label-or-declares-why-it-does-not)).

## Minting a key and setting a value are different permissions

- Minting a key is governance: an all-scope `tag:create` (and `tag:update`, `tag:delete`), held by an
  admin or curator ([identity and access](/architecture/identity-access/)).
- Setting a value is the ordinary entity write: binding `environment: prod` onto a component is
  `component:update`, and system and location likewise. A **platform** binding has no owning entity,
  so it takes `tag:update` plus `platform:update`.

The vocabulary stays curated while tagging stays routine. Reading rides the viewer floor.

## What a key governs

- **`applies_to`** narrows a key to a set of entity kinds. Empty means universal; a binding on any
  other kind is refused at write time.
- **`propagates`** says whether a bound value cascades. A propagating key (the default) resolves down
  the cascade. A non-propagating key is a flat per-entity set that resolves only from a binding on
  the entity itself.
- **`allowed_values`** constrains the key to an enum. Empty is free text, which autocompletes the
  distinct values already in use (`GET /tags/{name}:values`); a non-empty set is enforced on the
  binding write and refused with a 422 otherwise
  ([ADR-0024](/architecture/decisions/#adr-0024-a-tag-key-may-constrain-its-values-to-an-enum)).

## Values resolve union-on-key, shadow-on-value

An entity's effective tags resolve down the [cascade](/architecture/cascade/), whose chain and
precedence are stated once there. Tags differ only in the combinator: **keys union** (an entity
surfaces every key bound at or above it) and **values override** (for one key set at several
scopes, the most specific binding wins, and the shadowed candidates come back so the console can show
the override).

- `GET /components/{name}/effective-tags` returns the resolved set, winner plus shadowed.
- `GET /components/{name}:listTags` returns only the bindings set directly on the component.
- `:setTag` and `:removeTag` are the writes.
- A component in several systems resolves per system: `?system=` asks as one membership, otherwise
  the primary membership seeds the chain.
- A location resolves platform plus its own tree. A system resolves platform, its own tree, and the
  tree of the location it is placed at. An outpost resolves platform plus its own bindings
  ([ADR-0022](/architecture/decisions/#adr-0022-effective-tags-resolve-onto-systems-and-locations-a-placed-system-inherits-its-location)).
- The list routes carry an `effective_tags` map (key to winning value) per row, resolved for the
  whole page in one batched query.

**The cascade is authorized by the component it resolves for, not band by band**
([ADR-0093](/architecture/decisions/#adr-0093-the-tag-cascade-follows-the-component-it-resolves-for)).
A caller who can read the component sees every value that cascades onto it, including one owned by a
system or location they could not list directly, because a resolved value is part of that component's
configuration. `?system=` narrows the answer and never widens it.

:::design[Binding through groups and onto templates, tracked in #184]
A binding owned by a [group](/architecture/groups/) or a template, folded in by the shared cascade
resolver, is not built.
:::

:::design[Binding onto a file, tracked in #191]
A [file](/architecture/files/) is not on the structural arc and has no parent to cascade from, so it
needs the flat, non-propagating form of the same key model.
:::

:::caution[Open question]
Whether a key may carry a typed value (int, bool, date) and normalize values on input, so `Prod` and
`prod ` resolve to one value. The enum was the first slice; the rest is deferred.
:::
