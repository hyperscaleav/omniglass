Omniglass records what it knows about the fleet as **samples** in two lanes: a **metric** is a
quantity, a **property** is a value. This page is the value model: the lanes and their catalogs,
provenance, who may write a key, and how a value reads back. How samples arrive is
[collection](/architecture/collection/) and [messaging](/architecture/messaging/); the physical
tables are [storage](/architecture/storage/). To manage the catalogs, see
[metrics](/admin/metrics/) and [properties](/admin/properties/).

## Metric and property: quantity and value

The telemetry model is five lanes with no overlap: a **metric**, a **property**, an
[event](/architecture/events/), a [command](/architecture/commands/) and a
[log line](/architecture/events/). This page owns the two sample lanes:

- A **metric is a quantity**: a number of a registered `metric_type`, stored as a float. Quantities
  aggregate: an average volume, a p95 latency and a rate are all meaningful. It is the firehose, and
  every observation is kept.
- A **property is a value**: what something *is*, stored as jsonb and typed by a registered
  `property_type`. A value can be a number used as a name (input 3), which is meaningless to
  average. Values have **duration** instead ("how long was it on input 3?"), so the lane is written
  **transition-only**: one row per change.

A probe's state is a property (`icmp-reachable` is `up` or `down`, `tcp-open` is `open` or
`closed`), written once per flip, while its timing beside it (`icmp-rtt-avg`, `tcp-connect-time`)
is a metric
([ADR-1592](/architecture/decisions/#adr-1592-a-probes-state-is-a-transition-only-property-not-a-metric-row)).

A **sample** is one timestamped reading, `(owner, type, instance, ts, value, provenance, source,
lineage)`. A **series** is one stream of them, `(type, owner, instance, provenance)`. Which lane a
name belongs to is decided by catalog membership alone: `volume` is a metric because `metric_type`
holds it
([ADR-0079](/architecture/decisions/#adr-0079-five-telemetry-lanes-and-property-stops-being-the-genus)).

### Ownership: the exclusive-arc

A sample is owned by exactly one component, system, location or outpost
([the exclusive-arc](/architecture/core-entities/#ownership-the-exclusive-arc)). A system owns what
a push or a calc rule reports for it as a whole, and its health; an outpost owns its self-health; a
location owns only an operator's declared values and its calculated health, never an observed sample
([ADR-0422](/architecture/decisions/#adr-0422-a-system-owns-its-own-telemetry-and-a-location-owns-no-observed-sample)).

### The instance dimension: many values of one name on one owner

One owner can hold several values of one name (three fan speeds, per-port counters). The catalog
holds one row per measurement (`fan-speed`), and an `instance` text column, empty by default,
discriminates. Each provenance has exactly one stamper
([ADR-0456](/architecture/decisions/#adr-0456-an-instance-names-which-value-of-one-key-on-one-owner-a-row-is-and-an-owner-level-read-reduces-across-every-instance)):

- **observed**: the observer. An outpost-lane sample is stamped with the name of the endpoint whose
  task collected it, so two endpoints reporting one name stay two series. A push names an endpoint
  of its owner, or lands owner-level; naming anything else is a 422 that lists the owner's endpoints.
  A value a conduit fans out to another owner lands owner-level, its observer named in `source`
  ([ADR-1282](/architecture/decisions/#adr-1282-a-conduit-fans-each-identified-value-out-to-the-owner-its-binding-names-and-a-binding-costs-a-write-on-both-of-its-ends)).
- **declared**: owner-level, the empty instance, on every shipped route.
- **intended**: the command's instance, empty for an owner-level command.
- **calculated** and **health**: always the empty instance. An entity has one health.

A question about the owner reduces across every **live** instance of the key; a question naming an
instance reads that series alone. An instance is not live once its endpoint is deleted, or once its
driver's current spec no longer emits the key, so a frozen last reading never stands against the
owner forever. [Reconciliation](#reconciliation-want-told-is) reduces worst-case,
[command settlement](/architecture/commands/#settlement-the-settlement-is-computed-the-outcome-is-recorded)
reduces any-instance-agrees, and a current-value read shows the newest live value and says which
instance it came from, with `instance_count` and each instance's latest beside it.

:::design[A driver names its own instance, tracked in #1252]
A driver's extract spec names the instance with a `name[instance]` suffix
(`fan-speed[intake]=<oid>`): the parser strips the bracket so the catalog lookup matches the bare
name, and the instance rides into the column, one series per port.
:::

### The has-a-value-now razor (sample vs event)

A sample records a value; an event records an occurrence. "Input is 1" is a value, so a property.
"Call started" is an occurrence ("what is call-started now?" means nothing), so an
[event](/architecture/events/). An unnormalized raw line (a syslog line, a raw webhook frame) is
neither: it is a [log line](/architecture/events/), untyped and with no catalog gate.

## The two catalogs

Each typed lane has its catalog: `metric_type` and `property_type` for samples, `event_type` and
`command_type` beside them. The two sample catalogs split on what the value is:

- **`metric_type`**: `data_type` `int` or `float`, a `unit`, a display `precision`, an optional
  `retention_days`. Unit and precision live here and only here.
- **`property_type`**: `data_type` `string`, `bool` or `json`, an optional JSON Schema `validation`,
  an optional `retention_days`. No unit.

A name is **one kebab segment** (at most 100 characters, no dots) naming a **measurement, never its
owner**: `temperature`, not `room-temperature`; `fan-speed` with unit `rpm`, not `fan-rpm`. One
canonical name is one comparable signal across vendors. The shipped set seeds from
`internal/seed/metric_types.yaml` and `property_types.yaml`.

**One name space, two tiers.** The metric, property and event catalogs share one name space, so a
name resolves to one row across all three. Every row has a **namespace**: `og` for the platform's,
which only the boot seed writes, and `local` for an admin's
([ADR-0318](/architecture/decisions/#adr-0318-every-catalog-key-is-a-namespace-and-a-key)). A bare
name resolves along a **search path**, `local` first, then `og`, through one function,
`storage.ResolveNameLane`, which ingest, event rules, calc rules and driver emits all share. So when a
release ships a name an admin already coined, theirs **shadows** it and their series keep landing
where they did
([ADR-1307](/architecture/decisions/#adr-1307-an-operators-row-shadows-an-official-row-of-the-same-name-in-another-registry));
the server logs the shadow at catalog build and hourly. An admin's create never takes a name `og`
holds. A shipped rule or driver resolves its own names inside `og`.

**Checked on ingest.** A sample whose name does not resolve in its lane's catalog is refused
(reject-not-project), and a property value must parse as the type's `data_type` and satisfy its
`validation`. The ingest consumer keeps the catalogs between batches and rebuilds them when their
fingerprint moves, so a new type is honored within seconds
([ADR-1279](/architecture/decisions/#adr-1279-the-ingest-registry-is-kept-until-the-catalogs-fingerprint-moves)).

### Key scope: org and official

The `official` flag and the namespace together say whose a row is: a shipped, read-only `og` row, or
an admin's `local` one. Every sample is typed by a catalog row (the foreign key is non-null), and a
driver's emit names a catalog row, checked when the spec is written. A
[template](/architecture/templates/) is never a scope: it is cloned, never pointed at
([ADR-0827](/architecture/decisions/#adr-0827-the-template-layer-owns-the-clone-model-and-the-componenttemplate-authoring-model-is-superseded-by-the-driver-spec)).

:::design[Catalog content from outside the release, tracked in #318]
Beyond `og` and `local`, a catalog accepts content from outside the binary (a community or private
tier) and a `local` key merges into any key. Trust comes from distribution: a shipped name is in the
release and not spoofable; an imported one is the admin's to vet.
:::

## Units: one canonical unit per metric

Only a metric has a unit, and even a dimensionless one has one (`ratio`, `count`). **Storage is
canonical at rest**: each metric type declares one unit, every stored value is in it, and every
threshold and calc compares like with like. A driver normalizes at the edge (a Fahrenheit display's
driver emits Celsius), so the native unit is a collection fact, never a storage fact. A ratio is
stored `0..1` (`cpu-utilization` is `0.9`, shown as 90%). `precision` is a display default; storage
keeps full precision.

:::design[The unit catalog and conversion, tracked in #2613 and #2609]
A `unit` catalog groups units by family (temperature, data size, bitrate), one canonical unit per
family plus alternates, each with transforms to and from canonical
([#2613](https://github.com/hyperscaleav/omniglass/issues/2613)). A read converts out to a user's
display unit off the same rows, and `convert(value, "fahrenheit") > 100` authors a Fahrenheit
threshold over Celsius storage, same-family targets only
([#2609](https://github.com/hyperscaleav/omniglass/issues/2609)).
:::

## Provenance: how we know a value

Lane is a property of the **name**; provenance is a property of the **row**. The same name can be
observed, calculated, intended or declared, side by side in one table, each pointing at what produced
it (its **lineage**):

| Provenance | How we know it | Lineage |
|---|---|---|
| **observed** | reported by a component, an outpost or a push | `source_rule` and its version, where an edge parse produced it |
| **calculated** | derived by a [calc rule](/architecture/calculations/) | `source_rule`, its id and version |
| **intended** | the effect a [command](/architecture/commands/) we issued expects | `command_id` |
| **declared** | set by an operator | none |

The property lane admits all four; the metric lane admits the first three. A separate **`source`**
column records which sensor or path produced an observed value (`codec-cec` against `display-lan`),
so three sensors on one display's power are three observed rows differing only in source.

### observed: from a component, via an edge parse

The outpost parses the device's answer at the edge and publishes the sample onto the bus; it never
writes to Postgres. The raw payload is not kept. Two lanes feed one write path: the **outpost lane**,
where the server binds the owner from the task's endpoint, and the **push lane**
(`POST /telemetry:push`), where a scoped caller names the owner and the scope check is the fence.
Both land a batch in one transaction under its receipt, so a redelivered batch lands once
([ADR-0311](/architecture/decisions/#adr-0311-a-telemetry-batch-lands-once-in-one-transaction-under-its-receipt)).

### calculated: derived by a calc rule

A calc rule's tick reduces its inputs' current values and writes the result through the same write
path as a calculated row naming the rule, on a server tick rather than the stream
([ADR-0148](/architecture/decisions/#adr-0148-calc-rules-run-on-a-durable-pending-set-and-a-server-tick-not-a-jetstream-consumer)).
An unchanged result writes nothing. A calculated property resolves as the owner's value where nothing
is declared, after a declared value and before the contract default. How a rule runs is on
[calculations](/architecture/calculations/).

### intended: the declared effect of a command

Issuing a settleable command writes, in one transaction, the command row, a caused event and an
**intended** row in its target lane, whose lineage is the command itself. It is a bet, settled by the
observation that follows: intended against observed is the central razor, intent in progress against
measured reality. Only a command writes an intended row; an outside event implying a value ("meeting
started, so the room is occupied") is an observation.

### declared: an operator's assertion, as a series row

Anything an operator sets on an owner (an asset tag, a locked input) is a **declared row** in the
property series:

- **An edit appends**, so the edit history is the series.
- **Unset is a tombstone**: a declared row whose value is JSON null, read as absence.
- **An identical re-set writes nothing.**

The [effective read](/architecture/core-entities/#declared-properties-the-classifier-contracts-and-the-declared-rows)
coalesces the classifier's contract default in when the series says nothing.

## Who writes a key: the writer class

Provenance says how a row knows its value; the **writer class** says who may write the key at all
([ADR-0161](/architecture/decisions/#adr-0161-every-key-has-one-writer-class-held-at-the-storage-gateway)).
Every metric, property and event type has exactly one, resolved from its name and never stored, and
the [Storage Gateway](/architecture/storage/#every-key-has-one-writer) refuses any write the class
does not admit. Type reads carry it as `writer_class`:

<WriterClasses />

Three classes are reserved and internal: `outpost-probe` (an outpost's own account of an endpoint),
`platform` (what only Omniglass writes: the health rollup, and each outpost's and the server's
account of itself, listed on
[collection](/architecture/self-monitoring/#self-monitoring-every-outposts-account-of-itself)) and
`command-lifecycle` (the events a command's issue and terminal status write). Their names are closed
to an admin's catalog row and to every contract. A **writer** is the entry point a write comes
through, and it fixes the provenance: the outpost and push lanes write observed, a calc rule
calculated, a command intended, an operator declared.

- **An outpost-probe key reads only as the outpost's observation.** The one declared row the family
  admits is a key pin (an ssh host key, a tls certificate), set only through an endpoint's audited
  `:retry`.
- **A calc rule owns its output.** Once a rule outputs a key, a push, outpost lane or driver spec
  writing it is refused.
- **Fusion is within a class**: the perspectives of a `collected` key, told apart by `source`.

## Current value is the latest series sample

"What is this now?" is answered by reading the series: the latest row per
`(type, owner, instance, provenance)`. No current-value cache is kept beside it
([ADR-0079](/architecture/decisions/#adr-0079-five-telemetry-lanes-and-property-stops-being-the-genus)).

- **A declared or intended series orders by insertion.** Neither carries a caller's timestamp, so
  the row id is the sequence, and a database clock stepping backwards cannot make the earlier write
  win.
- **An observed or calculated series orders by `ts`, then id.** The lane accepts a caller's
  timestamp (an outpost backfilling), and a late-arriving older sample must not become current by
  being written last.

The property lane is sparse, so the read is an index probe. A metric is stored narrow,
`(id, series_id, ts, value)`, beside a `metric_series` row naming what it is a sample of
([ADR-1275](/architecture/decisions/#adr-1275-the-metric-lane-is-narrow-rows-on-a-series-dimension-partitioned-by-month)),
partitioned by month, with intended rows in their own table no retention pass touches.

Retention prunes metric samples past `retention.metric_days` (14 by default) and property
transitions past `retention.property_days` (90), or a type's own `retention_days` (`:setRetention`).
A prune never deletes a declared or intended row, and on the property lane never deletes the latest
row of a series, since a steady value may hold one row for months.

## A series chart is truthful at every zoom (#1269)

The samples routes (`GET /{components,systems}/{name}/metrics/{metric}/samples` and
`.../properties/{property}/samples`) answer a different question when given a **`resolution`** in
seconds: every regular bucket of the window, oldest first.

- **The grid is epoch-aligned and complete.** Thirty days at one hour is exactly 720 buckets, and an
  empty bucket is still there with `count: 0`: a gap is told, not skipped. More than 5,000 buckets is
  a 422.
- **A metric bucket keeps what an average loses**: `min`, `max`, `avg`, `count` and `last`, so a
  one-sample spike survives any zoom as the band under the line.
- **A property bucket is `count`, `last` and `held`**, the value in force across it, drawn as steps,
  with `carried_in` the value in force when the window opened.
- **A bucket is one series of measured rows**: a declared or intended row never moves it, and several
  instances with readings make the read a 422 that lists them, so a caller picks one rather than
  charting a blend.
- **Nothing is read past what is kept**: `covered_from` says where retention ends.
- **A wide metric read is whole hours.** Past 48 hours, the resolution rises to whole hours and
  closed hours come from the series' hourly trend, so a month reads 720 rows rather than 86,400
  samples
  ([ADR-1566](/architecture/decisions/#adr-1566-a-wide-bucketed-read-is-whole-hours-and-takes-closed-hours-from-the-trends)).

## Reconciliation: want, told, is

An owner's **properties read** (`GET /{components,systems,locations}/{name}/properties`) carries the
reconciliation on each row
([ADR-1297](/architecture/decisions/#adr-1297-the-properties-read-carries-reconciliation-and-the-reconciliation-route-retires)):

- **want**: the current declared value, else the contract default; null when nothing declares one.
- **told**: the newest intended value on any instance a command named.
- **is**: the observed value, worst-case over the live instances (one that disagrees with want, if
  any does), named by `is_instance`.
- **drift**: true when an observed instance disagrees with want, false when nothing is declared.
  Computed on read, so it cannot go stale.

An observed value is stored as its text form, so every comparison first reads it typed by the
property's `data_type`: `3` and `3.0`, or an object's key order, compare equal
([ADR-1202](/architecture/decisions/#adr-1202-an-observed-property-value-is-read-typed-where-it-is-compared)).
A reserved key (a probe key, `health`) is not a row here; a probe key reads on the reachability
read. The [command](/architecture/commands/) adds the windowed form: settlement is told against is,
gated on the settle window.

## The DAG invariant

The pipeline stays acyclic:

> A rule may **read** observed and calculated values as truth. It may **compare** an intended or
> declared value against observed. It may **not** treat an intended value as truth to infer a new
> fact.

The one forward edge, a command to its intended row, is terminal, so rules reading only observed and
calculated values keep the graph acyclic with no runtime guard.

:::design[disagree and divergence, tracked in #2609]

## disagree and divergence

Drift becomes an operator, **`disagree(A, B)`**, usable in event rule criteria over two provenances
or two sources of one key: `disagree(intended, observed)` (a command did not land),
`disagree(declared, observed)` (the world drifted from a declared value), and
`disagree(observed, observed)` across `source` (sensors conflict). Any two provenances of one name
that disagree are one anomaly, with one detector.
:::

:::design[Fusion, tracked in #2614]

## Fusion

Several sources reporting one key land as **perspectives**, source-tagged observed rows, all kept. A
reduce-on-read policy produces the effective value: priority, weighted, majority, worst, average or
latest, with a tie-break and per-source weights, defaulting from the type's `fusion_policy` (stored
today, read by nothing) and left open for read time where no default is right. Event rules judge the
fused value; the perspectives stay queryable. Fusion across different names (`room-in-use` from
display power, call state and occupancy) is a [calc rule](/architecture/calculations/), never fusion.
:::
