## Metric and property: quantity and value

The telemetry model is **five lanes** with five names and no overlap: a **metric**, a **property**, an [**event**](/architecture/events/), a [**command**](/architecture/commands/), and a [**log line**](/architecture/events/). This page owns the two **sample** lanes:

- A **metric is a quantity**: a numeric reading of a registered `metric_type`, a float8 row in `metric`. Quantities **aggregate**: `AVG(volume)`, a p95 latency, a rate over time are all meaningful. The firehose.
- A **property is a value**: what something *is* right now, a jsonb row in `property` typed by a registered `property_type`. A value can be a **number used as a name** (input 3, zone 4): averaging inputs is meaningless. Values do not aggregate, they **have duration**: "how long was the input 3?" is the question the lane answers, so it is written transition-only and the series is its own edge history.

A **sample** is one timestamped reading in either lane, `(owner, type, instance, ts, value, provenance, source, lineage)`. A **series** is one stream of them, `(type, owner, instance, provenance)`. The **current value** is the latest row of a series, derived by reading it, never stored beside it ([below](#current-value-is-the-latest-series-row)).

The two lanes are one shape in code and two tables in storage, split because they answer different questions and retain differently, not because they differ conceptually. The lane a name belongs to is decided by **catalog membership**: `volume` is a metric because `metric_type` holds it. There is no per-key `kind` column; the split catalog made it redundant ([ADR-0079](/architecture/decisions/#adr-0079-five-telemetry-lanes-and-property-stops-being-the-genus)).

A log line is **not** a third sample lane: it is untyped raw arrival on its own lane (`log_line` for a component's lines, `node_log` for a node's self-logs), no registered name, no catalog gate, where a sample is a *value of a named type at a time* ([ADR-0066](/architecture/decisions/#adr-0066-logs-are-a-raw-ingest-lane-not-events)). A driver collects one as it collects a sample, by an emit that declares a log line instead of a key ([an emit lands on any lane](/architecture/collection/#an-emit-lands-on-any-lane), [ADR-1145](/architecture/decisions/#adr-1145-a-driver-emit-lands-on-any-of-the-four-lanes-and-a-log-lines-severity-is-rfc-5424s)). An **event** is not a sample either: *our semantic assertion that something happened*, not an observed value ([the razor](#the-has-a-value-now-razor-sample-vs-event), [events](/architecture/events/)).

### Ownership: the exclusive-arc

The owner is the **exclusive-arc**: an `owner_kind` enum (`component` / `system` / `location` / `node`) plus the matching typed FK, a CHECK enforcing exactly one set. No platform or fleet-root arm (a fleet-wide series is a design question). The same arc owns `event` and `command` rows and is the design for `alarm` (component-local today). System- and node-level samples are first-class, fixing Zabbix's inability to put a verdict on a group of hosts: a system owns its [health](/architecture/health/), what a [calc rule](/architecture/calculations/) derives from its members, and what a push reports for it as a whole (a cloud service's account of the room it serves; `owner.kind: system`, read back on the system's own metrics, properties, events and a property's change history), and a node owns its self-health. A **location owns no observed sample**: nothing collects or pushes telemetry for a place, so its arm of the arc holds only an operator's declared properties and its calculated health ([ADR-0422](/architecture/decisions/#adr-0422-a-system-owns-its-own-telemetry-and-a-location-owns-no-observed-sample)). See Ownership on the spine and the storage DDL.

### The instance dimension: many values of one name on one owner

One owner can hold several values of the *same* name (three fan speeds, per-port counters). The catalog holds **one** row per measurement (`fan-speed`, not `fan-speed-intake`); the discriminator is an `instance text NOT NULL DEFAULT ''` column on both sample tables. Series identity is **`(owner, type, instance, provenance)`**: each instance its own series, the singleton (`instance = ''`) the default; aggregation groups by name and ignores `instance`, so per-instance trends stay distinct.

**An instance names which one of several values of one key on one owner a row is**, and each provenance has exactly one stamper ([ADR-0456](/architecture/decisions/#adr-0456-an-instance-names-which-value-of-one-key-on-one-owner-a-row-is-and-an-owner-level-read-reduces-across-every-instance)):

- **observed**: the observer. The ingest stamps a node-lane sample with the **name of the endpoint whose task collected it** where the sample names none, so two endpoints reporting one name stay distinct series (a driver naming its own instance, one series per port, is the authored form below, still design); a webhook's samples carry the endpoint the post arrived at; a value a conduit [fans out](/architecture/collection/#shared-api-collection-one-component-many-owners) to another owner lands at the **empty instance**, its observer named in `source` as `<conduit>/<endpoint>`, since the conduit's endpoint is no endpoint of that owner (a system has none) and would read as a retired observer ([ADR-1282](/architecture/decisions/#adr-1282-a-conduit-fans-each-identified-value-out-to-the-owner-its-binding-names-and-a-binding-costs-a-write-on-both-of-its-ends)); two conduits reporting one key on one owner stay told apart by `source`, and their values form one owner-level series; a push names an endpoint of its owner as its instance (an endpoint's name is its transport), else it lands on the owner-level series. A push naming an instance that is no endpoint on its owner is refused whole with a 422 that names the instance and lists the owner's endpoint names (at most ten, then a count), so a series no observer stands behind is never written.
- **declared**: the operator. Every shipped route declares owner-level (the empty instance), and a per-instance declaration waits for a surface that addresses instances; an endpoint's key pin is the one declared row written under an endpoint.
- **intended**: the command's instance, empty for an owner-level intent.
- **calculated**: the empty instance. A calc rule reads every instance of an input key and writes its output aggregate ([calculations](/architecture/calculations/#how-a-calc-rule-runs)); per-instance outputs are a separate capability, not a silent gap.
- **health**: the empty instance, always and on purpose: an entity has exactly one [health](/architecture/health/).

**How a read resolves an instance.** A question about the owner (the empty instance) over an instanced key reduces across every live instance of the key on that owner; a question that names an instance reads exactly that series and never reduces. A **retired observer** is not live: an instance naming a transport the owner has no endpoint of names an endpoint since deleted (an endpoint's name is its transport), and its frozen last reading is left out of the reduction rather than held against the owner forever, while an instance naming no transport (a series a push wrote before the push lane required an endpoint) stays live, since nothing extends it. One residual is open: an endpoint that still exists but no longer emits the key keeps its last reading live (#1217). [Reconciliation](#reconciliation-want-told-is) reduces worst-case, [command settlement](/architecture/commands/#settlement-the-verdict-is-computed-the-outcome-is-recorded) reduces any-instance-agrees, and a current-value display shows the newest value across the live instances and says which one it is: the owner's metrics read names the instance its value came from (`instance`), counts the live instances holding a sample (`instance_count`), and lists each one's latest when there is more than one (`instances`), applying the same liveness test reconciliation does, so a deleted endpoint's frozen reading is neither shown nor counted (#1020). A component's **Vitals** row renders it as "latest of 2 endpoints (tcp)" and opens to each endpoint's value; a key one instance holds, and every system's metric (a system has no endpoints), reads as a single value.

:::design[The authored instance form, tracked in #1252]
The instance rides the pipeline as a reserved **`instance` label**, authored in the extract spec as a
`name[instance]` suffix (`fan-speed[intake]=<oid>`); the parser strips the bracket into the label so
the catalog lookup matches the bare name, and the derive step reads it into the column.
:::

### The has-a-value-now razor (sample vs event)

A sample records a value; an event records an occurrence.

- `"input is 1"` is a value, so it is a **sample** (a property).
- `"call started"` is an occurrence, "what is call-started now?" is meaningless, so it is an **event** ([events](/architecture/events/)).

An unnormalized raw occurrence (a syslog line, a raw webhook frame) is neither: it lands on `log_line`; a derivation rule may later promote it to an `event`, though most lines never become one.

## The two catalogs

Each lane that carries typed data has its own registry: `metric_type` and `property_type` for the sample lanes, [`event_type`](/architecture/events/) for occurrences, [`command_type`](/architecture/commands/) for invocations. The two sample catalogs split on **`data_type`, the lane key**: the lane *is* the value type, so no discriminator column exists and none is needed.

- **`metric_type`** describes every numeric name: `(name, data_type: int | float, unit, precision, fusion_policy, official)`. The numeric facts, **unit** and display **precision**, live here and only here.
- **`property_type`** describes every value name: `(name, data_type: string | bool | json, validation, fusion_policy, official)`. The value domain (a JSON Schema in `validation`) lives here; no unit, no precision.

The three ingest registries (`metric_type`, `property_type`, `event_type`) share one name space: a name resolves to one row across all three, so an operator's create is refused when the name exists in a sibling catalog. Every catalog row also has a **namespace** ([ADR-0318](/architecture/decisions/#adr-0318-every-catalog-key-is-a-namespace-and-a-key)): `og` for the platform's, which only the boot seed writes, and `local` for the operator's. A bare name resolves along the **search path** (#1432): the operator's `local` row first, in whichever of the three catalogs, then the `og` row. So when a release ships a name an operator already coined, the shipped row lands beside theirs and theirs **shadows** it at ingest and in every reader, and their series keep landing where they did ([ADR-1307](/architecture/decisions/#adr-1307-an-operators-row-shadows-an-official-row-of-the-same-name-in-another-registry), the cross-catalog case). The registry reports the shadowed name on a rebuild and hourly, and the shipped one answers once the operator deletes theirs (`DELETE /metric-types/{name}` or its sibling on the registry it lives in). An operator's own create never takes a name `og` holds: a shadow arises only from a release. Two `local` rows of one name across the catalogs, or two `og` ones, still resolve to nothing.

**Naming is owner-agnostic and single-token**: a name is one kebab segment (at most 100 characters, no dots: `icmp-rtt-avg`, `power-state`, `video-input`), naming a **measurement, never its owner** (`temperature`, not `room-temperature`), with the canonical unit in `metric_type.unit` (`fan-speed` + `unit: rpm`, not `fan-rpm`). One canonical name is one comparable signal across vendors, the normalization cross-fleet dashboards and AI hinge on. The official set seeds from `internal/seed/metric_types.yaml` and `internal/seed/property_types.yaml` (the probe and ladder metrics, the endpoint verdicts and `session-state`, `health`, and a handful of device facts; the [metrics](/guides/admin/metrics/) and [properties](/guides/admin/properties/) guides render each set from the seed); the OpenTelemetry-semconv-aligned IT leaves and the [OpenAV minimum-device-functionality guidelines](https://github.com/OpenAVCloud/specifications/blob/main/min-device-functionality/OAVC-AV-Device-Minimum-Functionality-Guidelines.md) set are still to come.

**Validation on insert.** Ingest checks per lane: **(1)** the name resolves in the lane's own catalog; an unresolved name is **reject-not-project**, kept out of the typed series. The ingest consumer holds the three catalogs as one registry between batches and rebuilds it when their fingerprint moves, so a type created, renamed or retired is honored by the next batch ([ADR-1279](/architecture/decisions/#adr-1279-the-ingest-registry-is-kept-until-the-catalogs-fingerprint-moves)). Beside it the consumer keeps the property types some command type targets, the observations settlement watches, and hands them to each batch, so a new command type is honored by the next batch too ([ADR-1299](/architecture/decisions/#adr-1299-the-command-targeted-property-names-ride-the-kept-registry)). A name more than one row holds resolves by one rule, `storage.ResolveNameLane` (the search path), which the registry, an event rule's sample key, a calc rule's key and a driver's emit all share (#1307, #1432): the operator's `local` row shadows an `og` row of the same name, and any other name two rows hold in the answering tier (a collision: two `local` rows, two `og` ones, or a reserved key held in both tiers) resolves on no lane, so every sample carrying it is refused. A shipped rule or driver resolves its own names inside `og`, the catalog it shipped against. The server logs a collision, and separately a shadowed name, when it builds the registry and once an hour while it persists, rather than on every batch (#1298). A push of the official row of a shadowed name is refused with a reason that says so. **(2)** The value conforms: a metric is numeric by wire shape; a property's value must parse as the type's `data_type` and satisfy its `validation` schema when one is declared, and a violating push is refused before anything publishes. The cascade-resolved `validation_policy` modes (bypass / audit / enforce) and the `collection.failed` raw carry are design, tracked in #430.

## Units: one canonical unit per metric

Only a **metric** carries a unit (and the display `precision`); even a dimensionless metric has one (`ratio` or `count`); a property has neither. **Storage is canonical-at-rest**: every `metric_type` declares **one canonical unit**, stored values are always in it, and every threshold, calc, and fusion compares like with like. Mixed units are never stored, the unit never rides the `instance` dimension, and a genuinely different measurement is a different `metric_type`: units convert only **within one family**.

**Dimensionless is still a unit.** The `ratio` family is canonical `ratio` (`0..1`) with `percent` an alternate (`ratio * 100`): `cpu-utilization` is stored as `0.9`, shown as `90%`. A bare **count** is a cardinal `count`, distinct from a ratio.

Conversion happens only at the edges and in expressions:

- **Normalize-in at the edge.** The edge parse converts native to canonical before the sample is emitted: a Fahrenheit display's driver emits `celsius`. The native unit is a [collection](/architecture/collection/)-time fact, never a storage fact.
- **Convert-out on read.** The [UI](/architecture/ui/) and [views](/architecture/views/) convert to the operator's per-user / per-locale display unit via the `unit` registry, off the same rows.
- **Expressions: `convert(value, "<unit>")`.** A stdlib function in [expressions](/architecture/expressions/): the source unit is inferred from the bound sample; the target must be a registered unit in the **same family** (a compile error otherwise). `convert(value, "fahrenheit") > 100` authors a Fahrenheit threshold over Celsius storage. Available wherever expressions run: event rule and alarm criteria, calc leaves, list filters.

**Display precision is part of the type.** The optional **`precision`** (significant digits to render) is a presentation default: the stored `data_type` keeps full precision, the [UI](/architecture/ui/) or a locale can override, and dropping noise at *ingest* is a separate collection-time rounding.

:::design[The `unit` registry, tracked in #430]
The **`unit` registry** groups units by **family** (temperature, data-size, bitrate, ...): one
canonical unit per family plus alternates, each carrying **`to_canonical`** / **`from_canonical`**
transforms, **affine** or (dB) an **Expr**; official / org scoped like the other registries.
Temperature is canonical `celsius`; `fahrenheit` carries `to_canonical: (v - 32) * 5/9` and
`from_canonical: v * 9/5 + 32`. `metric_type.unit` would reference a canonical row and
`convert(value, "<unit>")` resolves same-family targets through it. No table exists today.
:::

## Key scope: org and official

Built: the **`official`** boolean on both catalogs (names unique per catalog, `official: true` the
seeded canonical set, `official: false` operator-authored).

:::design[The registry scope ladder, tracked in #318]
The target is a **`scope`** on the catalogs (the built boolean folding into the enum's top value),
deciding where a name is unique and where its trust comes from:

| scope | identity (uniqueness) | trust | who defines it |
|---|---|---|---|
| **org** | `name`, unique within the deployment | local custom canonical | the org / operator |
| **official** | `name`, globally | shipped with the distro | the distro |

Trust comes from **distribution**, not a label: an official name is **in the release**, not
spoofable; an org name is authoritative within its one database (one database is one tenant). The
community and private tiers of a catalog that accepts content from outside the binary are the rest of
[#318](https://github.com/hyperscaleav/omniglass/issues/318).

**The promotion ladder is org -> official**, a cheap re-scope, not a migration: official is earned by
shipping in the distribution, and collected samples keep resolving. Normalization is optional but
encouraged: aligning buys cross-fleet comparability, and most drivers just **reference** a shipped
official name.

**Governance is curation, not runtime enforcement**: Omniglass is a Postgres database an operator
runs; we vouch for what we **ship**, you vet what you import.
:::

There is no **template** rung. An earlier design scoped a name to the template that declared it,
`(template_id, name)`; a [template](/architecture/templates/) is a clonable example that is never a
row, so nothing can be scoped to one, and that rung retired
([ADR-0827](/architecture/decisions/#adr-0827-the-template-layer-owns-the-clone-model-and-the-componenttemplate-authoring-model-is-superseded-by-the-driver-spec)).
**Every sample is typed by a catalog row**: the sample-to-catalog FK is **non-null** in both lanes,
and a driver's emit names a catalog row, checked when the spec is written.

## Provenance: how we know a value

Lane is a property of the **name**, fixed by catalog membership (`power-state` is always a property); provenance is a property of the **row**: the same name can be observed, calculated, intended, or declared at different moments. Each provenance points at the immutable record that produced it (its **lineage**), the populated lineage column mutually exclusive per provenance, CHECK-enforced.

| Provenance | How we know it | Lineage points at |
|---|---|---|
| **observed** | measured from a component | on-row: `source_rule` (+ version), the edge function that parsed it |
| **calculated** | derived from other samples | on-row: `source_rule` (+ version), the calc_rule |
| **intended** | the declared effect of a command we issued, pending reconciliation | `command_id`, the [command](/architecture/commands/) that opened it |
| **declared** | asserted by an operator | none: no rule, no event, no command |

All four land in the same series tables, side by side for the same name, making divergence detection free. The property lane admits all four; the metric lane admits the first three today (there is no declared-metric writer yet, and its schema refuses the row until one exists).

A separate **`source`** column records *which sensor or path* produced an observed value (`codec-cec` vs `display-lan` vs `control-system`): three sensors on one display's power are three observed rows differing only in source, the basis of [fusion](#fusion).

**Trace columns, orthogonal to lineage.** `correlation_id` and `source_event_id` (the causation parent) live on `event`, `correlation_id` on `log_line` and `node_log`; the sample tables carry none today. The design adds them to samples, nullable and outside the lineage CHECK, so an action's command can propagate its `correlation_id` onto the adaptive-poll's observed sample, feeding [the DAG invariant](#the-dag-invariant)'s cycle guard ([alarms and actions](/architecture/alarms-actions/)).

### observed: from a component, via an edge parse

"Measured from a component," not "from a device": every device is a component, not the reverse. The node parses the payload at the edge and **publishes the observed sample to the JetStream raw ingress subject** (admission confines its owner before the trusted stream); it never writes to Postgres. Lineage rides the row: `source_rule` + `source_rule_version` (the backtest hinge). The verbatim payload is **not** kept (no telemetry table): raw surfaces only on a `collection.failed` event, a dev raw-mode tap, or the bounded opt-in `raw_sample` policy ([collection](/architecture/collection/)). No separate execution table: a derived sample is itself the evidence of its function's run.

### calculated: derived by a calc rule

Built for component and system owners (#996, #997; event rules judge component outputs only, #1002): a calc rule's tick reduces the inputs' current values and writes
the result through the sample-write path as a calculated row naming the rule and its version, where
event rules judge it and downstream calc rules are marked; an unchanged result writes nothing. A
property a calc rule writes resolves as the owner's value where nothing declares one, after a declared
value and before the contract default, naming the rule (`source_rule`, `source_rule_id`) as an
effective metric does (#999, #1018); reconciliation's want stays the declared value alone. How it runs
is on [calculations](/architecture/calculations/#how-a-calc-rule-runs).

:::design[The calculated producer on the stream, tracked in #430]

Parallel to observed, but the input is **other samples**, not a device payload. A calc consumer reads the trusted JetStream `samples` stream and **publishes its derived sample back onto it** (a trusted server producer, no admission pass), so calculated values re-enter the data lane and feed downstream calc and the rule engine. Both producers carry `source_rule` + `source_rule_version`; the **`provenance` column** distinguishes them. Inputs are reconstructable from the rule version (backtest); an immutable snapshot, if ever needed, is a nullable `inputs jsonb` column. The rule lives on [calculations](/architecture/calculations/).
:::

### intended: the declared effect of a command

Issuing a command records the invocation, a caused **event**, and the **intended** value it expects, in one transaction. The intended row's lineage is **the command itself** (`command_id`): the value points at what caused it, not at the event derived from the cause. It reconciles against the observed value the device round trip produces, and the command's **recorded status** carries the outcome ([commands](/architecture/commands/)). **Intended vs observed** is the central razor: intent in progress versus measured reality.

```text
1. command issued:  "power on display-5"  -> the command row + a caused event
2. intended write:  display-5 power = on, provenance=intended, command_id=<the command>
                    a bet: intended, not measured
3. the evidence:    the device's reply when its binding settles from the response,
                    else the next poll (adaptive: sooner than the normal interval)
4. observed arrives:
     observed = on  -> settled (the bet paid off; the command records it)
     observed = off -> failed (the command did not land)
```

No separate "mapping" primitive exists: which value a command intends lives on the command definition, and a command may target either lane (set an input is a property, set a volume is a metric). **Only commands set intended values**; an external event implying a value ("meeting started, so the room is occupied") is observed reality, landing as **observed** through the edge parse.

| The source says | Means | Path |
|---|---|---|
| "eth0 **is** down" | a component reporting measured reality | edge parse, then an **observed** row, directly |
| we sent "**power on**" | intent in progress, not yet confirmed | command, then an **intended** row naming it |

### declared: an operator's assertion, as a series row

mac, ip, serial, locked-input: anything an operator *sets* on an owner is a **declared series row**, `provenance='declared'`, in the same `property` table as every other row ([ADR-0079](/architecture/decisions/#adr-0079-five-telemetry-lanes-and-property-stops-being-the-genus)). Three consequences fall out of rows-not-store:

- **An edit appends.** Changing a declared value writes a new row; the old one stays. The edit history is the series, for free, with no shadow audit table.
- **Unset is a tombstone.** Clearing a declared value appends a declared row whose value is JSON null; every reader resolves that latest row as absence. The unset is itself part of the history, and an unset-of-unset is an explicit miss, not a growing pile of tombstones.
- **The current declared value is the latest row**, like every other provenance; the **effective** read (`EffectiveProperties`) coalesces the owner's classifier-contract default in when the series says nothing ([core entities](/architecture/core-entities/#declared-properties-the-classifier-contracts-and-the-declared-rows)).

An identical re-set appends nothing: a same-value save is a no-op, which the PUT route's idempotency and the dev seed's second-run-adds-nothing invariant both require.

The cascade-resolved **config** items, **variables**, and **secrets** remain their own primitive ([config, secrets, and variables](/architecture/variables/)): a declared property is a fact about one owner; a config binding is a policy resolved down a tree.

### Precedence: spec versus status

Which side wins is a per-item `reconcile` policy ([config](/architecture/variables/#drift-and-reconcile)):

- **observed wins** (`reconcile: observe` or `warn`): the declaration was a hint, reality is truth; a differing observed MAC surfaces as divergence (silent, or an alarm under `warn`); adopting it as declared is a separate one-shot import.
- **declared wins** (`reconcile: enforce`): the declaration is the spec; converge via the set command (the Kubernetes spec-and-status pattern), alarm if the set fails.

Sample provenances never contest: intended is a pending bet that observed confirms or refutes ([intended](#intended-the-declared-effect-of-a-command)), superseded on arrival. Device-swap is handled by [maintenance mode](/architecture/core-entities/#operational-mode-active-maintenance-disabled), which suppresses drift.

## Who writes a key: the writer class

Provenance says how a row knows its value; the **writer class** says who may write the key at all
([ADR-0161](/architecture/decisions/#adr-0161-every-key-has-one-writer-class-held-at-the-storage-gateway)).
Every metric, property and event type has exactly one, resolved from its name and the catalogs, never
stored, and the [Storage Gateway](/architecture/storage/#every-key-has-one-writer) refuses any sample
or event write whose writer the class does not admit, the way it injects scope on every query. The type
reads carry it as `writer_class`. The ruling, rendered from the code the gateway enforces:

<WriterClasses />

Three classes form the **reserved system family**, fixed and internal: `node-probe` (the node's own
account of an endpoint, declared in `internal/collection/probekeys`), `platform` (what only the
Omniglass process writes: the health rollup's `health`, and the webhook receiver's counts of the posts
it accepted and refused, #1369; the self-monitoring follow-on, #1094, is its planned consumer) and
`command-lifecycle` (`command-issued`, the event a command's issue puts on its owner's timeline, and
`command-settled`, `command-failed` and `command-timed-out`, the one its terminal status puts there). Their
names are declared in code and closed to an operator-created type on every lane, and no product,
standard or location-type contract declares one or gives it a default. A **writer** is the entry
point a write comes through, and it fixes the provenance: the node lane and the push lane write
`observed`, a calc rule `calculated`, a command `intended`, an operator `declared`. So operator and
command are writers, not classes: a declared or intended row is never an observation and contests no
observer, which is why a collected key keeps all four provenances side by side.

- **A node-probe key reads only as the node's observation.** The reachability panel, the session pill
  and the ingest's transition guard read the observed series alone, so no other provenance stands in
  for the node's; the one declared row the family admits, a key pin (the ssh host key, the tls
  certificate), is set only through an endpoint's audited `:retry` (its row's `source` is `key-pin`,
  the one mark a read trusts it by) and read only as the pin. A node-probe sample dated more than five
  minutes past the database's clock is stored at the database's now, so the node's account cannot
  outlive its tenure. Likewise the health reads serve the rollup's calculated rows alone. Rows written
  before the ruling that it refuses were retired into `retired_sample`
  ([ADR-1100](/architecture/decisions/#adr-1100-legacy-rows-and-stored-declarations-honor-the-one-writer-ruling)).
- **Fusion is within a class.** The same-key, multi-source reconcile [below](#fusion) is between the
  perspectives of a `collected` key (a driver's emits on the node lane, a push), told apart by
  `source`: the class is the trust boundary, the source the sensor path within it. A reserved key has
  one observer and never fuses.
- **A calc rule owns its output.** A calc output is never a reserved key nor a key a stored driver
  emits ([calculations](/architecture/calculations/)), and once a rule outputs a key, a push, a node
  lane or a driver spec writing it is refused; an operator's declared value still resolves ahead of
  the calculated one.

## Current value is the latest series row

"What is this property now?" is answered by **reading the series**: the latest row per `(type, owner, instance, provenance)`, ordered by `ts` (id breaks same-instant ties). That tiebreak is **insertion order**, not an arbitrary identifier: the row id is a bigint identity column, so two values written in the same tick resolve to the one written second, every time. `ts` leads rather than the id because the observed lane accepts a caller-supplied timestamp (a node backfilling, a device reporting a reading it took a minute ago), and a late-arriving older sample must not become current merely by being written last; the price of that, stated so it is not rediscovered, is that a database clock stepping backwards between two writes to one series resolves to the earlier-written row. There is no maintained latest-value store: the one-catalog design kept one (a `property` cache upserted from the sink) and it retired with the fold ([ADR-0079](/architecture/decisions/#adr-0079-five-telemetry-lanes-and-property-stops-being-the-genus)), because a derived copy of a fact the series already holds is a second thing to keep honest. The property lane is transition-only and sparse, so the read is an index probe, not a firehose scan; the metric lane's current-value read rides the same shape.

Two rules keep the read honest under [retention](/architecture/storage/#retention-what-is-kept-and-for-how-long), which prunes metric samples past 14 days and property transitions past 90 by default through the **`PruneSamples`** primitive (#417): a prune **never deletes a declared or intended row** (an operator's assertion is the whole truth however old, not a sample), and on the property lane **never deletes the latest row of any series** (a transition-only series still measured may hold one row for months). On the metric lane the floor is the latest row **within retention** ([ADR-1275](/architecture/decisions/#adr-1275-the-metric-lane-is-narrow-rows-on-a-series-dimension-partitioned-by-month)): a quantity stores every observation, so a series still measured always has a recent row, and one with none inside its window reads as no reading within retention. A metric sample is stored narrow, `(id, series_id, ts, value)`, beside a `metric_series` row naming what it is a sample of ([storage](/architecture/storage/#the-narrow-metric-lane)); every read joins the two, merging the series of one key, owner and instance that a change of collecting node or source started.

## Reconciliation: want, told, is

The read side pivots three values per property of an owner, and carries them on the owner's **properties read** itself (`GET /{components,systems,locations}/{name}/properties`), not a route of its own ([ADR-1297](/architecture/decisions/#adr-1297-the-properties-read-carries-reconciliation-and-the-reconciliation-route-retires)): one row per property the owner has, declared, calculated, observed or told, so a key the owner only observes is listed too. The pivot is **want** (the current declared value, with the contract default coalesced in; null when nothing declares the key), **told** (intended, nil until a command opens one), **is** (observed). A calculated row carries none: a calc rule's output is not what anyone asked for. The reserved keys (a native probe key, `health`) are not rows: a probe key reads on the [reachability read](/architecture/api/), which withholds a gated rung's frozen fact. All three are series reads, and the question is the owner's, so told and is [resolve across every instance](#the-instance-dimension-many-values-of-one-name-on-one-owner) of the key: told is the newest intended value on any instance a command named, and is is worst-case over the live instances, an instance that disagrees with want when any does (the newest such), else the newest agreeing one, named by the instance it came from (`is_instance`). **Drift** is any observed instance disagreeing with `want`, false when nothing is declared (there is nothing to drift from), computed on read so it cannot go stale ([`disagree`](#disagree-and-divergence)). The [command pillar](/architecture/commands/) adds the **windowed** form: settlement is `told` vs `is` gated on the command's settle window, and the command records the outcome as its status.

## Ground truth versus derived

- **Raw payload: not stored.** The sample is authoritative; see [observed](#observed-from-a-component-via-an-edge-parse).
- **Live on NATS, durable in PG.** The live sample is the message on the JetStream `samples` stream; the durable copy in `metric` / `property` is the persistence write, and samples **do not go through CDC** ([messaging](/architecture/messaging/#two-lanes-one-bus)).
- **Ground truth, logs** (immutable, append-only, the actor's own record): **`log_line`** (a component's words), **`node_log`** (a node's self-narration), **`audit_log`**, and the design-stage **`session_log`**, **`internal_log`**, and **`collection_log`**. No rule-execution table: a derived row *is* the evidence of its rule's run, carrying `source_rule` + `source_rule_version` itself.
- **Derived** (produced by rules, reconstructable in principle): **`metric`**, **`property`**, **event**, **alarm**, **action**.

## The DAG invariant

The pipeline must stay acyclic.

> A rule may **read** observed and calculated values as truth. It may **compare** an intended or declared value against observed (drift). It may **not** treat an intended value *as truth* to infer a new fact.

A drift rule reads the *pair* (intended, observed): the intended value is tested, not trusted. The one forward edge, command-to-intended-value, is terminal, so event rules reading only observed/calculated keep the graph acyclic with no runtime guard, except the command -> device -> observed-sample round trip, invisible to the static graph. The propagated `correlation_id` closes that gap: the cycle-guard walk follows a **real carried id** across the round trip instead of inferring lineage.

## disagree and divergence

Drift is a condition operator, **`disagree(A, B)`**, usable inside event rule conditions, comparing two provenances (or two sources) of one name:

- `disagree(intended, observed)`: the command did not land (reconciliation)
- `disagree(declared, observed)`: the world drifted from intent (config drift, device swap)
- `disagree(observed, observed)` across `source`: sensors conflict (a failing sensor)

> Any two provenances of the same name that disagree = an anomaly. One detector.

:::design[Fusion, tracked in #430]

## Fusion

Multiple sources reporting one signal land as **perspectives**: source-tagged observed rows, **all preserved**. A reduce-on-read **policy** produces the effective value:

- **same-name, many sources** reduces on read, among the perspectives of one writer class (a `collected` key's; [the writer class](#who-writes-a-key-the-writer-class)). **`fusion_policy`** is a **default/hint, not a mandate** (the right reduce is often unknowable a priori): a policy may default from the type, be source-weighted, per-instance, or **left open** for read time, an operator, or AI. When it reduces (`mode`: priority / weighted / majority / worst / average / latest, plus tie-break and per-source weights), the reduced value is what current-value reads and event_rule evaluation see; perspectives stay queryable. event_rule evaluation reduces over the **latest-per-source perspective set** held from the live `samples` stream (bounded, in-memory), never a firehose scan. A `source` registry carries default trust weights. A fused series materializes only if a profile earns it.
- **cross-name / system-level** is a **`calc_rule`** (the only fusion that authors a rule): `room-in-use` from display power + codec call-state + occupancy, a higher-order fact with a new name, not a same-name consensus. See [calculations](/architecture/calculations/).

Conflict detection (`disagree(observed, observed)` across sources) is complementary: a perspective disagreeing beyond tolerance is itself a signal.
:::
