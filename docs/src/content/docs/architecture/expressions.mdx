An **expression** is a small piece of text an operator writes wherever the platform needs a computation
or a judgement: an event rule's criteria (`value > 80 && instance != "aux"`), a calc rule's reduce
(`avg(temp)`), an action rule's `when` (`severity_rank >= 40`). Every one of them runs on **one engine**,
so there is exactly one language to learn: `internal/expression`, built on
[Expr](https://github.com/expr-lang/expr) (pinned at v1.17.8) (#524). To write one in the console, see
[rules](/admin/rules/) and [calc rules](/admin/calc-rules/).

## Sites

Each place an expression is written is a **site**, declared once in code as a Go struct: the names an
expression may use and their types and docs, the type it must yield (a criterion yields true or false),
the builtins it admits, and its run budget. The table below is generated from those declarations
(`make gen`):

<ExpressionSites />

- **criteria**: an [event rule's](/architecture/alarms-actions/#the-event_rule) fire and clear criteria,
  over one sample (`value`, `key`, `instance`, `component`) and, for a trend rule, its `window` and
  `age`.
- **calc**: a [calc rule's](/architecture/calculations/) reduce. Its bindings are authored with each
  rule: every input by its alias as the list of its values, from a struct type built when the rule is
  written, so the table describes them rather than listing them.
- **action**: an [action rule's](/architecture/alarms-actions/#the-action_rule-when-a-message-is-sent)
  `when`, over one alarm transition: the alarm facts a notification renders, in snake_case, plus the
  severity's rank. A test holds the two to one declaration, so a predicate and a message see the same
  alarm.

**`POST /expressions:validate`** (`omniglass expression validate`, gated `rule:read`) answers from the
same declarations: given a site, a source and its context (the sample key for criteria; the output key
and inputs for calc), it says whether the expression compiles, with each diagnostic, and returns the
site's bindings, builtins and budget.

## Compiling once

An expression compiles against its site's declaration. A name outside it, a result of the wrong type,
or a parse error is refused with a **diagnostic**: the line, the column and an operator-readable message
(a nested binding is named by its path, `component`, never by a Go type). A name nothing binds is said
by name, so an editor can offer to bind it; a `let` that would shadow a binding is refused where it is
declared. A fault inside a call's argument (an unknown name in `max(fan)`) is checked by the engine
itself, since Expr trusts a call's result type without looking inside again.

A compiled program is **cached** by its source and its site in a bounded cache, so a hot path (criteria
judged per sample) never recompiles; an event rule also holds its compiled criteria per rule version, a
failed compile included.

## Safety

Expressions are **sandboxed**: no I/O, no network, no unbounded loops, bounded execution
([ADR-0146](/architecture/decisions/#adr-0146-expressions-run-on-pinned-expr-with-an-allowlist-and-per-site-budgets-and-rule-criteria-are-expressions)).

- **An allowlist of builtins.** Every Expr builtin is off, and each site declares the builtins it admits.
  A builtin is admitted only once vetted: its cost linear in what the run is charged for, its output no
  larger than its inputs. The criteria set is comparison, arithmetic, `in`, `contains`, `startsWith`,
  `endsWith`, `matches` with a constant pattern (capped in compiled size and charged its subject's length
  times that size), `len`, `abs`, `ceil`, `floor`, `round`, `min` and `max` on numbers, `lower`, `upper`,
  `trim`, `trimPrefix`, `trimSuffix`, and `all`, `any`, `none`, `one`, `count` and `filter` over a bound
  list with no predicate nested in another. Equality and `in` take scalars and lists of scalars, never a
  record or a list of lists, whose deep comparison no charge covers. Builders and encoders (`map`,
  `reduce`, `repeat`, `replace`, `join`, `uniq`, `flatten`, `toJSON`, the range `..`) are never admitted:
  their cost is native work no input charge bounds.
- **List functions** (#1018), vetted the same way and admitted where a site binds lists: `max` and `min`
  over a list of numbers, `avg`, `sum` (with or without a predicate), `majority` (the most common text
  or bool, a tie to the value that sorts first), and one-list `any` and `all` over bools beside their
  predicate forms. Expr parses `any`, `all` and `sum` as predicate builtins only, so a one-argument call
  is told apart lexically before parsing and renamed in place to the engine's own function of the same
  length, keeping every position in the source where the author wrote it.
- **Trend functions** (#1985) read a list of timestamped points, each with a number `value` and its `at`
  in unix seconds: `slope` is the least-squares rise per second, `span` the seconds from oldest to
  newest, and `growth` the fitted rise across that span as a share of the points' mean
  (`slope * span / |mean|`), so `growth(window) > 0.25` reads "rose by more than a quarter of its level"
  whatever the unit. Fewer than two points, or no time between them, is no trend: 0. They are admitted
  where a site binds such a list: an
  [event rule's window](/architecture/alarms-actions/#a-trend-rule-reads-a-window-not-a-sample) and a
  calc rule's [windowed input](/architecture/calculations/#windowed-inputs).
- **Names stay owned.** A builtin's or list function's name can never be bound, so admitting one later
  never changes what a stored expression means. A `$` name (Expr's dynamic `$env`) is refused, so a
  site's bindings are the whole namespace.
- **Determinism.** The clock and zone builtins (`now`, `date`, `duration`, `timezone`) can never be
  vetted; a time an expression needs is bound by its caller as data. An expression calls builtins only,
  never a method, and a site's environment holds concrete data types, so no value chooses its behavior at
  run time.
- **Caps and budgets.** A source is at most 4,096 bytes and 1,000 parse-tree elements, a list or map
  literal at most 64 entries. A run is bounded deterministically by its site's budget of what it
  allocates and walks, under a fixed ceiling; a wall-clock deadline backs the budget for charged work
  only, which is why the allowlist exists.
- **Values are data.** A bound value (a sample's text, however hostile) is evaluated literally, never
  executed. Integer arithmetic wraps on overflow, as Go's does.
- **Refused, never crashed.** Expr's optimizer is off: in v1.17.8 it rewrites `filter(list, p)[0]` in a
  way that panics on a field read of the result, and it comes back on when upstream is fixed (#1006). A
  panic in any compile stage is refused as a type error naming the stage and the construct.

## The expression field

The console's **expression field** (an event rule's **Write as an expression**, #960; a calc rule's
reduce; an action rule's `when`) is the validate route's face: a CodeMirror 6 editor (#1000) driven
entirely by the route's answer. It highlights Expr as it is typed, completes exactly the site's bindings
and builtins (as a word begins, or on Ctrl-Space, the first word included), shows a binding's doc on
hover, and underlines each diagnostic where it sits as well as listing it beneath with its line and
column. A site's form may offer starters (a calc rule's list functions) and an action on an unbound name
(a calc rule's **Bind it to a key**). The editor is a chunk of its own, loaded only by a page with an
expression site; a page that cannot load it says so and refuses the source.

## Diagnostics: clear messages and quick fixes

Expr's own refusals are accurate but speak the checker's language: `sum(members, .has.t) > 0` is
refused as an operator mismatch at the `>`, when the mistake is the `sum`. And an expression can compile
and still probably be wrong. So the engine keeps a **registry of diagnostics** (#1021,
`internal/expression/diagnostics.go`). Each common mistake is one declared rule with:

- a stable **code** (`sum-of-bools`), a **severity** and the **sites** it applies at. An **error** refuses
  the expression; a **warning** (probably wrong) and a **hint** (could be simpler) ride along with one
  that compiles and never refuse it.
- a **trigger**: a **refine** rule runs when the engine refuses an expression and recognises the shape
  behind the refusal, replacing the message with a clearer one at the mistake; a **lint** rule runs on an
  expression that compiles and flags a likely mistake.
- a **matcher**, a pure function over the typed tree, returning the positions it found.
- a **message**, and an optional **fix**: one text edit an editor offers as a quick fix.
- **fixtures** in Go: expressions it must and must not flag, with the source a fix must yield (which must
  compile clean). A rule without both kinds of fixture refuses to register, and a fixture that disagrees
  with its rule fails the build.

A site's rules run once per compile, so a cached program carries its warnings and hints. A matcher that
panics is a bug in the rule: the expression is judged as if the rule were absent, never refused by it.

The validate route answers each diagnostic's `severity`, and a registered one's `code` and `fix`, so the
expression field shows them where they arise (#1053): an error is a wavy red underline and refuses the
source, a warning a wavy amber one, a hint a dotted one, neither stopping a save. Beneath the field each
diagnostic names its severity, links its code to its entry below, and offers its fix as a button (F8
moves to the next diagnostic; Mod-Shift-M lists them). A fix is the author's own edit, so Ctrl-Z takes it
back. A stored rule's warnings show on its blade as a note.

## Not every input is an expression

No driver evaluates an expression today. A [driver spec](/architecture/collection/#drivers-the-declarative-menu)
locates and transforms values with declared selectors and a `cast`, `scale` or enum `map`, and its
configuration values are typed **inputs** supplied at attach, a secret input a reference resolved under
the caller's own secret scope. So an operator's value is always data the interpreter reads, never text
it runs.

:::design[Driver transforms, guards and Omniglass functions, tracked in #1331]
A driver emit gains an expression **transform** (`raw / 100.0`, `int(groups[1])`) beyond the built
`cast`, `scale` and `map`, and a driver function gains a **guard** (a false guard skips the poll or the
step it gates). On top of Expr ride **Omniglass functions** that binary and raw-TCP protocols need: frame
`encode` and `decode`, and hex, ascii and base64 helpers, each vetted into the sites that need it. A
driver site binds `$var:<name>` (a variable through the cascade), `$prop.<key>` (a property, readable for
branching), `$event` (a listener's payload) and the extractor's own inputs (`raw`, `groups`, `outpost`,
`item`). Configuration values stay data in the environment, never spliced into text, and a secret field
rendered into a request is masked at interpolation and never surfaces in a log or an error. The engine is
not pluggable: one dialect everyone authors in.
:::

:::design[The remaining sites, tracked in #1023]
| Site | What it evaluates |
|---|---|
| rule `scope` | which components or instances a rule applies to, beside the built type-and-id selector |
| views and lists `filter` | the predicate a structured query composes |
| dynamic group membership | which entities a group holds, recomputed |
| calc `filter`, `worst`, `time_in_state` | per-input filters, a fold by a property's declared order, and the windowed time in a state that service levels need |
:::

:::design[Unit conversion and divergence, tracked in #2609]
**`convert(value, "<unit>")`** lets an operator write against a unit other than the key's canonical one:
`convert(value, "fahrenheit") > 100` reads in Fahrenheit while storage stays in canonical Celsius. The
source unit is inferred from the bound key, the target must be a registered unit of the same family (a
compile error otherwise), and the transform comes from the
[unit catalog](/architecture/properties/#units-one-canonical-unit-per-metric).

**`disagree(A, B)`** compares two provenances or sources of one key, one operator for drift from a
declared value, a reconcile conflict and cross-source disagreement: divergence, the universal anomaly
signal. It reads both sides as inputs and never writes back into either, which keeps the pipeline
acyclic.
:::
