:::design[The template authoring model, tracked in #827]

Collection is built from **functions**. A versioned `ComponentTemplate` declares how to reach a
class of device (its endpoints) and a set of **functions**, each a discrete unit of device logic
that runs on the edge node and parses the answer on the spot into samples; one authoring schema
covers everything from a single SNMP read to a multi-step branching procedure.

## Model overview

The shape:

```text
ComponentTemplate (apiVersion, kind, metadata.labels)
  inputs       typed parameters; required = the :apply gate
  endpoints   connections, declared once, may be persistent/stateful, own liveness
  functions    each = one trigger + a DAG of steps
    steps      typed operations (kind), gated by an endpoint, schema-validated
```

- **Authoring compiles to a runtime unit**: the compiler resolves inputs and variables, validates
  the DAG, and bakes each sample's lane into the per-node unit (no runtime catalog lookup); the
  unit is internal, never hand-authored.
- **Edge-local execution**: a function runs per component on the node, in one tick, zero server
  round trips; a step can branch on a value a prior step just collected.
- **Two data planes**: append-heavy timeseries [samples](/architecture/properties/) versus
  point-lookup [config and credentials](/architecture/variables/), config keyed to a sample as its
  observed side.
- **Kubernetes-style versioning**: `apiVersion: collection.omniglass.dev/v1alpha1` plus `kind`
  (`ComponentTemplate`; `SystemTemplate` / `LocationTemplate` reserved); the parser gates on
  `apiVersion`, converting older versions forward.

A **function** is the device-level unit; the platform workflow that responds to data is a
[flow](/architecture/alarms-actions/), which can call a function.
:::

## Endpoints: the device's APIs, declared once

An **endpoint is an API we intend to call** on a component (`web`, `qrc`, `ttp`, `snmp`), **not** a network endpoint; a host or IP is a variable it consumes, not its identity. It is **named by the protocol it speaks**, unique within its component. Reachability is the **first gate of a ladder** (reach, auth, responds, collecting), needing only the transport. The top-level `endpoints` array declares each once; steps reference one by `id`, the endpoint owns the connection, and a **persistent session outlives any single function run**, so subscriptions and inbound streams attach to a connection established once.

```yaml
endpoints:
  - id: snmp
    type: snmp                     # transport registry entry (param schema)
    host: ${input.ip}              # references INPUTS, not $var: directly (see Inputs)
    version: "2c"
    auth: ${input.snmp}            # snmp-community shape; community field is secret (masked, audited)
    liveness: { oid: 1.3.6.1.2.1.1.3.0 }   # reachability gate, per endpoint
  - id: cli
    type: ssh
    host: ${input.ip}
    credentialRef: ${input.ssh}    # basic-auth shape, bound to a $var: at apply
    persistent: true               # stateful session, outlives function runs
```

- **Type is the `transport`, which is the transport**, not the protocol driver: the registry covers `snmp`, `http`, `ssh`, `telnet`, `tcp`, `icmp`, `webhook`, `mqtt`, `syslog`, and `websocket`, each with a connection-param schema and default reachability probe. The protocol handler turning a device's API into a normalized menu of samples and functions is a separate **driver** layer, so a device's OIDs live in its driver, never on a template ([ADR-0039](/architecture/decisions/#adr-0039-an-endpoint-is-a-device-api-the-endpoint-type-is-its-transport-not-its-driver)).
- **A label is the one identity string an operator types on an endpoint.** The name is derived from the type, so every SSH endpoint in the fleet reads `ssh`: the row says which protocol it speaks and nothing about what it is for. The label ("Control processor") is where that goes, and it is settable at create rather than on a following edit, an endpoint labelled by a second call being unlabelled at the moment it is made ([ADR-0119](/architecture/decisions/#adr-0119-a-table-an-operator-names-carries-a-label-or-declares-why-it-does-not)). It is optional; an endpoint with none reads its derived name **verbatim**. Note the corollary of a derived name: since the name IS the protocol and is unique within the component, a component holds at most **one endpoint per protocol**, and a second of the same type is a 409.
- **`liveness`**: the per-endpoint reachability gate deciding whether its functions run ([nodes](/architecture/nodes/)).
- **`persistent: true`** keeps a session open across runs; scheduled functions borrow it to send, listen functions wake on its inbound.
- **Codec and framing**: raw-TCP AV control planes wrap payloads (line terminators, length prefixes, NUL framing, JSON-RPC or TTP envelopes); the endpoint's codec frames outbound and parses inbound to the declared envelope, so a step sees structure, not wire bytes.
- **Node placement is not declared here**; it is server-assigned from the component's location.

:::design[Functions: a trigger plus a step DAG, tracked in #827]

## Functions: a trigger plus a step DAG

A top-level `functions` array: each **function** is one trigger plus a DAG of steps. The trigger
unifies what used to be a poller, a listener, and a command:

| Kind | Fires when | This is |
|---|---|---|
| `schedule` | an interval elapses, or `onStart` once when the endpoint comes up | a poll (and `onStart` arms subscriptions) |
| `listen` | inbound data arrives on a `source` (`webhook` / `trap` / `syslog`, or `subscribe` / `stderr` / `session-line` on a persistent endpoint) | a listener for pushed data |
| `command` | invoked on demand, by an operator or by a [flow](/architecture/alarms-actions/) | an action you run against the device (`reboot`, `set-input`) |

A `command` function takes typed `args`: the imperative path, and how a reconcile pushes declared
config back (the **set** function, [config](/architecture/variables/)). Exactly one trigger per
function; `triggers` is a list only to admit a scheduled function that is also command-invocable
for a targeted refetch.
:::

### Two axes: task mode and endpoint transport

A **task** is a node's unit of collection work, described by two independent axes:

- **Task mode** (on the task): **poll** (we ask) or **listen** (we wait), stated from *our* perspective on purpose, since "pull/push" inverts with the frame.
- **Transport** (on the endpoint): **stateless** (a throwaway connection per shot) or **stateful** (a held-open connection, a **session** whose state is the `session-state` property per endpoint, its connect/drop/reconnect reasons in the node's own logs; [ADR-0150](/architecture/decisions/#adr-0150-a-held-sessions-state-is-a-property-series-and-node-logs-not-a-session-table)).

All four cells are real:

| | **poll** (we ask) | **listen** (we wait) |
|---|---|---|
| **stateless** | SNMP get, an HTTP request (a driver's poll over http or https), a udp datagram request | webhook, SNMP trap, syslog, a udp push to the endpoint's own port |
| **stateful** | SSH-exec or xAPI `xStatus` on a held session, a get frame over a websocket | MQTT subscribe, xAPI feedback, an http server-sent events stream, a websocket subscription |

Waiting for a frame is one mode (**listen**) regardless of transport; statefulness lives on the endpoint.

### Sessions

Built (#816): a session **holds its connection** across ticks. The node holds one per endpoint
whose worklist carries a standing listen task over a transport with a session dialer (the line
protocol over `tcp`, `tls` (#1035), `telnet` (#1033) and `ssh` (#1032), a server-sent events
stream over `http` and `https` (#1038), and a socket over `websocket` and `wss` (#1034)), or any driver poll over `tls`, `telnet`, `ssh`, `websocket` or `wss`, or a driver poll whose driver declares a `session` block (a login a
throwaway connection would skip, #1049), keyed by the endpoint's id, which the worklist carries
beside its name (endpoint names are unique only per component). The machine runs on its own:

- **establish**: the first dial; the session reads `establishing` until it connects.
- **authenticate**: when the driver declares an auth step, it runs on every connection between the
  dial and anything else ([auth and rejection, below](#auth-and-rejection)): no poll, command, or
  listener arm rides a connection whose auth step has not passed.
- **operate**: the session reads `up`, and the endpoint's line polls **borrow the held connection**
  instead of dialing per tick. One reader goroutine owns the connection: on an ask it discards
  whatever already arrived (a banner, a stray line), writes the line, and hands the next line to
  that ask. An ask whose answer does not come in time recycles the connection, since its late reply
  would answer the next ask. A pushed line a listener claims is never an answer, and a request that
  declares its reply shape takes only a line that shape matches ([routing, below](#listeners-over-a-held-session)).
  A poll issued while the
  first dial is in flight waits for it (on a budget of its own, then the exchange gets its whole
  timeout); any other poll over a session with no connection faults at once with a
  `collection-failed` naming the state, so a down device never stalls the node's tick, and it never
  dials a connection of its own.
- **recover**: a held connection that drops (the peer closed, a read failed, the TCP keepalive gave
  up, an unshaped answer timed out) reads `recovering` at once, without waiting for a poll, and redials with
  a jittered exponential backoff (250ms doubling, capped at 30s, 20% jitter). Five consecutive failed
  attempts read `down`, where an attempt fails if its dial fails, its connection drops unanswered
  within 10s, or an answer over it timed out; so a device that accepts and drops, or accepts and
  never answers, reads `down` rather than `up` forever. An answered exchange forgives the failures
  before it, so a healthy device's rare missed answer never reads `down`. The session keeps retrying
  at the capped pace and leaves `down` only when a returning connection proves itself (an answer, a
  listener's push, or outliving 10s unless answers were what failed), so a failing device publishes no flapping; a
  stable connection's drop redials at once.
- **teardown**: a listen task that leaves the worklist, a change to what the connection depends on
  (transport, address, timeout, credentials; a listen task's spec re-hash keeps it), or node
  shutdown closes the connection. Teardown publishes no state (the node stopped wanting the session,
  which says nothing about the device), so the last `session-state` outlives it and is read by its
  age.

There is **no session table**: each transition lands as the `session-state` property on the
endpoint's component (instance: the endpoint's name), published at the transition under the listen
task, and as a node self-log (`facility: session`) carrying the reason
([ADR-0150](/architecture/decisions/#adr-0150-a-held-sessions-state-is-a-property-series-and-node-logs-not-a-session-table)).
Proven against the simulator's line protocol: kill the device's listener mid-session and the session
reads `recovering`, then `up` once it returns, with the transitions landing on the server.

### Auth and rejection

Built (#1049). **Auth is a layer that gates the session**, the held-session form of the ladder the
stateless probes climb (dialed, responds, authenticated). Each attempt runs in order: dial, then the
**auth step**, then the listeners' arm, then `up`. The auth step is declared by the driver (a login
dialog in its `session` block) or by the transport (a transport that authenticates on its own); its
verdict lands as the `endpoint-authenticated` property (`yes` or `no`, published when it changes),
the same rung the ssh probe writes. A login that never prompts or a connection that drops mid-login
decides nothing: it is an ordinary failed attempt.

**One login dialog.** A driver declares the prompts to wait for, what to send at each (a secret
input's field, `${secret.<input>.<field>}`), and the match that means ready. A prompt need not end a
line (`login: ` waits on the same line): a partial line is judged once the component pauses on it,
never at an arbitrary read boundary, so a banner arriving in pieces is read whole. A prompt for a step
already answered (the component asking again) is a refusal. The same primitive answers a raw tcp password prompt, a telnet login, and
ssh keyboard-interactive questions. A credential is only ever written to the wire: a refusal names
the reference that was missing, never its value, and any text the component sends is scrubbed of
what was sent before it reaches an error or a reason, so an echoing component cannot leak it.

**Terminal or retryable.** A refusal retrying cannot fix is a **terminal error**, a class and the
component's own text: the driver declares which replies are terminal (`session.terminal`, each a
match with a class: `auth`, `host-key`, `certificate`, `protocol`), and a transport classifies its own
protocol refusals. A terminal reply during the login, to a poll, a command, or a listener's arm
rejects the session; anything unclassified stays retryable and follows the backoff and budget above.

**The login budget.** A component that hangs up after the final secret and before ready, with no
refusal text, cannot be told from a dropped connection one time; three such logins in a row are an
`auth` refusal (the #1056 ruling). A drop before the secret step stays an ordinary failure, and a
login that passes resets the budget.

**Rejected.** A terminal error moves the session straight to `rejected`, without spending the
budget: it closes the connection and dials no more. Polls fail fast with the refusal (a terminal
fault waits the poll's interval, never the failure backoff), commands fail with the reason, and
neither falls back to a throwaway connection, which would retry the bad credential. It leaves
`rejected` only when its **connection fingerprint** changes ([below](#the-connection-fingerprint-and-the-layered-gate)):

- anything it connects with changes: the attached secret rotated in the secret store (the endpoint
  row untouched), the address, port or attached secret (a driver-attached endpoint's inputs edit
  in place, `PATCH /endpoints/{endpoint}` with `inputs`), the transport, the driver's login or terminal declaration (re-derived to the endpoint, #823), or
  its pin. The session is recycled and reconnects within a tick;
- an operator retries it (`POST /endpoints/{endpoint}:retry`, gated by `endpoint:retry` and audited): the
  endpoint's retry counter, part of the fingerprint, moves;
- the driver declares a slow re-probe (`session.reprobe`, at least 5m; the default is never).

An unrelated edit (a label) moves nothing the fingerprint covers, and a rejected session stays
rejected.

Each transition also lands `session-reason`, the reason as a property (`auth: auth rejected` when
rejected), so an event rule can alarm on it, and the node logs it once, at the transition. Proven
over a real socket (`linesession_login_integration_test.go`: a raw tcp line protocol behind a
password prompt; the right password logs in before the first poll, a wrong one is dialed exactly
once, never arms, and reads `rejected` with the component's text) and over fakes for the machine
(`session_auth_test.go`: a wrong credential dials once over an hour of the session's clock, a retry
dials once more, a re-probe fires on its interval, a transient failure still spends the budget).

**In the console** (#1059). The component's reachability read carries each endpoint's latest
`session-state` with the `session-reason` beside it, while the endpoint is configured to hold a
session (teardown publishes nothing, so a session nobody holds is not served), and the rung and
class of its `endpoint-rejection` (never the fingerprint, which is the node's to compare). Like
every native probe key, a session's state and reason are the node's own facts, which the push lane
refuses ([the push lane refuses a native key](#the-push-lane-refuses-a-native-key)), so no push can read a
rejected session up or plant a reason the node never scrubbed. So the component's
Collection card, its Endpoints panel and the endpoint's detail show the session as a pill, the
ladder with the held rung marked, and, for a down or rejected session, the reason. A state is stored
only on a transition, so the pill is aged by the endpoint's `last_seen`, as ADR-0150 requires: a
session whose endpoint has delivered nothing for the staleness window reads grey, saying what it
last read. A rejected session offers **Retry** (`:retry`, gated `endpoint:retry`, greyed with its
reason for a caller without it) and the way into the endpoint's edit, where pointing the credential
at the right secret moves the fingerprint. The same refusal shows whatever met it (#1110): an
endpoint holding no session whose reachability probe was refused (a tls certificate, a udp terminal
reply, an snmp `authorizationError`, the ssh probe's params credential) carries the gate with its
reason, `endpoint-rejection-reason`, which the node publishes beside it, so the notice, its reason
and **Retry** read the same with no session pill beside them, the retry waiting on the gate rather
than on a session ([ADR-1110](/architecture/decisions/#adr-1110-a-gate-says-why-it-holds-and-the-console-shows-it-whatever-met-the-refusal)). The [collection guide](/guides/operator/collection/#held-sessions)
teaches it, and the `fix-a-rejected-session` walkthrough drives it against the simulated panel.
A refusal of a changed key (#1078) names both keys, the pinned and the offered, which the gate
carries as data, and offers **Trust this key**: a confirm that teaches why a key changes, then
`:retry` with exactly the offered key it showed as `host_key`, which the server refuses (409) unless
the refusal on record still names it ([ADR-0159](/architecture/decisions/#adr-0159-a-refused-keys-evidence-rides-its-gate-and-trusting-a-key-is-checked-against-the-one-offered));
the `trust-a-changed-host-key` walkthrough drives it against the simulated panel's ssh console.

### The connection fingerprint and the layered gate

Built (#1056 ruling, [ADR-0158](/architecture/decisions/#adr-0158-one-connection-fingerprint-gates-every-connection-on-a-ladder-the-driver-declares)). Every connection to an endpoint, held or
stateless (the reachability probe, a throwaway poll or command, the held session), is verified
bottom up on the existing ladder:

- **reachable**: a ping, **informational only**. An open, answering transport is what counts, so a
  component that blocks ping never reads down for it, and a cloud API is never pinged. The
  driver's ladder lands `icmp-reachable` beside the endpoint's probe (one observation per probe),
  after the verdict is judged. A layer-2 presence rung below it is #1062.
- **responsive**, the transport rung and **the gate**: a TCP connect on the transport's port, the
  protocol's handshake (the ssh key exchange, tls), or, where an open port cannot be detected
  (udp, snmp), the driver's named request answered (snmp's a standard get). A wrong host, address or port
  fails here, retryably, and never reads as auth.
- **authenticated**, the session rung: the login, attempted only when the transport rung passes.

The ladder is declared in the driver spec (`ladder.ping`, `ladder.transport`, `ladder.session`),
its defaults from the transport registry's `rung`, so most drivers declare nothing; a rung a
transport cannot run refuses at write. A terminal refusal gates its rung and every rung above it,
for the endpoint, while the **connection fingerprint** is unchanged: a digest the server computes
over every input a connection is made with (the transport, the declared params, the driver's
inputs, a digest of each attached secret's sealed envelope, never its plaintext, the session block,
the ladder, the ssh and tls pins an operator declared, and the `:retry` counter). A tls endpoint's
verification mode is one of its driver's inputs, so editing it moves the fingerprint too. The rungs below keep running, so reachability
stays observed while auth is rejected, except where the transport rung itself carries the credential:
an snmp get carries the community, so beneath an snmp auth gate nothing is sent and the rung reads
down, rejected ([snmp](#snmp)). The gate is published as `endpoint-rejection` (`<rung>
<class> <fingerprint>`, or `none`; a refusal of a changed key appends `<pinned-key> <offered-key>`,
its evidence, [ADR-0159](/architecture/decisions/#adr-0159-a-refused-keys-evidence-rides-its-gate-and-trusting-a-key-is-checked-against-the-one-offered))
and carried back on the worklist, so a restarted node makes no attempt against an unchanged
fingerprint and keeps the evidence it adopts. Beside it, in the same batch, the node publishes why:
`endpoint-rejection-reason`, the refusal's class and the component's own text, scrubbed of anything
the node sent, so a gate on an endpoint holding no session, which has no `session-reason`, still
says why it holds. A gate adopted after a restart publishes no reason, since the node never saw that
refusal, and the read serves the reason only while a gate holds ([ADR-1110](/architecture/decisions/#adr-1110-a-gate-says-why-it-holds-and-the-console-shows-it-whatever-met-the-refusal)). The ssh probe's params credential rides the same gate
(#1060): tried once, then the key exchange runs without it until the fingerprint moves, and never
past a pinned key that changed. So does the tls probe: under a `certificate` gate it runs only the
TCP connect, so no handshake reaches a key nobody trusted. A gate for a changed key carries the
pinned and offered keys after the fingerprint (`responsive certificate <fingerprint> <pinned>
<offered>`), which the reachability read serves as data (`rejection.pinned_key` and
`rejection.offered_key`). Proven end to end (`run_session_identity_test.go`): a silent panel
spends the login budget, then a label edit and a node restart try nothing, while a retry, a
login-declaration change, a rotated secret, and an ssh attachment each attempt again; a wrong
port reads down on refused connects and tries no login, and the port edited in place connects and
authenticates within a tick, a label edit through the same route recycles nothing, and the address
edited in place moves a healthy session to the new component; the ssh probe sends a wrong password once,
across a restart too, and authenticates after a params edit.

**Native push**: data pushed by smart senders is self-describing (it carries its key), its edge parse a near-identity pass-through marked `shape=native`; a failed parse keeps the raw on a `collection.failed` event.

### The push lane refuses a native key

Every key a native probe writes, its samples ([below](#poll-protocols-and-their-config)) and the
node's account of its own connection (the verdict and its rungs, the probe metrics and their
timings, a held session's state and reason, the host key or tls public key it trusted, a tls
endpoint's certificate facts, the gate it publishes), and the `collection-failed` a task lands when it
cannot collect (#1086), is the node's own observation, and the console reads it as one. So `POST
/telemetry:push` refuses each by name (#1080, [ADR-0158](/architecture/decisions/#adr-0158-one-connection-fingerprint-gates-every-connection-on-a-ladder-the-driver-declares)
point 5): on every lane, not just its own, under any instance and any casing, and the rejection's
reason names the key. The set is not a second list: it is `internal/collection/probekeys`, the
declaration the probes emit from, where each key is ruled node-only or pushable with the reason it may
be pushed. None is pushable today, and a key declared there without a ruling fails its test, as does a
key the reachability read serves that is not ruled node-only. A pusher with a measurement of its own,
an outside pinger's round trip say, registers a metric type for it rather than borrowing the node's.

The push lane is one write surface, and the refusal is no longer its alone: every key has one **writer
class**, and the Storage Gateway holds every write to it
([ADR-0161](/architecture/decisions/#adr-0161-every-key-has-one-writer-class-held-at-the-storage-gateway),
[the ruling](/architecture/properties/#who-writes-a-key-the-writer-class)). The probekeys set is the
`node-probe` class, so a declared value, a command, a calc rule or an event rule is refused on it the
same way (the ssh host key and the tls certificate admit one declared row, the pin set through an
endpoint's `:retry`), and a push is refused a `platform` key (`health`) and a calc rule's output,
naming the rule. On the node's own lane a node-probe key lands only under the endpoint whose task the
node ran: an empty instance is that endpoint's name, and any other (another node's endpoint on the same
component, a name no endpoint holds) is refused, while a driver's own keys keep the instance they name,
and a node-probe sample dated more than five minutes past the database's clock is stored at the
database's now, so a node's account of an endpoint cannot stay current past its tenure. A driver spec
may emit only a collected key: a reserved one is refused at the spec's write (#1035 found the pin
case: a driver emitting one would have the worklist hand it back as the pin), and again where the
node interprets a task derived before that refusal existed, so a driver cannot speak for the node
either.

## Endpoint types and their config

The poll types and listeners in the `transport` registry and the operator config they read. How the node *executes* these (tick scheduling, reachability gating, the task queue) is [nodes](/architecture/nodes/).

### Poll protocols and their config

Built today: the `icmp` and `tcp` probes, and the layer-7 `http` and `ssh` probes (#812): http
draws a real response off the API (any status is an answer), ssh runs a real key exchange and,
when the params carry a credential, tries it. The ladder facts each observes: an accepting port
whose API never answers is **reached but not responsive**, and a completed SSH exchange that
refuses the credential is **responded but not authenticated**. A task whose config cannot be used
lands a `collection-failed` event naming the task, never a silent skip. A probe's config rides
the endpoint's `params` JSON, unmarshalled on the node:

| transport | shape | config (`endpoint.params`) | samples |
|---|---|---|---|
| `icmp` | inline probe | `target` (host or IP), `count`, `timeout` | `icmp-reachable`, `icmp-rtt-avg` (fixed) |
| `tcp` | inline probe | `target` (`host:port`), `timeout` | `tcp-open`, `tcp-connect-time` (fixed) |
| `http` | inline probe | `target` (`host:port`), `timeout` | the tcp pair, `http-response-time`, `endpoint-responsive`; one `GET /` with no credential, any status an answer |
| `https` | inline probe | `target` (`host:port`), `timeout`, `tls-mode` (as `tls`) | the tcp pair, `tls-handshake-time`, `endpoint-responsive` (the handshake is the rung), `http-response-time` when a response follows, and the certificate facts as `tls` lands them; no credential |
| `telnet` | inline probe | `target` (`host:port`), `timeout` | the tcp pair, `telnet-response-time` (the first negotiation or banner bytes), `endpoint-responsive`; the login is the held session's auth step, never the probe's |
| `ssh` | inline probe | `target` (`host:port`), `timeout`, optional `username`/`password` (secret references arrive with the driver spec) | the tcp pair, `ssh-handshake-time`, `endpoint-responsive`, `endpoint-authenticated` (only when a credential was tried) |
| `tls` | inline probe | `target` (`host:port`), `timeout`, `tls-mode` (`verify`, `pin` or `skip`; derived from the driver's `tls-mode` input, verify when unset) | the tcp pair, `tls-handshake-time` (one per probe the component answered), `endpoint-responsive`, and for a certificate the mode accepted `tls-certificate-expiry` and `tls-certificate-days-left` |
| `websocket` | inline probe | as `http` | as `http`: a credential-free `GET /` is the rung, so reachability stays observed beneath a refused upgrade (#1034) |
| `wss` | inline probe | as `https` | as `https`: the handshake is the rung, then a credential-free `GET /` |
| `udp` | the driver's request rung | `target` (`host:port`), `timeout`, `listen-port` (derived from the driver's `listen-port` input; unset, the node picks one) | `endpoint-responsive` (here the verdict too), `udp-response-time` (one per probe the component answered); never `tcp-open`. A bare `udp` endpoint has no request to send and lands nothing |

The `raw-tcp` row below is built in its driver form: the line protocol over `tcp` holds a session
(#816) that polls, commands, and listeners share (#817). So is the `telnet` row (#1033): the same line
protocol behind a telnet filter that strips option negotiation and refuses every option (DO is
answered WONT, WILL is answered DONT, a literal 0xFF escaped), its login the driver's login dialog run
as the session's auth step on establish and every recover; proven against the simulated panel's
`nvp-telnet` face (login, poll, command, push, recover with a fresh login, and a wrong password
rejected after one attempt); while the node holds an endpoint's telnet session and it reads up, the
reachability probe takes its verdict from the session rather than dial a second connection (gear that
admits one telnet client would refuse it). And so is `ssh` (#1032): the line protocol over a shell
channel (with a PTY when the driver's `session.pty` asks, or an exec channel, `session.exec`), its
userauth the session's auth step with the credential the driver names (`session.credential`, a
username with a password or a private key, or keyboard-interactive answered by the login dialog). A
refused credential is `auth`, and the **host key is pinned on first use**: the node trusts the first
key it sees and publishes it as `ssh-host-key`, the server delivers it back as the pin on every
worklist, and a changed key reads `rejected`, class `host-key`, naming both fingerprints, which
the gate carries as data. An operator who trusts the new key (a replaced component) retries the
endpoint with it (`:retry` with `host_key`, audited with both keys; the console's **Trust this
key**), which declares the new pin and redials onto it; a key the refusal on record does not name is
refused. A declared pin is trusted only as that path wrote it (its row's `source` is `key-pin`): a
declared row any other path left is never delivered, and a pin the worklist stops delivering is one
the node forgets, trusting on first use again
([ADR-1100](/architecture/decisions/#adr-1100-legacy-rows-and-stored-declarations-honor-the-one-writer-ruling)).
Proven against
the simulated panel's ssh shell (poll, command, push, recover onto the same key, down after the
budget, a wrong password and a rotated key each rejected) and end to end ([ADR-0157](/architecture/decisions/#adr-0157-telnet-and-ssh-are-held-line-transports-their-login-is-the-drivers-and-the-ssh-host-key-is-pinned-on-first-use)).

#### tls

Built (#1035,
[ADR-0160](/architecture/decisions/#adr-0160-tls-is-its-own-transport-over-a-shared-primitive-and-its-pin-is-the-public-key)):
`tls` is the line protocol over a TLS connection, its own transport rather than an option on `tcp`, since an
endpoint is named by its transport (a component holds a raw control port and a TLS one side by side)
and its rung is the handshake. The handshake is one primitive: `https` consumes it as its own
registry entry by the same rule ([http and https](#http-and-https)), as does `wss`
([websocket and wss](#websocket-and-wss)), and the mqtt carrier consumes it later. Each connection, the held session's and the probe's,
runs the TCP connect and then the handshake under the endpoint's **verification mode**, its driver's
`tls-mode` input, edited in place like a host or a port:

- **verify** checks the certificate against the node's system roots, with the host input as the
  server name. Any failure (an unknown authority, a name mismatch, an expiry) is a `certificate`
  refusal carrying its reason, never a timeout: the gate's `endpoint-rejection-reason`, held session
  or not, which the console's refusal notice shows (#1110), beside the held session's
  `session-reason` where one is held, and a node self-log, said once when the probe meets it. A
  driver that declares no mode verifies.
- **pin** trusts the first public key the component offers and refuses any other, as the ssh host
  key is pinned. The pin is the key (its SubjectPublicKeyInfo, in the same `SHA256:` form as an ssh
  fingerprint), not the certificate, so a renewal that keeps the key is no change, and a certificate
  past its not-after still connects under its pinned key (its days left read negative, which a rule
  alarms on). The node publishes
  the key it trusted as `tls-certificate`, the server delivers it back as the pin on every worklist,
  and the node keeps one pin per endpoint, shared by its session and its probe and carried across a
  session's recycle. A changed key reads `rejected`, class `certificate`, naming both keys, and an
  operator who trusts it (a replaced component) retries the endpoint with it (`:retry` with
  `certificate`, audited), which declares the new pin. The seeded `newtron-nvp-tls` pins by default,
  since the gear it speaks to self-signs.
- **skip** checks nothing: an operator's explicit choice, never a driver's default (a spec defaulting
  to it is refused at write), shown on the endpoint's row as **unverified**.

The probe lands the handshake rung's timing (`tls-handshake-time`, one observation per probe the
component answered) and, for a certificate the mode accepted, its not-after as the
`tls-certificate-expiry` property and the days left as the `tls-certificate-days-left` metric, the
number a threshold rule reads (an expression cannot read the clock). Under a `certificate` gate the
probe connects only, so those freeze at the last accepted certificate; the reachability read
withholds them while the gate holds rather than show them as current, and serves the pinned key in
pin mode alone. A bare `tls` endpoint's `tls-mode` param is checked where it is written, as a
driver's input is. TLS 1.2 is the floor, and the
component is authenticated alone: no client certificates, and no per-endpoint CA bundle. Proven
against the simulated panel's `nvp-tls` face over a real handshake (poll, command, push, recovery
onto the same key, a changed key held beneath the gate across a node restart and accepted with
`:retry`, verify refusing the self-signed face as `certificate`, skip connecting) and end to end.

#### http and https

Built (#902, [ADR-0902](/architecture/decisions/#adr-0902-http-polls-and-commands-send-real-requests-read-through-one-extraction-authenticated-by-a-declared-scheme)):
`http` is a full collection transport, stateless: every poll and every command is a request of its
own, with no connection held (a login's session, below, is state the node keeps, never a held
connection). `https` is the same over the shared TLS primitive, its own registry
entry as `tls` is ([ADR-0160](/architecture/decisions/#adr-0160-tls-is-its-own-transport-over-a-shared-primitive-and-its-pin-is-the-public-key)'s
rule: its rung is the handshake, and a component may serve a plain web port beside a TLS one).

**The request.** A driver's http request declares its `method` (GET unless it says otherwise),
`path`, `query`, `headers`, a `body` and the response's `format`: `json` (the default), `xml`,
`html` or `text`. The format is declared, never sniffed from the `Content-Type`, since gear
mislabels its content. A command's request renders its `${value}` and `${arg.key}` references
injection-safe: a path substitution is escaped as one segment (a value cannot add a `/` or a `?`),
a query value is encoded, a header value carrying a control character is refused, a JSON body is
rendered leaf by leaf and then encoded (a leaf that is exactly one reference keeps the value's type,
so an intended volume rides as a number), and an xml body's substitutions are escaped as text. A
request never sets the credential headers (`Authorization`, `Cookie`) or the ones the client owns,
and never names a secret.

**The answer, through one extraction primitive.** An emit locates its value with exactly one
selector, bound to the declared format at write: a `jsonpath` (the dotted path) on a json answer, an
`xpath` on an xml answer (namespace-aware, its prefixes declared on the request's `namespaces`) or on
an html answer parsed as a browser would (an OEM component's status page), and a `regex` on any
body as text. A selector yields exactly one value: an element's text (trimmed) or an attribute's
value, or a scalar expression's result (`count(...)`); one that finds nothing, or more than one node,
faults that emit by name while the rest still land. An answer is parsed once, however many emits
read it.

**Auth is the session block's scheme.** `session.credential` names the secret input and
`session.scheme` says how it rides every request: `basic` (a `basic-auth` username and password),
`bearer` (a `bearer-token`), `api-key` (an `api-key`, in a header or a query parameter as the
driver's `session.api_key` places and names it), or `digest` (a `basic-auth` username and
password, [below](#logging-in-over-http)). The credential is written only into the outgoing
request: no error, reason, label or log line carries it, a query key is masked in every URL the node
names, and a component's text is scrubbed of it before it reaches a reason.

**The status table.** A rule the driver declares terminal decides first (`session.terminal` may
match a response's `status`, its body, or both: a gear's 403 for a wrong credential, an "account
locked" body). Then:

| answer | reads as |
|---|---|
| 2xx | success: the body is the payload |
| 401 to a credentialed request | a terminal `auth` refusal at the session rung (over a login session, a lapse first: [below](#logging-in-over-http)) |
| 408, 429, 5xx | retryable: the poll backs off, never sooner than its `Retry-After`, never later than its interval |
| 3xx | not followed: the request's own fault, naming where it pointed (a redirect to a login session's declared login page is a lapse) |
| any other 4xx (a 403, a 404) | the request's own fault: a `collection-failed` naming the status, the poll waiting its interval, nothing gated |
| no answer (refused, reset, timed out) | retryable, at the transport rung |
| a certificate the mode refuses | `certificate` at the transport rung, as `tls` |

A body past 1 MiB (64 KiB for a command's reply) faults naming the cap.

**The session rung is proven by the credentialed exchanges.** A credentialed 2xx lands
`endpoint-authenticated` `yes`, and a refusal `no`; a redirect, a 403, another 4xx or a 5xx never
judged the credential, so proves nothing either way.
A refusal gates the endpoint at the session rung for its connection fingerprint: no credentialed
poll or command is sent beneath it, across a node restart too, until the fingerprint moves (the
secret rotated, an input edited in place, an operator's `:retry`). The gate publishes its reason
beside it, `endpoint-rejection-reason` (`auth: the component refused the credential (401)`), so the
console's refusal notice says why and offers **Retry** on an endpoint holding no session
([ADR-1110](/architecture/decisions/#adr-1110-a-gate-says-why-it-holds-and-the-console-shows-it-whatever-met-the-refusal)).
The reachability probe sends no credential, so reachability stays observed beneath the gate. A probe request that carries the
credential (for a driver with commands alone) is #1120.

**https.** The endpoint's driver's `tls-mode` input (verify, pin or skip) judges the certificate as
it does for [tls](#tls), and its public key is pinned on first use as `tls-certificate`, one pin per
endpoint, shared by its probe, its polls and its commands; a changed key reads `rejected`, class
`certificate`, naming both keys, and `:retry` with `certificate` trusts the offered one. The probe
runs the handshake as its rung (`tls-handshake-time`, one per answered probe), lands the certificate's
expiry and days left for a certificate the mode accepted, then draws a response
(`http-response-time`). Beneath a certificate gate only the TCP connect runs.

**Commands.** An http command's delivery carries its rendered request and never a credential: the
node applies the endpoint's scheme from what its worklist delivered, so a credentialed http driver
that declares commands needs a poll to carry its credential (refused at write otherwise). The
answer is judged by the same table; its body (scrubbed of the credential) is the reply a binding
settling from the response reads through the same extraction (`settle.extract` may be a `jsonpath`
or an `xpath`, `settle.success` a match on the body).

The seeded `kestrel-api` reads the simulated Kestrel bar over https with basic auth (its system,
call and audio polls; `set-volume`, `set-mute` and `set-power`), and `http-json` reads the simulated
Tessellate sensor over http with its header key. Proven over real sockets
(`internal/collection/httpfetch_integration_test.go`: the request and its key, a redirect not
followed, the body cap, a query key never named, verify, pin and skip, the https probe) and end to
end against the simulator (`internal/node/run_http_test.go`: the bar polled and actuated three ways,
each command settled from its reply, a replaced key held beneath the gate across a restart until
trusted; a wrong header key sent once per fingerprint across a restart, a rotated key bringing it
up; a bearer token over namespaced XML and a query key over an HTML status page).

#### Logging in over http

Built (#1114, [ADR-1114](/architecture/decisions/#adr-1114-an-http-login-is-the-login-dialog-carried-over-to-http-and-its-session-lives-in-node-memory-alone)):
much gear's web API has no per-request credential. It has a sign-in: a form post that sets a
session cookie, or a JSON login that answers a token. An http session declares it as
`session.login`, the same login dialog a line session runs (#1061), carried over to http: each step
is a `request` rather than a prompt, and its references are only the secret fields it sends,
`${secret.<input>.<field>}`.

```yaml
session:
  login:
    path: /login                       # a redirect back here means the session lapsed
    steps:
      - request:
          method: POST
          path: /login
          body_format: form
          body: { username: "${secret.login.username}", password: "${secret.login.password}" }
```

A JSON login that answers a token captures it through the one extraction primitive and names the
headers that carry it on every later request, `${session.<capture>}`; an `expiry` reads how long
the session lasts (seconds), and `expired` is the text a request draws once it has lapsed:

```yaml
session:
  login:
    steps:
      - request: { method: POST, path: /api/login, body: { username: "${secret.login.username}", password: "${secret.login.password}" } }
    capture: [{ name: token, extract: { jsonpath: token } }]
    expiry: { jsonpath: expires_in }
    headers: { Authorization: "Bearer ${session.token}" }
    expired: { regex: "token expired" }
```

**The session lives in the node's memory alone.** Each http endpoint has one auth state on its
node, shared by its polls and its commands: a cookie jar holding the component's cookies, the
values the login captured and the headers they fill, and a digest challenge. It is never logged,
published or persisted, and it is dropped whole when the endpoint's connection fingerprint moves
(every login input is a fingerprint input: the steps, the captures, the headers, the paths, each
secret's sealed version), on a terminal refusal, and with the node process. A login runs on a fresh
jar before the first request, and again before a declared expiry lapses (with a tenth of the
lifetime to spare), never once per poll. A declared lifetime is held between 10 seconds and 30 days
(gear says "never" with a huge number); one the answer omits, or gives as zero or a word, declares
none, and the session lasts until a request finds it lapsed. Only a login session keeps cookies:
a request under a scheme is its own, as before, and a jar holds at most 64 cookies of at most 4 KiB.

**A lapse logs in once.** A request over a login session whose answer is a 401, a redirect to the
declared login `path`, or the declared `expired` text has lapsed: the node logs in once more and
replays the request once. A lapse right after a fresh login is the credential's terminal `auth`
refusal (`auth: the component refused the session a fresh login opened (401)`), never a second
login.

**A refused login is one attempt.** A login step's answer is judged as a login: a rule the driver
declares terminal, a 401, a redirect back to the login page, any other 4xx, or a 2xx at the last
step without the declared `ready` text (or without a value it captures) is the component refusing
the login, a terminal `auth` at the session rung (`auth: the login was sent back to the login page
(302 to /login)`). It is held as refused for the life of the auth state, the gate holds every
request beneath it across a restart, and the next login is the one the moved fingerprint brings.
No retry loop can lock an account out. A login that draws no verdict after its secrets were sent (a
5xx, a 408, a 429, a connection dropped once the request was written) is retried on the poll's
backoff, but three in a row spend the login budget, as a line session's does, and read `rejected`
with the component's last answer; a connection never made sends nothing and charges nothing. A
redirect anywhere else passes (a form login's way of saying yes).

**Digest** (RFC 7616) is `scheme: digest` on a `basic-auth` secret. The first request draws the
component's challenge, which the node answers (MD5, SHA-256, or their `-sess` forms; `qop=auth`, or
the legacy form with none), then holds, answering every later request at once with a rising count.
A challenge the component marks `stale`, or one under a nonce it rotated without saying so, is
answered afresh, never read as a refusal; a 401 to an answer of the nonce it still offers is the
credential's refusal. A 401 offering no digest challenge the node answers (Basic alone, an
algorithm other than MD5 or SHA-256) is the request's own fault, its schemes named: the credential
was never sent, so it says nothing about it. The password never crosses the wire.

**Never logged.** The values the auth state holds (the secret fields a login sent, the values it
captured, the component's cookies) are scrubbed from every reason and error as the credential is,
in every form a component could echo them, and from every URL the node names (a login step may
render a secret into its query, though never into its host: a step's path opens with a literal
`/`). What a login would capture is scrubbed even from the reason that refuses it. A captured
value with a control character, or longer than 8 KiB, refuses rather than riding a header, and a
command whose delivery names an address the node's worklist does not is never sent, so a session
opened with one component never rides a request to another. The node logs that it logged in and why (`opening`, `renewing
before expiry`, `the session lapsed`), never a value.

**Shaped for OAuth2.** A client-credentials grant (#1119) is this shape with no new primitive: a
request step posting the client's secret fields, a captured `access_token`, its `expires_in`, and a
bearer header.

The seeded `newtron-panel-web` reads the simulated Newtron panel's https API behind its form login,
and `boreal-edge-web` the simulated Boreal display's web admin over digest (and drives its power).
Proven over real sockets (`internal/collection/httpsession_integration_test.go`: one session across
many requests, one re-login and replay on a lapse, a wrong password one attempt and never retried, a
token renewed before its expiry, concurrent requests sharing one login, digest with MD5 and SHA-256
and a stale nonce, nothing the state holds in any reason) and end to end against the simulator
(`internal/node/run_http_login_test.go`: a form and a token login keep one session across many polls
and log in exactly once more when the component forgets it; digest answers its challenge, a stale
nonce, and a command; a wrong password reads `rejected` with its reason after exactly one attempt,
across a node restart, and the secret fixed in place brings each back).

#### A server-sent events stream

Built (#1038, [ADR-1038](/architecture/decisions/#adr-1038-an-http-session-holds-a-server-sent-events-stream-and-a-held-connection-carries-messages)):
many components' web pages update live from a server-sent events stream (`text/event-stream`), so
a driver can hold that stream and land each change the moment the page would, with no poll. The
session block declares it, a `GET` held open, and listeners claim its events:

```yaml
session:
  credential: login
  scheme: basic
  stream: { path: /api/events }          # format json (the default) or text
listeners:
  - name: volume-change
    match: { event: change, field: { path: path, equals: status.audio.volume } }
    emits:
      - { name: volume, extract: { jsonpath: value } }
```

**The stream is a held session.** A standing listen task holds it through the staged dialer every
held session uses: the connect is the TCP connect (and the TLS handshake over https, its pin the
endpoint's), the auth step logs in first when the session declares a login, then sends the stream's
`GET` with the scheme's credential, the login's session and the component's cookies, and reads the
answer's head, and only then does the reader start. A 200 carrying `text/event-stream` opens it; a
refusal is judged as any request's is (a 401 is a terminal `auth`, a lapsed login logs in once more,
a digest challenge is answered), and anything else (a 404, an answer that is not a stream) is a
failed attempt the session retries on its backoff. `session-state` and `session-reason` land as for
a held line session, `endpoint-authenticated` lands when the stream carries a credential, and the
registry's `http` and `https` entries read `held` because they now are. The endpoint's learned auth
(the jar, a login's session, the digest challenge) is the one its polls and commands share, so one
login serves them all.

**A message, not a line.** The held connection's unit is a message: a line on a line session, one
event here (its data, its event name, its id). The router offers each to the listeners first, as it
offers a line, and a listener's match claims one by its event name (`event`, alone or with a data
rule), a `prefix` or `regex` on its data, or a **JSON field match** (`field: { path, equals }` or
`{ path, regex }`, the dotted jsonpath grammar, compared as the extraction renders it). A claimed
event is read through the one extraction primitive in the stream's declared format (a `jsonpath` on
json data, a `regex` on text). An event no listener claims follows the spec's `unmatched` policy. A
stream has no upstream, so its listeners declare no `arm`.

**Resume.** The event-stream interpretation is the WHATWG standard's (`event`, `data`, `id`,
`retry`, comments, every line terminator). A dropped stream reads `recovering` and reconnects with
`Last-Event-ID`, the last event id it was sent (carried across a reconnect that saw no event), after
the server's `retry` (held between 250 ms and 30 s, the session backoff's bounds). A server replays
the events after that id, so nothing is lost and nothing comes twice; one that replays from that
event, sending it again first, has that one event dropped. A component that reboots and numbers its
events from 1 again has every new event land. The resume lives with the endpoint in the node's
memory, across a session's recycle while the endpoint reaches the same address, never persisted. An
event whose data passes 1 MiB is dropped whole (its id still counts, and it is named unclaimed) and
the stream reads on; an id past 1 KiB is ignored; an answer's head is held to 64 KiB, and to the
endpoint's timeout, as a refused answer's body is. A component must send the stream's head when it
opens it: one that holds the head back until its first event never opens while quiet.

**Beside polls.** The endpoint's polls and commands stay requests of their own. A refusal on the
stream gates them through the one fingerprint gate; a refusal a poll or a command meets stops the
stream too (it restarts rejected, and every reconnect checks the gate before it sends), and the
stream coming up never lifts a gate one of them met; and while the stream makes its first attempt
under a fingerprint, the endpoint's polls and commands wait for its verdict rather than sending the
same credential beside it. A poll's own fault (a 404, a redirect) waits its interval, whatever the
stream beside it reads.

The seeded `kestrel-api` holds the simulated Kestrel bar's stream beside its polls: its call, volume,
mute and power arrive the moment they change. Proven by the event-stream interpretation's tests
(`internal/collection/sse_test.go`), over real sockets (`httpstream_integration_test.go`: events in
order, a drop resumed after the server's retry with nothing lost or twice, a refused credential one
attempt, digest answered across a reconnect, a form login run first and again on a lapse, an
uncredentialed stream proving no credential, an answer that is not a stream never a refusal), in the
simulator's events face, and end to end (`internal/node/run_http_stream_test.go`: a change on the bar
lands within a second with no poll; a dropped stream reads recovering and resumes, landing each change
once; a wrong password reads rejected with its reason, sent once under the fingerprint, across a
restart; the secret fixed in place brings it back; a stream behind a form login logs in first).

#### websocket and wss

Built (#1034, [ADR-1034](/architecture/decisions/#adr-1034-a-websocket-is-a-held-session-of-text-frames-and-a-reply-is-matched-by-a-minted-id)):
many components' control APIs are a websocket, one socket carrying a subscription's pushes and the
answers to requests at once. `websocket` holds it, and `wss` holds it over the shared TLS handshake
(its own registry entry, its key pinned on first use and trusted again with `:retry` and
`certificate`, as `tls` and `https` are). A message is a **text frame**, routed by the precedence a
line session's is ([below](#listeners-over-a-held-session)), and a request is a frame: a
`line` sent verbatim, or a JSON `body` rendered injection-safe as an http body is (a whole-leaf
`${value}` keeps its type).

```yaml
transport: wss
session:
  credential: login
  scheme: basic                          # basic, bearer or api-key; or an http login
  upgrade: { path: /api/ws }             # a GET: its path, query and headers
listeners:
  - name: volume-change
    arm: ['{"type":"subscribe","paths":["status.audio.volume"]}']
    match: { field: { path: path, equals: status.audio.volume } }
    emits:
      - { name: volume, extract: { jsonpath: value } }
polls:
  - name: volume
    schedule: { every: 60s }
    request: { body: { type: get, path: status.audio.volume }, reply: { correlate: id, error: { regex: '"type":"error"' } } }
    emits:
      - { name: volume, extract: { jsonpath: value } }
```

**The upgrade is the auth step.** The socket is a held session through the staged dialer every
held session uses: the connect is the TCP connect (and the handshake over `wss`), the auth step logs
in first when the session declares an http login, then sends the upgrade, a `GET` built as every
http request is (`session.upgrade`'s path, the root when none is declared, its query and headers,
the scheme's credential, the login's session headers and its cookies), and reads the answer through
a 64 KiB head bound. A `101` that completes the opening handshake opens the socket. The upgrade is
one request, so a `401` or a `403` to it refuses the session as a terminal `auth` (a credential
refused, one the component wants and the driver does not send, or an origin it will not admit),
where the status table lets a request's `403` fault that request alone; a lapsed login (or a `403` to
a login session the attempt did not just open, which may be that session forgotten) logs in once
more and upgrades again, and only a `403` to a fresh login's session is judged; anything else (a
`200` from a web page, a `404`) is a failed attempt on the session's backoff. A terminal rule that
names a status judges the upgrade's answer alone: a frame has no status, so a status-scoped rule's
text never rejects the session from a reply. `digest` is refused at validation, since it answers a
challenge per request, and so is a `reprobe`, since a refused upgrade gates the endpoint and the
auth step reads the gate before it sends.
`session-state`, `session-reason` and `endpoint-authenticated` land as for any held session, and
the socket coming up lifts the endpoint's gate.

**A reply is matched by a minted id.** A request whose `reply` declares `correlate: <field>` (a
dotted path of object keys, on a JSON object body that does not set that field itself and holds an
object at every step of the path it does carry) has a fresh random id written into that field by
the node when it sends the frame (at execute, so a redelivered command never reuses one), and its
answer is the frame carrying the id back: a push before it goes to the listeners, and another
request's answer is never taken for it. Its `error` shape answers only a frame carrying its id. A
reply may instead declare a `prefix` or a `regex`, as a line's does, or a JSON `field` match (on any
held line session). A correlated or shaped request that gets no answer in time fails alone, the
socket kept; an unshaped one recycles the socket, since its late answer would answer the next.

**Keepalive, bounds and the probe.** The node pings every 30 s and the socket is dead when it hears
neither a frame nor a pong for two intervals, so a component that stops answering reads
`recovering` without waiting for a poll. Whatever the component sent before it closed the socket
is routed before the connection dies: an answer (a terminal reply among them, which rejects the
session) or a push read just before the close is never lost to it. A frame past 1 MiB is read off the wire, dropped and named
unclaimed, and the socket reads on; a binary frame is named unclaimed, since a listener reads text.
The node sends no `Origin`; a component that admits only its own pages takes one from
`session.upgrade`'s headers. No header the handshake owns (`Upgrade`, `Connection`, a
`Sec-WebSocket-*` header bar a subprotocol) may be set by the upgrade, an api key's placement or a
login's headers. The probe is http's (`https`'s over `wss`): a
credential-free `GET /` whose answer, any status, is the transport rung, so reachability stays
observed beneath a refused upgrade.

The seeded `kestrel-ws` holds the simulated Kestrel bar's control socket over `wss`: its subscribe
armed on every connection, its call, volume, mute and power pushed as they change, polls and the
`set-volume` and `set-mute` commands answered by their ids (a command settling from its answer).
Proven by the driver's validation and correlation tests (`internal/driver/websocket_test.go`), over
real sockets (`internal/collection/websocket_integration_test.go`: an arm on connect, pushes to the
listeners, an exchange answered by its id past a push and another id's answer, a refusal carrying
the id, a drop recovered and armed again, a wrong credential refused once whether `401` or `403`,
basic, bearer and both api-key placements, a form login first and again on a lapse or a forgotten
session's `403`, an answer and pushes before a close routed and a terminal reply before a hang-up
rejecting every time, a silent
component caught by the keepalive, an oversize and a binary frame dropped, a pinned key, the head
bound and a redacted key), in the simulator's websocket face, and end to end
(`internal/node/run_websocket_test.go`: the subscription armed on connect, a change on the bar
landing within a second, a command settled from the answer to its id, a drop recovered and armed
again, a wrong password rejected after one upgrade across a restart and fixed in place, and a
replaced bar's key held beneath the certificate gate until `:retry` trusts it).

#### udp

Built (#1037, [ADR-0163](/architecture/decisions/#adr-0163-a-udp-endpoint-binds-its-own-socket-and-its-rung-is-a-request-answered)):
`udp` is the line protocol as datagrams, one line each, and stateless: there is no connection to
hold and no `session-state`. Each udp endpoint binds **its own socket** on the node, on its
driver's `listen-port` input (unset, a port the kernel picks), and every request it makes leaves
from that socket, so the component's replies and its pushes arrive on the one socket with no table
of sources to keep. The operator configures the component to send to the node's address and the
endpoint's port (and opens the node's firewall for it); a shared node port routed by source address
was rejected, since two endpoints behind one address (the IP-to-serial gateway shape) would be
indistinguishable. The listen port is derived into the endpoint's params as `host` and `port` are,
so editing it moves the connection fingerprint. A datagram from any source but the endpoint's
component is counted, self-logged once per tick (`foreign datagrams dropped`, with the count and the
last source), and dropped, never published.

An open udp port cannot be detected, so the **transport rung is the driver's named request
answered** (`ladder.transport.request`, which a udp driver must name): an answer reads responsive, a
silent component reads not responsive (`timeout`), and a port the host reports unreachable reads
`refused`. The socket is not connected (a connected socket filters other sources in the kernel, and
they must be counted), so the node turns on the socket's error queue (`IP_RECVERR`) to hear that
report; it names a cause and never gates. With no port to open, the responsive rung is the
endpoint's verdict too, and no `tcp-open` lands; the ping stays informational, so a component that
blocks ping but answers reads up, and one that answers ping but not the request reads down. Each
answered probe lands one `udp-response-time`, an error-shaped answer included, timed from the
request's first send, so a lost datagram's retry shows as time (a rung-specific name until #1063 folds probe timings into `rtt`); loss shows through `endpoint-responsive` and its reason. The reachability read
serves the rung as a `request` layer, timed by `udp-response-time` only while answered, and the
Endpoints panel's breakdown lists it beside the ping, and a ping-up endpoint whose request goes
unanswered says so in its why-line.

An exchange takes its reply by the request's declared shape (`request.reply`, which every udp
request must declare), with the held line connection's precedence, so a datagram that does not match
is never the answer and a push arriving mid-exchange still reaches its listener; a reply matching
the error shape fails it with the component's text. A component slower than a send's share answers every
send, so an exchange whose answer came back too soon after its last send to be that send's reply
(sooner than half the latency the socket learned from sends answered at once) leaves surplus
replies behind; until they arrive, or its timeout passes again, a repeat of its answer is absorbed,
never taken as the next ask's. A retry that loss caused leaves nothing, since a lost send draws no
reply, so a next ask's identical answer (a common ack) is never starved. A reply later than the
whole timeout is not told apart, so the endpoint's timeout should exceed the component's latency. A lost datagram is re-sent: `request.retries` (udp only, 0 to 5) defaults to 2 for
a poll and for the request rung, and the attempts share the endpoint's one timeout, so loss never
stretches a tick. A **command is sent once** unless its binding declares retries, since a command may
be relative (a volume step) and a lost reply must not send it twice; the seeded `newtron-nvp-udp`
declares them on `set-input`, which names the input. A reply the driver declares terminal (its
session block, which over udp may declare only terminal replies) gates the endpoint at the transport
rung, since nothing logs in over udp, and beneath the gate no request is sent under that fingerprint.
Listeners ride the socket as they ride a held session: their instantiation commands are sent once
each (a subscribe that adds a destination must not add one per retry) when the socket opens and
again whenever the request rung recovers (a component that rebooted forgot its subscriber), and
never beneath a gate. Text payloads only, unicast only. Proven over real sockets
(`internal/collection/udp_integration_test.go`, `internal/node/datagram_test.go`) and end to end against the
simulated panel's `nvp-udp` face dropping 30% of datagrams each way (`run_udp_test.go`: the rung up
through the loss and its timing, the poll through its retries, a command actuated, a push with no
poll, a stranger's datagram dropped, a silent face and a refused port down, no `tcp-open` and no
`session-state`).

#### snmp

Built (#821, [ADR-0821](/architecture/decisions/#adr-0821-snmps-rung-is-a-standard-get-answered-and-only-an-authorizationerror-reads-as-auth)): `snmp` is v2c and stateless.
Its transport rung is a **get of a standard OID answered**, `ladder.transport.request.get`, by
default `1.3.6.1.2.1.1.3.0` (sysUpTime.0), so `snmp-generic` gains its rung with no spec change and
a driver may name another (sysObjectID.0, say); a rung request that names a line, or an OID that
is not a numeric one, is refused at write. The get carries the endpoint's own community, the
secret its driver's `community` input references, which the worklist delivers to the reachability
probe as it does to the polls, so a rotated community moves the fingerprint like any secret. Any
response is an answer, a `noSuchObject` included, as any http status is: the rung reads responsive,
lands one `snmp-response-time` (a rung-specific name until #1063 folds probe timings into `rtt`),
and, since a v2c agent answers only a community it accepts, `endpoint-authenticated yes`. With no
port to open, the rung decides the endpoint's verdict, and no `tcp-open` lands; the ping stays
informational, so an agent that blocks ping but answers reads up.

**The v2c limit, stated plainly:** a wrong community is dropped silently by the protocol (RFC
3584), so it reads not responsive, `timed out`, retryable, and cannot be told apart from a stopped
agent. Only an agent that answers `authorizationError` (a community it knows and refuses) refuses
detectably: a terminal `auth` refusal at the session rung, `endpoint-authenticated no`, and since
v2c has no request without the community, nothing is sent under that fingerprint, neither the
probe's get nor a poll's (a restarted node adopts the gate too), until the fingerprint moves
(rotating the community secret brings it up within a tick). The get is snmp's only transport
probe, so beneath the gate the agent is unobserved: the rung reads down, rejected, and the verdict
with it, rather than freezing at the last answer. An snmp driver must declare its community, a
secret input named `community` of type `snmp-community`, which the poll and the rung both read. SNMP v3, whose report PDUs make auth detectable, is #1083. The read serves the rung
as a `request` layer timed by `snmp-response-time`, and the Endpoints panel names it the get, its
why-line naming the v2c limit instead of a control port. A v2c scalar get only: no walk, no tables,
no v1. Proven against a BER agent of its own (`snmp_integration_test.go`), the simulated faces
(strict, and answering a refused community with `authorizationError`), on the node over fakes, and
end to end (`run_snmp_test.go`: the get answered and timed, the poll beside it, a wrong community
silent and never rejected, the refused community gated and not sent again until the secret
rotated, a stopped agent down), with loss injected through the impairments under NET_ADMIN.

The other held transports are each their own
issue: #1036 (mqtt), #1039 (modbus/tcp), #1040 (bacnet/ip), #1041 (knxnet/ip); a
server-sent events stream is held over http and https ([above](#a-server-sent-events-stream)), and a
socket over websocket and wss ([above](#websocket-and-wss)). There is no serial transport: an RS-232 or RS-485 device is reached
through an IP-to-serial gateway, which is the `tcp` transport (or `tls` or `telnet`), so its driver is
a line protocol like any other ([ADR-0153](/architecture/decisions/#adr-0153-the-held-session-proof-is-the-line-protocol-over-tcp-other-held-transports-are-their-own-issues)).

:::design[The remaining transports and their per-task spec, tracked in #603 and #1036 (mqtt), #1039 (modbus/tcp), #1040 (bacnet/ip), #1041 (knxnet/ip)]

| endpoint type | shape | host/target | per-task params | samples |
|---|---|---|---|---|
| `raw-tcp` | held connection | `endpoint.address` (`host:port`) | `task.params.command` (sent verbatim + line ending), `timeout`, `extract` (comma-separated `name=re:<pattern>`); `endpoint.params.line_ending` (default `\r\n`), `read_delim` (default `\n`), `connect_timeout`, `read_timeout` | `rawtcp-reachable`, `rawtcp-response-time` (fixed) + one per `extract` entry |

`icmp`/`tcp` are inline probes (config on `endpoint.params`); `snmp` is built as its own stateless transport, configured by its driver's inputs ([snmp](#snmp)), and `http` and `https` as request transports configured by their driver's spec, a declared stream held as a session ([http and https](#http-and-https)); the rest, in the design model, are held connections: the connection lives on the endpoint, the task names what to read. The ship-with registry seeds the probe built-ins above, the endpoint verdicts, and `session-state` (`internal/seed/metric_types.yaml`, `internal/seed/property_types.yaml`; the [metrics](/guides/admin/metrics/) and [properties](/guides/admin/properties/) guides render each set from the seed); the wider per-transport set (`<proto>-reachable`/`<proto>-response-time` for the remaining text family; an http answer's status is a poll fault's reason, never a sample of its own; `telnet-response-time`, `udp-response-time` and `snmp-response-time` are seeded, and there is no `udp-open`, since an open udp port cannot be detected) is Design, and unregistered names would be reject-not-project dropped at ingest.

For `snmp`, each OID keeps its **native SNMP type**: numeric OIDs land as `metric`, string OIDs

(`fan-speed[intake]=<oid>`) strips into the sample's reserved `instance` label so the catalog

([the instance dimension](/architecture/properties/#the-instance-dimension-many-values-of-one-name-on-one-owner));

Extraction is typed by value: a numeric leaf or numeric capture -> `metric`, a string or bool ->

### Listeners over a held session

Built (#817): a listener declared in a driver's spec derives a standing listen task, and the
node runs every listen task on an endpoint over that endpoint's one held session:

- **Instantiation commands** (`arm`): the subscribe conversation, sent in order on every connection
  before the session reads `up`, so on establish and again on each recover. They are **plumbing**,
  not command rows (the #603 ruling): each is a node self-log (`session armed`, with the device's
  reply). The ack is the first line of any kind, one a listener claims included (the listener has
  it too), since a device may acknowledge a subscribe with the push itself; an arm with no ack
  within the timeout is logged at warn (`session armed, unacknowledged`) and does not fail the
  attempt, while the connection dying during the arm does.
- **Match** (`prefix` or `regex`): classifies an inbound line. Listeners are offered a line in
  function-name order and the first whose rule picks it claims it. The unit is a **message**
  (#1038): a line on a line session, an event on an http stream, a text frame on a websocket
  (#1034), which a match may also claim by its event name (`event`, a stream's only) or by a JSON
  field of its data (`field: { path, equals | regex }`)
  ([a server-sent events stream](#a-server-sent-events-stream)). An arm is sent as one line (one
  frame), so it carries no line break.
- **Extraction**: the claimed line runs through the same emit shape a poll's answer does (locate,
  transform, type by the baked lane), and lands at once under the listen task as a sample, an event
  or a log line ([an emit lands on any lane](#an-emit-lands-on-any-lane)): the component owns it,
  the endpoint is its instance, and no poll schedule is involved. A claimed line whose emits do not
  extract is a `collection-failed`, landed once per change.

Every inbound line on a held session is routed by one precedence
([ADR-0151](/architecture/decisions/#adr-0151-a-held-line-session-routes-every-inbound-line-listeners-first-answers-by-reply-shape)):

1. A line a listener claims is the listener's. It is never an exchange's answer, unless the
   exchange declared a reply shape the line matches, in which case both have it.
2. An exchange in flight (a poll, a command) takes the first line its declared reply shape
   (`request.reply`, a `prefix`, a `regex`, a JSON `field`, or over a websocket the `correlate`d
   id, [below](#websocket-and-wss)) matches, or, when it declares none, the first line no
   listener claims. When the shape also declares an `error` shape, an unclaimed line matching it
   answers the exchange as a **refusal** carrying the device's text. A line that began before the
   request was written is never its answer.
3. Anything left is **unclaimed**: counted, and once per tick the node logs the count and the last
   such line; a spec declaring `unmatched: collection-failed` also lands one `collection-failed`
   per tick naming them, and one declaring `unmatched: log` lands each as a log line on the
   endpoint's component, the whole message as raw arrival (#1145); the default is `discard`.

A request with a reply shape closes the window #816 left open (a stray line arriving just before
the device reads the request); without one, a line no listener claims in that instant can still be
taken as the answer, so a driver whose protocol mixes unsolicited lines with answers declares its
replies. A shape's `regex` is Go RE2 with **substring** semantics, so anchor it (`^INPUT \S+$`), or it
also matches a push containing it. Because shape routing cannot hand a late answer to the next ask,
a shaped request that gets no answer in time fails only that exchange: the connection is kept and
the session is not charged (an unshaped one still recycles the connection, ADR-0150). A poll whose
answer is a refusal lands a `collection-failed` naming the device's text. Commands ride the held
session too: a delivery names its endpoint, and a node holding a session there actuates over it
(falling back to a throwaway connection only when none is held). A command the device answers
settles from that answer as it did over a throwaway connection; one it refuses reports the
device's text as both its execution error and its reply, so it fails at once with the reason on
the row rather than timing out.

### Listeners and their config

### Push ingress: webhooks on the server

A **push endpoint** is one a sender pushes to rather than one a node dials
([ADR-1024](/architecture/decisions/#adr-1024-omniglass-receives-webhooks-on-the-server-and-a-webhook-token-is-a-sealed-secret)).
`webhook` is the first push transport in the registry: nothing is dialed, so its endpoint has no
reachability task and no ladder (a ladder declared on one refuses at write), and it reads **last
heard**, stamped by every post that lands, in place of a verdict. It is never shown down for
silence. A webhook endpoint is hosted by the server (it takes no node) and names one component.

Every message pushed at omniglass runs one pipeline, the **listener primitive**, whichever host
runs it: **bound** (token buckets per source, per endpoint and for the listener, a cap on posts in
flight, a 1 MiB body whose read stops at the cap, a read deadline), **authenticate**, **attribute**,
**route** (listeners first), **extract**, **land**. The server hosts it for webhooks; a node hosts it
for the push transports of #1148, #1149 and #1150.

A webhook sender's **source**, the key its bucket, its refusals and the inbox count it by, is the
client address the server resolves for every request: the connection's peer, or, only when that
peer is in `OMNIGLASS_TRUSTED_PROXIES` (default the loopback and private ranges, where the chart's
ingress sits), the rightmost `X-Forwarded-For` hop outside it. An IPv6 sender is its /64. The
address a session or token is stamped with is the same answer, so the two never disagree about who
posted ([ADR-1185](/architecture/decisions/#adr-1185-the-client-address-believes-a-forwarded-header-only-from-a-configured-proxy)).

**The URL and its token.** Creating a webhook endpoint mints its token (128 random bits) as the
`webhook-token` secret on the endpoint's component: sealed, revealed and copied only under
`secret:reveal`, audited, deleted with the endpoint, and rotated by
`POST /endpoints/{endpoint}:rotateToken`, after which the old token resolves to nothing. A sender
posts to `/api/v1/webhooks/<token>`. The token names one endpoint, and so one component: nothing in
the payload selects further.

**The scheme.** A webhook driver declares how a post is authenticated in its session block, and
never by default:

| `session.scheme` | credential | what is checked |
|---|---|---|
| `hmac` | an `hmac-key` secret input | `webhook.signature`: the header the signature rides, `algorithm` (`sha256`, or `sha1`), `encoding` (`hex`, or `base64`), a `prefix` the sender puts before it, and a `timestamp` header the sender signs, joined to the body by a `separator` (`.`) |
| `token` | a `bearer-token` secret input | `webhook.token`: the header the shared token rides, behind an optional `prefix` |
| `basic` | a `basic-auth` secret input | the request's basic login |
| `none` | none | nothing: the endpoint reads **unsigned**, anyone holding its URL can post, and there is no replay protection |

hmac over a signed timestamp is the scheme to reach for first. A signed timestamp more than five
minutes from arrival refuses, and a declared delivery id (`webhook.delivery`, a header) is
remembered per endpoint for that window, so a sender's redelivery lands once. Every comparison of a
secret runs in constant time, and the check fails closed: a scheme whose secret no longer resolves,
or holds an empty field, refuses every post. A bare webhook endpoint (no driver) is `none`.

**The body.** The driver declares its format (`webhook.format`: `json`, `xml`, `form` or `text`),
and the listeners claim a post and read it through the one extraction primitive: a json body by
`jsonpath`, a form body by `key`, an xml body by `xpath`, any body by a regex. A listener's match
may also read a header the sender sets (`match.header`, by name, `equals` or `regex`), never a
credential's. What no listener claims lands as a log line, and a claimed post lands its raw log
line beside its emits unless the listener declares `log: false`. A bare webhook endpoint lands
every post as a log line.

**The answers.** Senders retry on anything but 2xx, so: `202` only once the post is published;
`401` for a refused scheme, saying nothing of which part failed; `404` for an unknown, rotated or
malformed token, byte for byte the same; `409` with `Retry-After` for a redelivery whose first copy
is still landing; `413` past 1 MiB; `429` with `Retry-After` past a limit;
`5xx` only for omniglass's own fault. A `GET` verifying the URL answers the query parameter the
driver declares as its challenge (`webhook.challenge`), echoed as text, or `204`.

**Writers, refusals and strangers.** A post is published on the push lane with its endpoint's
component as owner, whose writer admits only `collected` keys, so a leaked token can write only
collected keys on one component. A refused post is counted, never gated: it never reads rejected.
Refusals are tallied per endpoint, source and reason, and land on the endpoint's read once per tick
(the count, the latest time, source and reason, never the credential). A post to a token no
endpoint holds lands its sender in the **unclaimed-source inbox** (`GET /unclaimed-sources`, under
`node:read`): one row per source address, with a count, first and last heard, and the last message
cut to 512 bytes, bounded at 256 sources per listener and aged out after seven days. The token a
stranger tried is never kept. Claiming a source is creating its endpoint, and its row is let go once
its posts land.

:::design[Node-hosted push: shared tcp and udp ports, syslog and SNMP traps, tracked in #1148, #1149 and #1150]

A node hosts the listener primitive for the push transports that should not cross a WAN: a shared
udp or tcp port routed by source address, syslog over udp, tcp and tls, and SNMP traps and informs.
The source address authorizes the endpoints placed on the node that declare it, and a declared
payload identity only selects within that set. Node-hosted webhooks for LAN senders, and
server-hosted syslog where the source address survives, are later.

:::

:::design[The step DAG and extractors, tracked in #827]

## Steps: the DAG

A step is a typed **operation**: a `kind` that runs on a referenced `endpoint` and, for a read,
produces samples through a typed extractor.

```yaml
steps:
  - id: poll
    endpoint: snmp
    kind: snmp-get                  # gated by the endpoint type; schema-validated
    when: "$dp.power-state == 'on'" # optional guard = explicit branch
    samples:
      oid:
        - { key: cpu-utilization, oid: 1.3.6.1.4.1.55540.2.1.0, value: "raw / 100.0" }
```

- **Dependencies are data references, not array order**: a step reads `$steps.<id>.*` (ephemeral
  scratch, never emitted) or `$dp.<key>` (a real measurement, readable for branching); the
  reference set *is* the DAG, array order cosmetic, so an editor can round-trip the graph.
- **`when`**: an expression guard, the explicit branch; false skips the step and its dependents.
- **`forEach`**: step-level fan-out (element bound as `$steps.<id>.item`), downstream steps running
  per element; distinct from an extractor's `each`, which fans one response's array into many
  samples in one step.
- **`kind` is endpoint-gated and registry-driven** (`snmp-get`, `snmp-walk`, `http-request`,
  `ssh-send`, `ssh-subscribe`, the endpoint-agnostic `extract` and `blend`), each kind's param
  schema in the registry.

In-scope namespaces: `$var:<name>` (config and secrets via the [cascade](/architecture/cascade/)),
`$dp.<key>` (samples), `$steps.<id>.*` (scratch), `$event` (a `listen` function's inbound payload),
and the extractor-local `raw`, `groups`, `node`, `item`.

### Extractors: locate, then optionally transform

An extractor locates a raw value with its protocol-specific field, then optionally transforms it
with one [Expr](/architecture/expressions/) expression in `value` (default identity). **One
interpolation convention**: `${...}` is interpolated, a bare string is literal; `value` is always an
Expr expression by definition, so it needs no wrapper.

```yaml
samples:
  oid:
    - { key: device-uptime, oid: 1.3.6.1.2.1.1.3.0, value: "raw / 100.0" }  # centiseconds to seconds
  regex:
    - { key: fan-speed, match: 'fan \(rpm\)\s*:\s*(\d+)', value: "int(groups[1])" }
  jsonpath:
    - { key: channel-gain, each: $.channels[*], value: "node.gain",
        labels: { channel: ${node.index}, name: ${node.name}, role: "main-display" } }
```

The extractor names a `key`; what it *means* lives on
[the lane's catalog](/architecture/properties/#the-two-catalogs) at some
[scope](/architecture/properties/#key-scope-template-org-official): a template declares its own keys
at **template** scope (no registry friction) or references an **org** / **official** key.
Compile-time validation resolves every key to a reachable scope; an unresolved key is
reject-not-project at ingest, so a template never silently collects a measurement no scope knows.
:::

:::design[Template inputs, tracked in #827]

## Inputs: the template's typed parameters

A template takes typed `inputs`, never a hardcoded `$var:`: it needs a `basic-auth`, not
specifically `$var:crestron-ssh`. At `:apply` each input binds to a literal or a
[variable](/architecture/variables/) reference (`$var:<name>`), with an optional shipped default;
required inputs are the apply gate, and the UI renders the form.

```yaml
inputs:
  - group: connectivity
    fields:
      - { key: ip,   type: ipv4,           required: true, label: "IPv4 address" }
  - group: auth
    fields:
      - { key: snmp, type: snmp-community, required: true, label: "SNMP community" }
      - { key: ssh,  type: basic-auth,     default: $var:crestron-ssh, label: "SSH login" }
```

The body references `${input.snmp}` / `${input.ssh}`; bindings resolve at apply, overridable per
component, so `$var:` lives only at the binding layer and the template stays reusable with any value
of the right shape. Each input `type` is a `variable_type`, so per-field secrecy comes from the
shape.
:::

## Execution: parse at the edge

A function runs the parse at the **edge**, not server-side:

- **Steps parse, extract, and normalize on the node**, **publishing** resolved samples to the JetStream [samples](/architecture/properties/) stream, not the typed tables; the [persistence consumer](/architecture/properties/) batch-writes them async, each batch landed once by its receipt ([ADR-0311](/architecture/decisions/#adr-0311-a-telemetry-batch-lands-once-in-one-transaction-under-its-receipt)), while the [rule engine](/architecture/alarms-actions/) consumes the same stream live. The wire is per-lane, so the lane rides the message shape itself, routing `metric` versus `property`.
- **Raw payloads are not stored**: a dev raw-mode taps the wire live, a failed parse emits a `collection.failed` event carrying the raw, and there is no telemetry table.
- **Owner attribution:** a single-owner function stamps identity at the edge; a many-device function publishes for multiple owners, resolved server-side from identity labels (below).
- **Placement-scoped writes.** A node publishes only the owners in its **placement visible_set** (the owners of its assigned tasks), expressed as **NATS subject permissions** (the `node` gateway mode, [identity and access](/architecture/identity-access/)). An owner label outside the set is never an authoritative write, only an **orphan / discovery candidate** for the `discovery_rule` stream, so a compromised node cannot manufacture writes for owners it was never placed on; the perspectives / `disagree` model backstops a legitimately-placed node reporting bad values.
- **No separately authored transform rule**: routing is the template's fan-out, cross-entity rollups are [calc](/architecture/calculations/) samples on system and location templates; the server-side remainder is shared-endpoint owner-binding and untemplated raw ingress.

### Raw sampling: an opt-in re-parsable window

An opt-in **`raw_sample`** policy keeps a bounded window of raw frames so a corrected extractor can re-derive its samples over that window, without reintroducing a telemetry table. It is **cascade-resolved** (settable on an endpoint, task, or template) to **`off`** (default, no raw retained), **`all`** (every frame buffered), or **`1-in-N`** (sampled, bounding a high-cadence source). Kept frames carry the **immutable function version** that parsed them, so the window re-parses against that exact version and corrects retroactively; outside it, a wrong-but-conforming parse is **forward-fixable only**, the raw being gone. A short-TTL holding pen, range-partitioned and cold-tierable ([storage](/architecture/storage/)), not a parallel history of record.

### On demand: validate, preview, and run a poll now

Three routes let an author (or an agent) build a driver against the real component without waiting
on a schedule ([ADR-1163](/architecture/decisions/#adr-1163-a-poll-runs-once-on-demand-through-its-node-as-a-preview-that-stores-nothing-or-a-run-now-that-lands)):

- **Validate** (`POST /drivers:validate`, `driver:read`) checks a spec by the rules a save applies
  and writes nothing. Where a save names a spec's first fault, validate names every fault it can pin
  down, each on the function it is in (a poll, a listener, a command binding), the first always the
  one a save would name.
- **Preview** (`POST /drivers:preview`, `driver:preview`) runs a spec's polls **once** through the
  node named, against the target its inputs name, and answers with what each read: its samples,
  each emit that did not locate, and an excerpt of the raw answer, before any emit read it, masked
  of every secret the preview used. **Nothing is stored.** The spec is a stored driver or an unsaved
  one, refused with its findings when it does not validate. A preview runs a poll that is its own
  request (http, https, an snmp get, a tcp line on a throwaway connection); a poll that rides a held
  session or a bound udp socket needs an endpoint, so it is attached and run now instead. A secret
  input must be one the caller may **reveal**, since the preview hands it to the target named, and
  each secret used is audited.
- **Run now** (`POST /endpoints/{endpoint}/polls/{poll}:run`, `endpoint:run`) runs one of an
  attached endpoint's polls on the node that holds it, outside its schedule, and **lands** what it
  reads as a scheduled run does. A gated endpoint refuses the run with the gate's reason and nothing
  is sent.

Preview and run now share one primitive, the **on-demand node run** ([nodes](/architecture/nodes/)):
the server asks the node and waits for its one answer. A poll's request is whatever its spec says (a
POST, any line), so a preview reaches the component as a command does; its MCP tool says so
(destructive, open-world). Both hold a request open while a node works, so they are bounded by a
stricter class than the API's own (#962 is the API-wide limit): a few runs in flight across the
server, fewer per caller, a run past either refused (429) before anything is asked. Each asking is
audited: a preview on the node (and on each secret it used), a run now on the endpoint.

## Shared-API collection: one component, many owners

Some sources describe **many entities at once**: a SaaS / UCC platform (Zoom, Teams), a controller fronting many devices, a building gateway. The API is **one component** (one endpoint, one credential) whose data **fans out** to the entities it describes, not one component per described entity.

- Its function pulls the batch in one call, **labeling each emitted sample with the external identity** it belongs to (a Zoom Room ID).
- The function is the conduit, not the owner: ownership resolves **server-side** against a declared **identity config** (`zoom-room-id` on the target), the same shared-ingress owner-binding used for webhooks and traps.
- **The owner can be a system.** SaaS state that is telemetry *of* a room maps to **system-owned samples**; a virtual component is for the genuine *member* case (its own topology node, a `health_role`, a lifecycle). **Member -> component, telemetry -> system.**
- **Unmatched identities are orphans**, discovery candidates (below).

**Best practice**: map SaaS / cloud telemetry to system-owned samples wired into system health via a system-scoped `event_rule`; the vendor's own status is an input to that judgment, not the verdict, so corroborate a reported "offline" before downing the room ([health](/architecture/health/)).

### Identity binding: the value-to-owner index

Binding an externally-tagged row to an Omniglass owner is a lookup against the **value-to-owner index**: an **identity arc** on identity config, a `(property_type, value) -> owner` mapping where `property_type` is the **match key** (`zoom-room-id`) and `value` the emitted identity. The index resolves **in the cascade scope** the identity config is set at, so an identity declared at a system or location binds every member below it. A **declared identity config value wins**, falling back to the **observed identity sample** sharing the key; the [samples](/architecture/properties/) ownership-resolution machinery reads this same index.

### discovery_rule: orphans become candidates

A `discovery_rule` turns the orphan stream, every emitted identity the index does not resolve (an unmatched shared-API `(property_type, value)`, plus a node's out-of-placement labels), into proposed entities: the onboarding win, no hand-mapping.

- **Creates** candidate components or owners, each seeded with the identity that surfaced it (it becomes the new entity's identity arc), so the next batch resolves through the index.
- **Idempotent on re-discovery**: keyed on the `(property_type, value)` already bound, so a steady stream of the same orphan resolves to one candidate.
- **Scope and standing**: a cascade **scope** and an `official` / private standing like the other rule families (`event_rule`, calc).

## Drivers: the declarative menu

A **driver** turns a class of device API into a normalized menu of signals and actions. Its body
is the **spec**: a versioned declarative document (data, not code) interpreted by one generic
engine, stored as `jsonb` on the driver row and validated against the catalogs at **every write**
(create, update, and the boot seed), so a spec that cannot be interpreted refuses at authoring
time, never at collection time
([ADR-0135](/architecture/decisions/#adr-0135-a-drivers-spec-is-data-one-engine-interprets-it)). A
spec declares:

- **The transport it rides** (one, from the code registry): `snmp-generic` rides `snmp`,
  `newtron-nvp` rides `tcp`, `kestrel-api` rides `https`.
- **Inputs** an attachment must supply: typed (`string`, `number`, `secret`), required or
  defaulted. A `secret` input carries a `secret_type` and is supplied as a **reference** (the name
  of a secret row of that shape), never a value; the reference is checked at attach.
- **Three function families**, every emit a metric, a property or an event referencing its lane
  catalog **by name**, or a log line, which names none ([an emit lands on any lane](#an-emit-lands-on-any-lane)):
  - **Poll functions**: a `schedule`, a transport-shaped `request` (scalar OIDs for an SNMP get, a
    line for a line protocol, a method, path, query, headers, body and response format for http,
    [#902](#http-and-https)), and per-emit **extraction**, one primitive with a selector per format
    (`oid`, `regex` capture, `jsonpath`, `key`, `xpath`), with an optional declared **transform**
    (`cast`, `scale`, enum `map`; the expression engine is deliberately not a dependency). An emit
    lands on any of the four lanes ([below](#an-emit-lands-on-any-lane)).
  - **Listeners**: the `arm` conversation sent on session establish and re-sent on every recover
    (session **plumbing**, not recorded command rows), a `match` rule that claims an unsolicited
    inbound payload, and the same extraction shape. A listener rides a held line session or a udp
    socket; on any other transport it is refused at write, since nothing would run it (#1115).
  - **Command bindings**: how a `command_type` actuates over this protocol.

**Attach is the authoring move**: creating an endpoint with a `driver` reference (instead of a
`transport`) derives everything from the spec. The transport and params come from the spec (the
`host` and `port` inputs join into the probed `target`), required inputs must be supplied and
defaults bake, and the spec's functions derive the endpoint's tasks in the same transaction: a
poll task per poll function, a standing listen task per listener, each task's spec carrying the
function **whole with its emit lanes resolved at attach** (the compile step: the node never
looks up a catalog at runtime). The tasks **re-derive when the driver's spec changes** (#823): a
driver update over the API, and the boot seed's upsert of an official spec, rewrite every attached
endpoint's driver tasks in the same transaction, writing the ones the spec now derives and retiring
the ones it no longer does. Task ids are content hashes, so an unchanged function keeps its row and
a re-seed that changes nothing writes nothing at all (not the driver row, not a task); an endpoint
whose tasks changed has its config generation moved, and its node runs the new spec from its next
pull. An attach reads the driver row under a share lock, so one that races an update waits for it
and derives the committed spec, and a re-derive skips an endpoint a concurrent delete removes.
One gap is accepted: between the re-derive and the node's next pull (one tick), samples the node
still publishes under a retired task's id are dropped at ingest as orphans, the same confinement
that drops any unknown task id; the next tick publishes under the new one. Refusals name the fault as a 422: a missing required input, an
input the spec does not declare, an ambiguous secret name. A secret input is resolved under the
**caller's own secret read scope and admin tier**, so an attach can only bind a credential the
operator could themselves read: an out-of-scope or admin-sensitive secret refuses
indistinguishably from an absent one, no name or type oracle. The worklist delivery re-confines
to a secret that cascades onto the endpoint's component. A driver-attached endpoint's address is
derived from its inputs and edits in place through them (#1061): `PATCH /endpoints/{endpoint}` takes
`inputs` (the host, the port, an attached secret's reference), validated against the driver's
declared inputs (a value it refuses is a 400 naming the field), every attached secret re-resolved
under the editor's own secret scope (so an edit cannot send a credential its editor could not use to
a new address), audited, and the tasks re-derived in the same transaction through #823's one
derivation; a raw `params.target` on it, or a transport its driver does not speak, refuses. A
driver row without a spec is a **stub** that cannot be attached. The console's endpoint
create offers both moves (a bare probe endpoint, or attach a driver and fill its inputs), and the
Drivers page renders each spec as the menu it is.

**The interpreter runs the poll functions** (#814) **on their declared schedule** (#822): a poll's
`schedule.every` is honored at heartbeat granularity, the node running it on the first tick at or
after it is due (a new task at once, and a run whose fetch failed retried on a backoff from the
heartbeat, doubling, capped at the interval), while reachability probes run every tick and a listener's
pushes ride the held session as they arrive, never gated ([ADR-0152](/architecture/decisions/#adr-0152-a-driver-poll-runs-on-its-declared-schedule-at-heartbeat-granularity)).
The node tells a baked driver task from a probe task by its spec, fetches over the transport (an http request rides the node's http fetcher with the endpoint's credential, [above](#http-and-https); the v2c scalar GET rides `gosnmp`, proven
against a from-the-spec BER agent; a line poll runs one stateless ask over a throwaway
connection, or borrows the endpoint's [held session](#sessions) when the node holds one), and interprets the payload against the baked
function: locate each emit by its one extractor, apply the declared transform (enum map, then
scale, then cast), and type it by the baked lane. A metric-lane value that is not numeric is a
fault, never a wrong-lane sample; a missing emit faults by name while the rest of the payload
still lands; a failed fetch lands nothing; every fault is a `collection-failed` event naming the
task. Secret inputs reach the node **unsealed in the worklist reply**: the server resolves each
reference once per pull (the per-node NATS grant is the isolation boundary, and the attach that
bound the reference is the audited operator action), and a reference that no longer resolves is
delivered as absence, which the node reports as the missing credential. Sessions and the
listeners over them are built ([above](#sessions)). The ship-with set:

### An emit lands on any lane

Built (#1145, [ADR-1145](/architecture/decisions/#adr-1145-a-driver-emit-lands-on-any-of-the-four-lanes-and-a-log-lines-severity-is-rfc-5424s)):
a poll's or a listener's emit maps what it reads onto any of the four collected lanes. A **metric**
or a **property** names its key and locates its value with one extract. An **event** names its
event type (the emit's name resolves against the metric, property and event catalogs, one
namespace) and carries a `message`, a constant or an extract, by default the whole claimed message
or answer, and `attributes`, each a constant or an extract (a cast to int or float renders a JSON
number), rendered into its payload and held at write to the type's `payload_schema` where it
closes or requires fields; it lands as a `caught` event, its endpoint the instance. A **log line**
names no key: it declares `log`, with its `severity` and `facility` (each a constant or an
extract) and its `source` (by default the endpoint's transport), beside a `message` and
`attributes`. A log line is raw arrival ([ADR-0066](/architecture/decisions/#adr-0066-logs-are-a-raw-ingest-lane-not-events)),
so it always lands: a message extract that misses falls back to the whole text, and a severity,
facility or attribute that misses is left out, each miss a `collection-failed` naming it; an event
is an assertion, so an attribute that misses lands nothing. A reserved event type
(`collection-failed`, `command-issued`) is refused at the spec's write naming its writer, as a
reserved metric is.

```yaml
listeners:
  - name: events
    arm: ["SUBSCRIBE INPUT"]
    match: { prefix: "EVT INPUT " }
    emits:
      - { name: video-input, extract: { regex: "^EVT INPUT (\\S+)$" } }   # a property
      - name: input-changed                                                # an event
        message: { value: "Video input changed" }
        attributes:
          input: { extract: { regex: "^EVT INPUT (\\S+)$" } }
  - name: logs
    arm: ["SUBSCRIBE LOG"]
    match: { prefix: "LOG " }
    emits:
      - log:                                                               # a log line
          severity: { extract: { regex: "^LOG (\\S+)" } }
          facility: { value: panel }
        message: { extract: { regex: "^LOG (?:\\S+\\s+)?(.+)$" } }
        ts: { extract: { regex: "at (\\S+)$" }, layout: rfc3339 }
```

Any emit may read its **time** out of the payload (`ts`: an extract and a `layout`, one of
`rfc3339`, `rfc3164`, whose missing year is the one nearest arrival, read in the declared `zone`,
`unix`, `unix-ms`, or `go:` a Go reference layout carrying at least a month and a day); without
one, the time it arrived at the node. A time more than five minutes ahead of arrival lands at
arrival instead, a log line keeping the claim as its `ts_claimed` attribute and the node saying so
in its self-log; a time that does not parse, or no timestamp could hold (outside the years 1 to
9999, or not a number), lands the record at arrival and faults. A value cast to a number that is
not finite (`NaN`, `Inf`) is a fault naming the field, never a payload that cannot be written. On a plain poll an event or a log line fires only
when its content changes from what that task last landed (remembered in the node's memory, so a
restart may fire one again), so a status page's last error lands once per change.

The node carries a task's log lines in a field of their own (`task_logs`), beside its self-logs, and
ingest writes them to `log_line` on the task's component, the endpoint that collected them as the
line's instance, owner-bound from the task as every sample is: a node lands a line only for a
component its own task collects for, and never as its own. Every writer's line is held at the
Storage Gateway to one severity vocabulary, RFC 5424's eight levels (`emergency`, `alert`,
`critical`, `error`, `warning`, `notice`, `info`, `debug`) through one alias table (`warn` reads
`warning`, `err` reads `error`), a word outside it kept as the `severity_raw` attribute with no
severity, to 16 KiB each for the message and the attributes, cut and marked past it, and to no
NUL byte (which Postgres refuses, and which telnet's CR NUL makes ordinary), each replaced. The
component's and the system's log reads window and order on a line's arrival, so a component whose
clock reset still reads in the last day, its own time shown beside when it arrived; the Logs panel
filters by a severity threshold and a source. Proven end to end against the
simulator: the Newtron panel's input push lands as the `video-input` property and an
`input-changed` event carrying the input, its diagnostics line as a `warning` log line, and a scene
change no listener claims as a raw log line, none of them in the node's self-logs; the Kestrel
bar's feed reports a call starting and ending as named events, which `kestrel-api` lands as
`call-started` and `call-ended` carrying the call's id.
