The chart at `deploy/chart/` is the deploy primitive: one chart serves both
disposable per-PR previews and production. It runs the
[container image](/guides/container-image/); the live
[per-PR preview environments](/guides/pr-previews/) are its first consumer, and
production reuses it unchanged by flipping two values.

## Two modes

| Mode | `postgres.enabled` | `bootstrap.enabled` | Database |
|------|--------------------|---------------------|----------|
| Preview (default) | `true` | `true` | bundled, ephemeral (emptyDir) |
| Production | `false` | `false` | external, via `externalDsn` |

The bundled Postgres is deliberately ephemeral: its data is an `emptyDir` and
does not survive a pod restart, which is what you want for a throwaway preview.
Production points at a real, managed Postgres.

## Install

Preview (bundled Postgres, an auto-created owner):

```bash
helm install og-pr-42 deploy/chart -n og-pr-42 --create-namespace \
  --set image.tag=sha-<full-sha>
```

Production (BYO Postgres, no auto-owner):

```bash
helm install omniglass deploy/chart -n omniglass --create-namespace \
  --set postgres.enabled=false \
  --set externalDsn='postgres://user:pass@db:5432/omniglass?sslmode=require' \
  --set bootstrap.enabled=false \
  --set image.tag=<release>
```

## How it boots

The server Deployment gates startup with init containers rather than Helm
pre-install hooks, because a bundled Postgres in the same release is not up
during the pre-install phase:

1. `wait-for-db` (only when `postgres.enabled`) blocks until Postgres answers.
2. `migrate` applies the schema (idempotent: dbmate runs each migration once).
   It refuses a database a newer release migrated, naming the database's newest
   migration and the newest the image knows, so the pod fails here rather than
   serving on a schema it does not know.
3. `bootstrap` (only when `bootstrap.enabled`) creates the first owner and mints
   its bearer token, printed once to this container's logs. Idempotent: a
   restart mints no second token.

Migrations only move forward: a `helm rollback` to an image older than the
newest migration the schema carries stops at `migrate`. Roll back the image only
together with the database backup taken before the upgrade, or roll forward.

Both `migrate` and `bootstrap` are safe to re-run on every rollout. At
`server.replicas` > 1 each replica's `migrate` runs, but they take turns on a
Postgres advisory lock: the first applies the pending migrations and the others
wait for it, then find nothing left to do.

## Durable state

A chart deployment keeps two things across a pod restart, a `helm upgrade` and a `helm uninstall`
followed by a `helm install` of the same release into the same namespace: its encryption key and its
data volume. Nothing a user can observe changes across any of them.

### The encryption key

Every secret Omniglass stores in Postgres is sealed under one encryption key. The server reads it
from `OMNIGLASS_ENCRYPTION_KEY`, which the chart fills from a Kubernetes Secret (key
`encryption-key`), so the key never lives in the pod:

- **Supplied.** Set `encryptionKey.existingSecret` to the name of a Secret you manage that holds
  `encryption-key` (base64 of 32 random bytes, e.g. `head -c 32 /dev/urandom | base64`). A supplied
  Secret always wins; the chart generates nothing.
- **Generated** (the default, `encryptionKey.generate=true`). The chart creates
  `<release>-encryption-key` on the first install and reads its live value back on every upgrade, so
  the key never changes. The Secret carries `helm.sh/resource-policy: keep`, so `helm uninstall`
  leaves it behind and a reinstall of the same release adopts it.

With no `existingSecret` and `generate=false` the chart refuses to render, rather than boot a server
with no key.

:::caution[Back up the key]
Lose the key and every stored secret is unreadable, by anyone: there is no recovery. Read it out
after the first install and keep it outside the cluster:

```bash
kubectl -n omniglass get secret omniglass-encryption-key \
  -o jsonpath='{.data.encryption-key}' | base64 -d
```

The output is the value of `OMNIGLASS_ENCRYPTION_KEY`. To restore, create a Secret holding it under
`encryption-key` and install with `encryptionKey.existingSecret` naming it. The chart's `NOTES.txt`
prints this command after every install and upgrade.
:::

The generated key relies on Helm reading the live Secret at render time (`lookup`). A renderer that
runs `helm template` without a cluster, as a GitOps controller such as Argo CD does, cannot, and
renders a fresh key each time; there, supply the key with `encryptionKey.existingSecret`.

### The data volume

The server's data directory is `/var/lib/omniglass` (`OMNIGLASS_DATA_DIR`), and the embedded
JetStream store sits under it at `/var/lib/omniglass/nats` (`OMNIGLASS_NATS_STORE_DIR`), the same
layout as the [lab](/guides/lab/). With `persistence.enabled` (the default) the chart mounts a
`ReadWriteOnce` PersistentVolumeClaim there, `<release>-data`, also marked
`helm.sh/resource-policy: keep`. The Deployment uses the `Recreate` strategy: one server owns one
bus and one volume, so the old pod stops before the new one starts.

The guarantee this buys: **a batch the stream acknowledged before a restart lands after it.** A node
drops a batch from its spool once the `OG_TELEMETRY` stream acknowledges it
([messaging](/architecture/messaging/#delivery-a-batch-lands-once)); the stream's store is on the
volume, so a batch acknowledged and not yet written to Postgres by `og-telemetry-worker` is still
there when the server comes back, and lands then.

`persistence.enabled=false` swaps the claim for an `emptyDir`, which a pod restart loses, along with
any telemetry the bus held. That suits a disposable preview and nothing else.

### What an uninstall keeps

`helm uninstall` removes the release and keeps exactly two resources, which it names in its output:
the generated key Secret and the data claim. Reinstalling the same release name into the same
namespace adopts both. To remove an instance for good, delete them by hand, after backing up the key
if the database is staying:

```bash
kubectl -n omniglass delete secret omniglass-encryption-key
kubectl -n omniglass delete pvc omniglass-data
```

The database is separate: with `postgres.enabled=false` it is yours and the chart never touches it;
the bundled preview Postgres is an `emptyDir` and goes with the release.

## Values

| Key | Default | Purpose |
|-----|---------|---------|
| `image.repository` | `ghcr.io/hyperscaleav/omniglass` | image to run |
| `image.tag` | `latest` | pin to `sha-<full-sha>` for an exact, immutable build |
| `image.pullPolicy` | `IfNotPresent` | |
| `server.replicas` | `1` | server pod count |
| `server.resources` | small requests/limits | |
| `service.port` | `8080` | ClusterIP service port |
| `ingress.enabled` | `false` | create an Ingress (on for per-PR previews) |
| `ingress.className` | `traefik` | ingress controller class |
| `ingress.host` | empty | required when `ingress.enabled`; the public host |
| `bootstrap.enabled` | `true` | auto-create an owner (previews) |
| `bootstrap.username` | `preview` | owner username |
| `bootstrap.email` / `bootstrap.label` | empty / `Preview Owner` | optional owner fields |
| `postgres.enabled` | `true` | bundle an ephemeral Postgres |
| `postgres.image` / `user` / `password` / `database` | `postgres:18` / `omniglass` x3 | bundled Postgres settings |
| `postgres.resources` | small requests/limits | bound the throwaway DB |
| `externalDsn` | empty | required when `postgres.enabled` is false |
| `encryptionKey.existingSecret` | empty | name of a Secret holding the key under `encryption-key`; always wins |
| `encryptionKey.generate` | `true` | generate and keep `<release>-encryption-key` when no `existingSecret` is set |
| `persistence.enabled` | `true` | put the data directory on a kept PersistentVolumeClaim; `false` uses an `emptyDir` |
| `persistence.size` | `1Gi` | the claim's requested size |
| `persistence.storageClass` | empty | the claim's storage class; empty uses the cluster default |
| `server.secureCookies` | `true` | marks session cookies `Secure` (https-only); set `false` only for a plaintext-http deployment |
| `nameOverride` | empty | override the chart name in resource names |
| `fullnameOverride` | empty | override resource names outright; default release-named resources keep preview service DNS predictable (e.g. `og-pr-42`) |

## Server environment

Anything the chart's values do not cover reaches the server as plain environment (via
`extraEnv`-style values or a Secret). The full server surface renders from the declared
environment registry (`make gen`). The chart already sets `OMNIGLASS_SECURE_COOKIES` from
`server.secureCookies`, `OMNIGLASS_ENCRYPTION_KEY` from the key Secret, and `OMNIGLASS_DATA_DIR` and
`OMNIGLASS_NATS_STORE_DIR` into the data volume ([durable state](#durable-state)).

Upgrading a deployment that sets the old names (`OMNIGLASS_SECRET_KEY` or
`OMNIGLASS_SECRET_KEY_FILE`): it keeps working, because the server still reads them while neither
new name is set, and it logs a deprecation warning naming the replacement on every boot. Rename the
variable in your values or Secret (the value is unchanged) before the release that stops reading
it; once a new name is set the old one is ignored, and a leftover is called out in the log.

## Exposure

By default the chart creates no Ingress: the standing deploy is reached by
port-forward (or a cloudflared route dialing the ClusterIP Service directly).

```bash
kubectl -n omniglass port-forward svc/omniglass 8080:8080
# open http://localhost:8080/web
kubectl -n omniglass logs deploy/omniglass -c bootstrap   # the one-time token
```

For per-PR previews, set `ingress.enabled=true` and an `ingress.host`. The chart
then emits a plain-HTTP Ingress (class `traefik`) that the in-cluster controller
Host-routes; the shared cloudflared tunnel fronts it with one wildcard route and
terminates TLS at the edge, so the Ingress carries no `tls` block.

```bash
helm install og-pr-42 deploy/chart -n og-pr-42 --create-namespace \
  --set image.tag=sha-<full-sha> \
  --set ingress.enabled=true \
  --set ingress.host=og-pr-42.preview.hyperscaleav.com \
  --set fullnameOverride=omniglass
```
